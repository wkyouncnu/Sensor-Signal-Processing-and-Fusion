# 주차 자료를 쓰는 절차

## 1. 골격은 바꾸지 않는다

`_templates/주차자료.md` 를 복사해서 시작한다. 학생이 15주 내내 **같은 자리에서 같은 것을
찾게** 만드는 것이 목적이다. 절을 빼거나 순서를 바꾸지 않는다.

```
프론트매터 → 제목 → 이 문서를 읽는 방법 → 학습 목표 → 준비물
1부 이론 (1-1, 1-2, …)  그림 1~3장
2부 실습 (2-1, 2-2, …)  단계별 명령어 + 정상 출력
이번 주차 요약(표) → 수업 진도 체크 → 과제 → 막혔을 때 → 참고 자료 → 다음 주 예고
```

주차별 실제 분량 감각 — PDF 기준 **16~24쪽**. 6주차 전(Simulink 기초)만 42쪽으로 예외.

---

## 2. 대상 독자 — 매번 이 사람을 떠올린다

> 리눅스·ROS·시뮬레이터를 **한 번도 안 해 본** 학부 4학년

| 이렇게 쓰면 실패한다 | 이렇게 쓴다 |
|---|---|
| "관리자 권한으로 PowerShell 실행" | "`Win` 키 → `powershell` 입력 → 검색 결과에서 **우클릭** → **관리자 권한으로 실행**" |
| 용어를 설명 없이 씀 | 첫 등장 시 반드시 설명. 세 개 넘으면 "용어 정리" 표를 절로 만듦 |
| 명령어만 나열 | 명령어 뒤에 **정상 출력 예시**를 붙인다 |
| 학생이 당황할 지점을 방치 | 미리 적는다 — "비밀번호를 입력해도 화면에 아무것도 안 보이는 것이 정상임" |

비유를 쓴다: `apt` = 앱스토어, 노드 = 직원 한 명, 토픽 = 사내 게시판.

### 명령어

- **반드시 복사 가능한 코드블록.** 스크린샷 속 명령어는 오타 공장이다
- 코드블록 하나에 **한 덩어리**만
- 한 줄로 이어져야 하는 긴 명령은 `[!warning]` 으로 명시
- `rm -rf` 등 되돌릴 수 없는 명령은 `[!caution]`

## 3. 문체 — 개조식

- 문장을 **명사형 또는 `-함/-임/-음`** 으로 끝낸다
- 한 항목은 **한 줄**. 두 줄이 되면 하위 항목으로 쪼갠다
- 비교·대조는 **표**. 줄글로 설명하지 않는다
- 절차는 **번호 목록**. 한 단계에 한 동작
- 강조 `**굵게**` 는 한 문단에 2개까지

예외 — 콜아웃 안의 짧은 설명, 지식카드의 `## 한 줄 요약`.

## 4. 어조 — 정식 교재

> [!important] 1·2인칭과 시점 표현을 쓰지 않는다

검사 대상 표현(스크립트가 세는 것과 같다):

| 쓰지 말 것 | 쓸 것 |
|---|---|
| 여러분 · 우리 | 학습자 · 본 과목 |
| 오늘 · 오늘의 | 이번 주차 · 본 절 |
| ★ 오늘의 핵심 | (중요) · — 핵심 항목 |
| 담당 노트북 실측 | 기준 환경 실측값 |
| 함정 · 지뢰 · 드디어 · 그냥 | 유의 사항 · 별도 옵션 없이 |
| "여기서 매년 막힌다" | "매 학기 반복되는 오류" |
| 이모지 장식 (본문) | 쓰지 않음. README 의 절 제목만 예외 |

- **콜아웃 제목도 서술형 명사구**로 — "왜 위험한가"(×) → "오류 메시지 없이 잘못된 결과가 나온다"(○)
- `~할 것`, `~하지 않는다` 같은 지시형 어미는 **교재 어투이므로 그대로 쓴다**

```bash
bash .claude/skills/capstone-lecture-vault/scripts/vault_check.sh --style
```

> [!warning] 일괄 치환은 코드블록을 망가뜨린다
> 문체 교정을 정규식으로 돌릴 때 **공백 압축 규칙을 넣지 말 것.** ASCII 정렬로 맞춰 둔
> 정상 출력 예시가 한 줄로 뭉개진다. 실제로 겪었다. 치환 뒤 반드시 `diff` 로 본다.

## 5. 수업 진도 체크 (필수)

문서 끝, 과제 앞에 반드시 넣는다. 목적은 **학생이 스스로 확인하고 넘어가는 것**이다.

```markdown
## 수업 진도 체크

> [!important] 다음 주 수업을 따라가기 위한 최소 조건

### 이론 이해
- [ ] ...를 설명할 수 있다

### 실습 완료
- [ ] ... 명령이 성공했다

### 관찰 기록 / 다음 주 준비 / 신고 사항
- [ ] ...
```

항목은 **검증 가능한 형태**로 쓴다.

| 나쁨 | 좋음 |
|---|---|
| `- [ ] ROS 2를 이해했다` | `- [ ] ros2 run demo_nodes_cpp talker / demo_nodes_py listener 통신 성공` |
| `- [ ] 제어기를 만들었다` | `- [ ] 헤딩 스텝응답 정착시간을 초 단위로 기록했다` |

## 6. 과제 — 배점표가 없으면 과제가 아니다

- **평가 배점표를 반드시 붙인다**
- **"검증했는가" 항목이 30% 이상.** 7주차 55%, 10주차 65% 가 실제 사례다
  → [[측정하지-않은-성공은-성공이-아니다]]
- 검증은 **수치로 제출**하게 한다. "잘 됐다" 는 인정하지 않는다
- 좋은 검증 항목의 형태
  - 조건을 **한 번에 하나만** 바꾼 비교표 (게인 3조건, 외란 3조건)
  - 오프라인 ↔ VRX 대조표
  - 이론값과 실측값의 차이 + 그 차이에 대한 5~10줄 분석
