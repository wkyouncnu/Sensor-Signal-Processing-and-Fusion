### 15-16. 통합 주차는 **절제(ablation)** 로 쓴다 (2026-09-25, W09 에서)

여러 주차를 한 모델에 얹는 주차는 "다 된다" 를 보여 주는 자리가 아니다. **각 주차가 얼마를
벌었는지를 재는** 자리다. W09 를 그렇게 썼고, 앞으로 통합 주차(W12 · 기말 프로젝트)도 그렇게 쓴다.

| 규칙 | 왜 · 어떻게 |
|---|---|
| **주차마다 스위치 하나** | 각 주차의 기여를 `use_<이름>` 하나로 끌 수 있게 쓴다. 0 이면 그 주차가 넣은 줄만 빠지고 **구조는 그대로**다. W09 는 아홉 개: `use_Ki_u`(W3) · `use_ssa`·`use_Kd`(W4) · `use_ilos`·`use_pass`(W5) · `use_scale`(W6) · `use_notch`(W7) · `use_vane`·`hand_over`(W8) |
| **모델 둘이 아니라 스위치 하나** | 비교가 정직하려면 두 실행이 **한 가지만** 달라야 한다. 모델을 둘로 나누면 해석기·파랑·웨이포인트·게인이 모두 따로 흘러갈 수 있다. 같은 모델을 두 번 돌린다 |
| **지표는 한 곳에서** | `WXX_metrics.m` 하나가 한 번의 실행을 몇 개의 수로 줄이고, **모든 절이 그것만 쓴다.** 절마다 다르게 재면 표를 나란히 놓을 수 없고, 그러면 "이 주차가 무엇을 벌었나" 에 답할 수 없다 |
| **움직이지 않는 행도 싣는다** | W09 의 `use_pass` 는 기준 조건에서 아무것도 바꾸지 않았고, §9-5 에서 임무 성패를 갈랐다. "값이 0 인 행" 은 실패가 아니라 **그 조건이 그 기여를 시험하지 않았다는 측정**이다. 지우지 말고 그렇게 쓴다 |
| **이음매의 고장을 찾는다** | 통합 주차에서만 나오는 고장이 진짜 수확이다. W09 의 `ssa` 실패(셋째 다리가 psi=180° 에 놓여 한 바퀴를 돈다)는 4주차도 5주차도 혼자서는 만들 수 없었다. 이런 것을 찾으면 **절의 주제로 올린다** |
| **한계는 두 종류로 나눈다** | 힘의 한계는 서서히 나빠지고, 판정(비교문)의 한계는 나빠지지 않다가 한 번에 실패한다. 둘을 각각 재고, 어느 쪽이 **먼저 막는지** 말한다 — 대개 고치기 싼 쪽이 먼저 막는다 |

### 15-17. 수치를 싣기 전에 **폭**을 잰다 (2026-09-25, W09 §9-6)

난수 아닌 외란(`wave_train` 의 황금비 위상)이라도 그것은 **한 실현**이다. 한 실현에서 나온 수를
설계의 성질처럼 쓰면 안 된다.

- 같은 스펙트럼의 다른 실현을 만든다 — **위상만 통째로 옮긴다** (`phi_i + phase_shift`).
  진폭도 주파수도 그대로이므로, 바뀌는 것은 성분들이 만나는 방식뿐이다.
- 다섯 실현을 돌려 **폭**을 싣는다. W09 는 임무 시간 275.2~278.6 s, 유지 오차 0.732~0.757 m (3.4 %).
- 판정 기준: **폭이 주장하려는 차이보다 작아야** 그 주장을 실을 수 있다. W09 의 절제 결론
  (0.75 m 대 3.68 m)은 폭 0.025 m 에 대해 압도적이므로 실린다.
- `wave_train.m` 은 고치지 않는다. 옮기는 것은 그것을 부르는 `WXX_read.m` 의 일이다.
- 검증기에 검사 하나로 내린다 (`verify_w09_integration` 검사 6).

### 15-18. 실습 계약은 **플랜트가 받는 것**을 적게 한다 (2026-09-26, W06~W09 실습)

W06~W09 실습을 만들며 굳은 것. 문제지의 "이 신호를 로그에 담아라" 는 편의가 아니라
**무엇을 시험하는지를 정하는 계약**이다. 잘못 고르면 틀린 모델이 통과한다.

| 규칙 | 왜 · 실례 |
|---|---|
| **의도한 값이 아니라 전달된 값을 적게 한다** | W06 계약은 추력이 아니라 **회전수**를 요구하고, 체커가 프로펠러 곡선으로 추력을 되계산한다 — 선체가 하는 것과 똑같이. 추력을 직접 적게 했다면 역곡선을 틀리게 만든 모델도 "옳은 추력" 을 로그에 남기고 통과했을 것이다. 그것이 바로 2번 문제다 |
| **결과로 구별할 수 없는 것은 구조로 검사한다** | W07 계약은 `psi_f` — 제어기가 **실제로 쓴 값** — 을 요구한다. 노치를 만들어 놓고 연결하지 않은 모델은 필터 없는 수치를 내므로 어떤 성능 지표로도 구별할 수 없다. 그래서 `zeta_n = zeta_d` 일 때 `psi_f == psi_m` 을 1e-6 으로 요구한다 |
| **제어기가 고른 것을 적게 한다** | W08 계약은 `psi_d` 를 요구한다. 조류 속에서 배는 **조종하지 않아도** 저항만으로 뱃머리를 돌린다. 명령을 함께 적어야 "뱃머리가 명령을 따라갔는가" 를 물을 수 있다 |
| **모든 수를 한 함수가 낸다** | W09 3번 문제는 열 번의 실행을 한 표로 읽는다. 행마다 다르게 재면 그 표는 가로로 읽을 수 없고, 그러면 아무 말도 하지 않는다 → §15-16 |
| **주차의 주제는 블록을 빼서가 아니라 수로 끈다** | W06 `fit_mode`, W07 `zeta_n = zeta_d`, W09 아홉 스위치. 모델 둘을 비교하면 아무도 의도하지 않은 차이가 낄 수 있다. 한 모델을 두 번 돌리면 그럴 수 없다 |
| **출발 모델은 처음부터 돌아야 한다** | Constant 로 빈 자리를 채워 둔다. 학생이 첫 줄에서 컴파일 오류를 만나면 그 뒤로 문제지를 믿지 않는다 |
| **틀린 모델이 1번 문제를 통과하게 둔다** | W06 1번은 추력이 전부 양수라 잘못된 역곡선도 통과한다. 그것이 의도다 — 시운전이 놓이는 자리가 바로 거기이고, 2번 문제가 그것을 드러낸다 |

### 15-19. 그린 그림은 **본문에 박아 넣을 때까지** 끝난 것이 아니다 (2026-09-29, W05)

W05 는 개념도가 일곱 장 `figures/` 에 있는데 본문이 **한 장도 부르지 않고** 있었다
(W01 은 10장, W04 는 2장을 부른다). 사용자가 "설명만 있고 그림들이 없어" 라고 한 것이
그것이다. 더 나쁜 것은 고아가 된 동안 그림과 본문이 **따로 늙었다**는 점이다.

| 무엇이 어긋나 있었나 | 실제 |
|---|---|
| 수치 | 그림은 $\Delta = 8$ m · 출발 18 m, 본문은 $\Delta = 5$ m · 출발 20 m. 그대로 실었다면 **본문과 그림이 서로 모순**됐을 것이다 |
| 절 번호 | 주차 번호를 한 칸 민 뒤(2026-09-21) 그림 안의 §4-6·§5-7·"Section E" 가 그대로 남았다 |
| 렌더 | `.tex` 는 일부 고쳐졌는데 `.svg` 를 다시 뽑지 않아 **디스크의 그림이 자기 소스와 달랐다** |
| 라벨 | `w05-track-frame` 의 $y^n$ 이 축 아래 설명글 위에 겹쳐 찍혀 있었다 (§4 규칙 6) |

규칙:

- 그림을 그렸으면 **그 자리에서 본문에 `![...](../figures/....svg)` 로 넣고 "reading the
  figure" 표를 붙인다.** 넣지 않은 그림은 만들다 만 것이다
- 본문의 수치를 바꾸면 **그 수치를 적어 둔 그림을 같이 고친다.** 그림 안의 수치도
  §4 규칙 8 의 "러너 출력까지 추적 가능" 대상이다
- `.tex` 를 고쳤으면 **`tikz2svg.sh` 를 돌려 `.svg` 와 `.png` 를 다시 뽑고 눈으로 본다.**
  소스만 고치고 끝내면 디스크의 그림이 거짓말을 한다
- 주차 번호를 밀 때는 `figures/src/*.tex` 안의 §번호도 함께 센다 — `vault_check` §14 는
  `.md` 만 본다

기계로 거를 수 있는 것: 주차 문서가 부르지 않는 `figures/wNN-*.svg` 를 세는 검사.

### 15-20. 실시간 화면은 **모델 안에** 둔다, 그리고 현실 시간은 선택사항이다 (2026-09-29, W05, 사용자 지시)

사용자 지시: *"웨이포인트 돌면서 최종적으로는 시뮬링크를 실제 현실 시간하고도 맞춰서
돌리면서 cross track error, waypoint index 값 증가... 맨 왼쪽에는 웨이포인트와 실시간
궤적과 선박 모양 표시... 속도 제어 명령과 속도 값 (실제), 그리고 n_L, n_R 등도 다 볼 수
있도록... 그렇게 실시간으로 그림 그리는 것들은 다 시뮬링크에 포함해줘... 그리고 현실
시간하고 맞춰서 돌리는 것은 선택사항으로 할 수 있도록"*

`.m` 을 돌려야 그림이 나오는 모델은 **반쪽짜리**다. 학생이 처음 하는 것은 Run 을 누르는
것이고, 그때 아무 일도 일어나지 않으면 그 모델을 믿지 않는다. 그래서 주차마다 셋을 둔다.

| 무엇 | 어디에 | 언제 도나 |
|---|---|---|
| `WXX_animate.m` → `_tools/live_guidance.m` | 캔버스의 **Animate** MATLAB Function 블록 | **도는 동안** 매 `animate_every` 초 |
| `WXX_plot.m` | 모델의 `StopFcn` | **끝났을 때**, 절 스크립트와 같은 그림 |
| `WXX_H_….m` | 절 스크립트 | 여러 값을 한 번에 |

규칙:

- **블록을 빼서 끄지 않는다.** `animate` 라는 Constant 하나가 Animate 블록으로 들어가고,
  0 이면 블록이 아무것도 하지 않는다. 껐다 켤 때마다 모델을 다시 만들면 학생의 모델과
  강의의 모델이 갈라진다
- 그리는 함수는 `coder.extrinsic` 으로 선언한다 — MATLAB Function 블록은 그림을 못 그린다
- **핸들을 다시 쓴다.** 스텝마다 `patch` 를 만들면 객체가 쌓여 창이 기어간다 (`live_track`
  에서 이미 밟았다). `set(h,'XData',…)` 로 고쳐 쓰고 `drawnow limitrate` 로 끝낸다
- **현실 시간은 `InitFcn` 이 켠다**, 모델에 박아 두지 않는다:
  ```matlab
  set_param(m, 'InitFcn', ['if base_var(''pace'', 0) > 0, ' ...
      'set_param(bdroot, ''EnablePacing'', ''on'', ''PacingRate'', ''1''); else, ' ...
      'set_param(bdroot, ''EnablePacing'', ''off''); end']);
  ```
  작업공간의 `pace` 를 바꾸고 Run 만 누르면 된다. **측정한 것**: 10 s 임무가 `pace = 1`
  에서 12.7 s, `pace = 0` 에서 1.4 s 벽시계, 수치는 완전히 같다. 수업에서는 1, 표를
  만들 때는 0 이다
- **절 스크립트에서는 꺼 둔다.** `WXX_vars.m` 은 `animate = 0`, `WXX_0_setup.m` 은 `= 1`.
  전자는 한 번에 여러 번 돌리고, 후자는 사람이 Run 을 누르는 파일이다
- `StopFcn` 의 플로팅 함수는 **절 스크립트가 도는 동안 자야 한다.** 그때 로그는 `out`
  안에 있고 기본 작업공간의 것은 직전 Run 이 남긴 낡은 것이다 — 그대로 그리면 **돌린 적
  없는 그림**이 나온다. `WXX_read` 가 `W05batch` 플래그를 세우고 `onCleanup` 으로 지운다
- 명령이 없는 신호는 **선을 긋지 않는다.** 속도 루프가 없는 모델에 `u_d` 점선을 그리면
  따라가지도 않는 목표선이 되어 거짓말이 된다. Constant 의 값을 `NaN` 으로 두고 화면이
  `isfinite` 로 거른다

### 15-21. 범례에 `data1` 이 보이면 **보조선이 범례에 들어간 것**이다 (2026-09-29, W05)

사용자가 화면을 보내 왔다: *"지금 legend가 이상해 오른쪽 값"* — $\psi_d$·$\psi$ 범례
아래에 `data1 data2 data3` 이 붙어 있었다. 전환 시각을 긋는 `xline` 셋이다.

- `xline`·`yline`·`plot` 중 **설명이 필요 없는 것에는 `'HandleVisibility','off'`** 를 준다
- 범례에 넣을 것에는 **`'DisplayName'` 을 직접 준다.** 순서에 기대지 않는다 — 나중에 선을
  하나 끼워 넣으면 이름이 밀린다
- 범례를 만든 뒤에 선을 더 그릴 일이 있으면 `'AutoUpdate','off'`
- 그리고 **명령과 실제는 같은 축에 함께**, 이름에 어느 쪽인지 적는다:
  `u_d = 1.00 m/s  commanded` 와 `u  actual` (사용자 지시, 2026-09-29)

### 15-22. 힘 하나가 상수에서 제어기 출력이 되면 **한계식을 다시 유도한다** (2026-09-29, W05 §5-7)

W05 §5-7 에서 3주차 속도 루프를 얹자마자 배분기가 $n_R = 116.2$ rad/s 를 요구했다.
Otter 의 한계는 $n_{\max} = 103.9$ rad/s 다. 원인은 게인이 아니라 **4주차의 요 모멘트
한계 $N_{\max}$ 가 $X_{ff} = 60$ N 에 대해 한 번 계산된 상수**였다는 것이다. 속도 루프가
$X$ 를 120 N 까지 올리면 그 상수는 더 이상 실현 가능한 값이 아니다.

- 한계는 **지금의 $X$ 에서 매 스텝 다시 계산한다**:
  $N_{\lim}(X) = \min\{2y_p(k_{pos}n_{\max}^2 - X/2),\; 2y_p(X/2 + k_{neg}n_{\min}^2)\}$.
  **측정**: $X = 60$ N 에서 70.85 N·m, $X = 120$ N 에서 47.15 N·m, 최대는 $X \approx 53$ N
- 그리고 **`otter.m` 이 안에서 이미 $n$ 을 자른다** (MSS `otter.m` 167–170 행). 배분기가
  자르지 않으면 로그의 $n$ 이 플랜트가 받은 $n$ 과 달라진다 → §15-18
- 일반 규칙: 어떤 값이 상수에서 신호로 바뀌면, **그 값이 들어 있는 모든 한계식·포화
  한계·정규화 분모**를 찾아서 같이 신호로 만든다. 찾는 법은 그 상수의 이름으로
  `grep` 하는 것이다

> 부분으로 해줘....선들도 꼬여 있는데 직선으로 해주고...너무 복잡해"* · *"ssa 부분도
> 너무 복잡해 간단하게 함수로 해줘봐"*

MATLAB Function 한 덩어리는 **읽히지 않는다.** 두 번 눌러야 하고, 눌러도 코드다.
제어기는 그림으로 읽는 것이 낫다.

| 무엇을 | 어떤 블록으로 |
|---|---|
| 오차를 $(-\pi, \pi]$ 로 감기 | **`Fcn` 하나**, `atan2(sin(u), cos(u))`. sin·cos·atan2 세 블록으로 풀지 않는다 |
| 게인 | **`Gain`**, 값은 작업공간 변수 이름 (`Kp`, `Kd`, `Ki_u`). Constant + Product 두 블록이 아니다 |
| 되감기 배선 | 뺄셈을 **두 입력 바로 아래**에 둔다. 요구값과 포화값이 각자 **곧장 아래로 떨어져** 만나고, 돌아가는 선은 `Kb` **하나뿐**이다. 예전에는 포화 출력이 오른쪽으로 갔다가 위로, 다시 왼쪽으로 돌아와 네 토막이었다 (사용자 지적, 2026-09-29: "antiwindup 부분도 너무 가독성이 낮아") |
| 부호 | **게인은 전부 양수**, 빼는 것은 **합산점에서** (`'+-'`). `-Kd` 를 게인에 넣으면 부호가 블록 이름·블록 값·합산점 셋에 흩어져 그림을 보고 부호를 세어야 한다 (사용자 지적, 2026-09-29). 예외는 **부호 자체가 실험의 주제**일 때뿐이다 — W04 4-3e 절이 'minus Kd' 와 'plus Kd' 를 나란히 놓는 것 |
| 포화 | **평범한 `Saturation`**. 한계가 정말로 신호일 때만 `Saturation Dynamic` 을 쓴다 |
| 적분기 | **연속 `Integrator`** (`1/s`). 플랜트가 연속시간이므로 제어기도 연속시간이다 — 이산 적분기를 섞으면 모델이 시간축 둘을 갖는다 (사용자 지시, 2026-09-29) |
| 안티와인드업 | **back-calculation**: `sat(X) - X` 를 `Kb` 배 하여 적분기 입력에 더한다. 3주차가 쓴 그 배선 그대로이고, **그림에서 보이는 유일한 오른쪽→왼쪽 경로**다. 적분기 안의 Limit output 은 보이지 않아서 "안티와인드업이 없다" 는 말을 듣는다 |
| 상태 꺼내기 | `Selector`, 이름을 `psi = x(12)` 처럼 **식으로** 붙인다 |

그리고 **밖에서 들어오는 것**과 **안에서 읽는 것**을 가른다.

- **명령은 캔버스의 Constant** — 웨이포인트, $\Delta$, $R$, $\kappa$, $u_d$. 학생이 무엇을
  지시하는지가 그림에 보여야 한다
- **게인은 Gain 블록의 값** — 어차피 작업공간에서 읽으므로 명령창에서 바꾸고 Run 이면 된다.
  Constant 로 빼내면 블록만 늘고 선만 꼬인다
- 근거는 **MSS 데모 `demoOtterUSVPathFollowingHeadingControl`** 이다. 웨이포인트·`Delta`·
  `R_switch`·desired surge thrust 가 최상위 Constant 이고, `Heading autopilot` 서브시스템
  안에 `Kp`·`Td`·`1/Ti` Gain 과 `ssa` 가 들어 있다. 새로 정한 규칙이 아니라 **그 모델의 모양**이다

배선은 **한 행에 한 신호**다. 주 흐름을 한 높이에 두고, 옆에서 들어오는 것은 **각자 다른
세로 통로**로 올린다. 같은 높이를 나눠 쓰면 `check_overlaps` 가 잡는다 — W05 에서 `N_lim`
과 `N` 이 `y = 110` 을 함께 쓰다 2건, 속도 루프에서 같은 실수로 4건이 났다.
**서브시스템 안도 센다**: `check_overlaps` 는 스스로 내려가므로 최상위만 0 이어도 소용없다.

그림도 서브시스템마다 따로 뽑는다. 다만 `open_system` 으로 열고 뽑지 말 것 —
`print('-s<경로>')` 는 창 없이 뽑는다. 모델 일곱을 연달아 지으면서 창을 열었다가
**세션이 멈췄다.**

> [!important] 안티와인드업은 **보이지 않으면 없는 것과 같다**
> 처음에 적분기의 Limit output 으로 클램핑을 걸었더니 사용자가 도면을 보고 *"pi
> controller 속도 제어에서 왜 antiwindup이 없어?"* 라고 물었다. 있었다 — 블록 안에
> 램프 아이콘 하나로. **도면에서 읽히지 않는 제어 구조는 가르칠 수 없다.**
> back-calculation 은 뺄셈 하나와 게인 하나이고, 도면에서 **오른쪽에서 왼쪽으로 가는
> 유일한 선**이라 눈에 띈다. 그리고 `Kb = 0` 으로 껐다 켤 수 있어 **재서 보일 수 있다**
> — W05 §5-7 은 속도 오버슛 0.0380 -> 0.0216 m/s 로 그 값을 싣는다.
> 작으면 작다고 적는다: 그 임무는 한계에 1 초도 머물지 않는다.

### 15-24. 알고리즘이 여럿이면 **한 블록에 넣고 플래그로 고른다** (2026-09-30, W05, 사용자 지시)

### 15-25. 수식은 **유도해서 내놓는다**. 알고리즘이 갑자기 튀어나오지 않게 (2026-09-30, 사용자 지시)

사용자: *"수식은 가능한 유도 과정을 추가해줘.... 이해하기 쉽게... 갑자기 알고리즘만 나오지
않도록... 항상 주의"*

`CLAUDE.md` §3 에 이미 "① 왜 필요한가 ② 원리 ③ 수식 ④ 적용 ⑤ 특징" 이 있고 §4 규칙 9 에
"수식을 떨어뜨리지 않는다" 가 있는데도 **ILOS 가 그대로 빠져나갔다.** 어떻게 빠져나갔는지가
이 절의 요점이다.

> [!warning] 성질을 설명하는 것은 유도가 아니다
> W05 §5-5 는 `"ILOS adds the integral."` 한 줄 뒤에 곧바로
> $\dot y_{int} = \Delta y_e/(\Delta^2 + (y_e+\kappa y_{int})^2)$ 를 내놓고,
> 그 다음에 **성질**을 셋 설명했다 — 작은 신호에서 PI 다, 적분이 크랩각을 든다,
> 분모가 커져서 와인드업을 막는다. 전부 맞는 말이고 전부 **유도가 아니다.**
> 학생은 여전히 "그 분모는 어디서 왔는가" 를 모른 채로 남는다.
>
> **판정법**: 그 수식을 **다른 수식으로 바꿔 놓아도 본문이 그대로 읽히면** 유도가 없는 것이다.
> 분모를 $\Delta^2 + y_e^2$ 로 바꿔도 위의 세 문장은 전부 그대로 맞는다. 그러면 실패다.

**되는 순서 — W05 §5-5 를 다시 쓰면서 확인한 것.**

| 단계 | 하는 일 | §5-5 에서 |
|---|---|---|
| 1 | **오차의 운동방정식을 쓴다.** 대개 여기가 빠져 있다 | $\dot y_e = U\sin(\chi - \pi_p)$ — 정의를 미분한 한 줄 |
| 2 | **옛 법칙을 넣고 닫는다** | $\dot y_e = U\sin(\beta - \arctan(y_e/\Delta))$ |
| 3 | **평형점을 푼다** | $y_e = \Delta\tan\beta$. 과도현상이 아니라 **닫힌 루프의 유일한 평형점**이라는 것이 여기서 나온다 |
| 4 | **무엇이 참이어야 하는가를 묻는다** | $y_e=0$ 이 평형이 되려면 arctan 이 $y_e$ 아닌 것을 먹어야 한다 → 항을 하나 더한다 |
| 5 | **새 항이 가야 할 값을 푼다** | $\kappa y_{int}^\star = \Delta\tan\beta$ — **옛 법칙이 오차로 남기던 바로 그 값** |
| 6 | **거기로 보내는 방법**에 조건을 걸고, 그 조건으로 형태를 고른다 | (a) $y_e=0$ 에서만 0 (b) 멀리서 폭주 금지 → 분자·분모가 각각 그 둘이다 |
| 7 | **작은 신호로 읽는다** | $\arctan x \approx x$ → $K_p = 1/\Delta$, $K_i = \kappa/\Delta$ 인 PI |
| 8 | **한계를 적는다** | 분모의 상한 1/2 은 적분이 작을 때만. $\kappa=3$ 은 수렴하지 않는다 |

**어기지 않는 것 넷.**

- **유도는 측정 가능한 예측을 하나 낳아야 한다.** 5 단계가 $\kappa y_{int} \to 2.10$ m 를
  예측했고, 실제로 $2.1013 / 2.1042 / 2.1456$ 이 나왔다. **유도와 러너가 같은 수를 말하는
  자리**를 만들지 못하면 그 유도는 장식이다
- **새 수식의 모든 조각을 설명한다.** 분모가 왜 그것인지, $\kappa$ 의 **단위가 무엇인지**
  (속도다, m/s — 그래서 $\kappa y_{int}$ 가 길이다). 설명 못 하는 기호를 남기지 않는다
- **버린 가정을 적는다.** "곧은 다리라 $\pi_p$ 가 상수", "정상상태라 $\psi = \psi_d$"
- **그 자리에 문헌을, DOI 까지** (§7·§4 규칙 10-1). 유도를 내가 다시 했더라도 적는다.
  **DOI 는 열어서 확인한다** — §5-5 의 것은 IEEE Xplore 4739352 로 실제로 열어 보았다

**놓치기 쉬운 자리.** 절 안의 수식만이 아니라, **실습 문제지·답안지·`.m` 주석**도 같다.
블록 안의 코드가 강의의 유도와 **같은 순서·같은 기호**여야 학생이 둘을 잇는다 (§13).

> [!warning] 이것은 **기계로 거를 수 없다.** 시도해 보고 접었다
> §0-0 은 기계로 거를 수 있는 것을 `vault_check` 에 내리라고 한다. 이 규칙은 해 보았고
> 안 된다 — 2026-09-30 에 둘 다 재 보았다.
>
> | 시도한 검사 | 결과 |
> |---|---|
> | `$$` 블록 앞 10 줄에 번호 붙은 유도 줄이 있는가 | **127 건**. 여러 식으로 이어지는 유도의 중간 단계가 전부 걸린다 |
> | 절에 수식이 있는데 번호 붙은 줄이 하나도 없는가 | **25 건**. W01 §1-3 "The rotation matrix" 처럼 **산문으로 제대로 유도한 절**이 대부분이다 |
>
> 둘 다 통과선을 만들면 기준선이 잡음으로 덮이고, 통과하려고 **하나의 문체를 강요**하게 된다.
> 유도는 번호 목록일 수도 있고 줄글일 수도 있다 — 형식이 아니라 **내용**의 문제다.
>
> 그래서 이것은 **손으로 보는 검토 항목**이다. §11 전체 검토에 넣었다. 질문은 하나다:
> **"그 수식을 다른 수식으로 바꿔 놓아도 본문이 그대로 읽히는가?"**
> 읽히면 유도가 없는 것이다.

### 15-26. 수업 노트를 받으면 **그 구조 그대로** 자료에 옮긴다 (2026-10-13, 사용자 지시)

### 15-28. 회전 화살표는 **계산해서** 그린다 — 같은 지뢰를 두 번 밟았다 (2026-10-13)

사용자: *"이 그림이 맞아? N 방향이 시계방향이 + 아니야?"* — 맞다. 내가 **반시계로** 그렸다.

`CLAUDE.md` §4 규칙 6-2 가 **바로 이것**을 경고하고 있었다 (`w01-pqr.svg` 의 roll 과 yaw 가
반대로 그려졌던 일). 그런데 새 그림 둘에서 또 틀렸다. 규칙을 적어 두는 것만으로는 부족하고,
**그릴 때마다 실제로 따져야** 한다.

**따지는 법 — 세 줄이면 된다.**

| | |
|---|---|
| 1 | NED 에서 $z_b$ 는 **아래**를 향한다. $N$ 은 $+z_b$ 둘레의 모멘트다 |
| 2 | 오른손 법칙: $+z$ 둘레의 양의 회전은 $+x \to +y$. 곧 **선수가 우현으로** |
| 3 | 위에서 내려다본 그림은 $x$ 가 화면 위, $y$ 가 화면 오른쪽. 위 → 오른쪽 = **시계방향** |

따라서 **위에서 본 그림에서 $N>0$ 화살표는 시계방향이다.**

**플랜트로 확인한다.** 논증만 믿지 않는다. 좌현을 더 세게 밀어 `otter.m` 에 넣으면:

```
plant: r_dot = +0.28904 rad/s^2        r > 0 이므로 psi 가 커진다 = 우현으로
```

> [!warning] TikZ 의 함정
> `arc (시작:끝:반지름)` 은 **끝 각이 클 때 반시계**, **작을 때 시계**다.
> `arc (-60:-18:2.0)` 은 반시계이고 `arc (-18:-60:2.0)` 이 시계다. 시작점 좌표도
> **시작 각**의 것으로 바꿔야 한다 — 안 바꾸면 호가 엉뚱한 곳에 그려진다.
>
> 눈으로 볼 때는 **뱃머리 근처**에 그린 호가 가장 읽기 쉽다. 거기서는 시계방향이

### 15-30. 그림이 블록 하나를 그린 것이면, **그 블록의 코드를 그 자리에 싣는다** (2026-10-13, 사용자 지시)

사용자가 W03 §3-6 의 두 단계 그림을 가리키며 *"이 부분에 대한 실제 MATLAB 시뮬링크 안에
코드도 아래에 복사해서 보여줘봐"* 라고 했다. 맞는 요구다 — 그림과 수식은 **무엇을 하는가**를
말하고, 학생이 모델에서 보는 것은 **코드**인데, 그 둘이 같다는 것을 자료가 보여 주지 않으면
학생이 직접 대조해야 한다.

**손으로 옮겨 적지 않는다. 모델에서 뽑는다.** 빌더 `.m` 의 문자열 배열을 복사하면
빌드 이후에 손댄 것이 반영되지 않고, 따옴표 두 개(`''`)가 그대로 실린다.
저장된 `.slx` 에서 꺼내는 것이 **실제로 학생이 더블클릭해서 보는 글자**다.

```matlab
load_system(f);
c = rt.find('-isa','Stateflow.EMChart','Path',[mdl '/allocation']);   % rt = sfroot();
fid = fopen(out,'w','n','UTF-8'); fprintf(fid,'%s', c(1).Script); fclose(fid);
close_system(f,0);
```

> [!warning] `sfroot.find` 는 **안 된다**
> `sfroot.find(...)` 는 "함수 이름 뒤에 괄호가 와야 합니다" 로 죽는다.
> `rt = sfroot();` 로 받아서 `rt.find(...)` 를 쓴다.

실을 때 지키는 것 넷.

| | |
|---|---|
| **어디에** | 그림의 읽는 표 **바로 뒤**. 그림 → 표 → 코드 → "무엇을 말하는가" 순서 |
| **무엇을 덧붙이나** | `In the code / In the figure / Note` 세 칸 표. 코드 줄을 **그림의 어느 부분**과 잇는다. 코드를 산문으로 다시 읽어 주지 않는다 |
| **주차마다 다르다** | 같은 `allocation` 이라도 W03 은 `X/2` 한 줄, W04 는 손으로 푼 두 줄, W05 는 `B \ [X; N]` 이다. **그 주차의 블록**을 싣고, 다른 주차와 무엇이 달라졌는지 한 칸으로 적는다 |
| **없는 것도 적는다** | W05 표의 마지막 행은 "코드에 없는 것 = $N_{\lim}$" 이다. 결함이 어디서 나는지를 그것이 가리킨다 |

**PDF 로 뽑아 눈으로 본다.** 코드 블록은 고정폭 글꼴로 조판되는데, 한글 주석이 두부(⃞)로
나오면 자료가 못 쓰게 된다. 2026-10-13 의 `pdf-template.html` 은 멀쩡했지만, **확인하지 않고
넘어가지 않는다.** 페이지를 찾아 그림으로 뽑는 것이 빠르다:

```python
import fitz
doc = fitz.open(pdf)
for i,p in enumerate(doc):
    if 'function n = allocation' in p.get_text():
        p.get_pixmap(dpi=110).save(png); break
```

같은 코드를 한 절에서 **두 번 싣지 않는다.** W05 §5-7 은 유도 3번에 세 줄 발췌가 있었는데,
전문을 8번 뒤에 넣으면서 발췌를 지우고 "the listing follows line 8" 로 가리켰다 (§9-5).
