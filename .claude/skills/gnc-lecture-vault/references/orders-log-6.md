## 15-71. 실시간 화면은 **명령 대비 실제**를 그린다 — 2026-10-28

> **"애니메이션에는 위치제어 x ref, y ref 명령값 대비 실제 x, y 값 heading degree
> 명령 값과 실제 값....등이 실시간으로 표시되고 캡스톤 디자인 처럼 도킹 스테이션도
> 표시가 되면 좋겟는데"**
> **"이 그림에서 왼편 위의 점들은 대체 무슨 의미야....모르겟어.... 명령 값 대비
> 실제 값을 보여줘야지..."**
> **"외부 제어인 위치제어의 출력이 u, v 속도 명령이고...그것을 제대로 추종하고
> 잇는지 확인하고 싶은거야..제일 중요한 것은 x,y,psi 값이 명령 대비 실제 값이
> 실시간 그래프 이고..."**

궤적 하나만 흐르는 창은 **계단식 제어기를 보여 주지 못한다.** 바깥 루프가 무엇을
지시했는지가 화면에 없으면, 안쪽 루프가 그것을 따라갔는지도 없다. W06 의 실시간
화면과 인쇄 그림을 같은 계약 아래로 넣었다.

### 명령을 로그에 넣지 않으면 추종을 잴 수 없다

바깥 위치 루프의 출력이 곧 $u_d$, $v_d$ 다. 그것을 로그에 **열로** 넣기 전까지는
"안쪽 루프가 추종한다" 가 가정이었다. 열을 둘 늘려 **측정량**이 되었다.

| 열 | 무엇 |
|---|---|
| 1-6 | `u v r N E psi` — 모든 주차 공통 |
| 7-9 | `N_set E_set psi_set` — 위치·선수각 명령 |
| 10-12 | `X_dem Y_dem N_dem` |
| 13-15 | `n_L n_R F_B` |
| 16-17 | `d phase` |
| **18-19** | **`u_d v_d` — 바깥 루프가 낸 속도 명령** |

> [!important] 속도 명령은 **항상 선체 축**으로 로그한다
> NED 단(`W06_8_ned`)은 명령을 NED 로 계산하므로, **로그에 쓸 때만** 한 번 회전해
> 넣는다. 그러지 않으면 점선과 실선이 서로 다른 축의 양이라 겹쳐 놓을 수 없고,
> 그 칸의 "추종한다" 는 거짓이 된다.

### 로그 폭은 **한 곳에만** 적는다

`W06_read.m` 과 `W06_plot.m` 이 같은 계약을 두 번 이름 짓는다 — StopFcn 에는 `out`
객체가 없어서 플로터가 스스로 열을 알아야 한다. 그 둘이 어긋나는 것을
`verify_w06_actuation.m` 의 17 번 검사가 막는데, 숫자 `19` 를 그 안에 두 번 쓰면
열을 늘릴 때 한쪽만 고쳐진다. **상수 하나로 뺀다.**

```matlab
nlog = 19;                       % 이 주의 로그 폭. 한 곳에만 적는다
same = numel(A1) == nlog && numel(A2) == nlog && isequal(A1, A2) && ...
       ~any(cellfun(@isempty, A1));
```

### 그림의 규칙 넷

1. **점선이 명령, 실선이 실제.** 주차 전체에서 바꾸지 않는다
2. **한 축에 쌍이 하나면** 명령은 빨강 `[0.75 0.10 0.10]`, 실제는 파랑
   `[0 0.45 0.74]`. **쌍이 둘이면** 축을 색으로 가른다 ($u$ 파랑
   `[0.00 0.45 0.74]`, $v$ 주황 `[0.85 0.33 0.10]`) 하고 **점선·실선으로** 명령과
   실제를 가른다. 색 둘에 선종 둘이면 넷이 섞이지 않는다
3. **점선 명령을 마지막에 만든다.** 먼저 그리면 추종이 가장 좋은 구간에서 실선
   밑으로 들어가 사라진다 — 가장 보여 주어야 할 자리에서 안 보인다
4. 범례는 비운다 (`'Box','off','Color','none'`) 그리고 **빈 항목을 두지 않는다**

> [!warning] 전부 NaN 인 계열은 **그리지 않고, 제목이 그렇다고 말한다**
> 열린 루프 단(`W06_3_thrust`)에는 선수각 명령이 없다. 그래도 `plot` 을 부르면
> 범례에 `\psi_{set} commanded` 가 데이터 없이 앉고, 제목이 `|error| NaN deg` 를
> 찍는다. 가드를 세운다 —
> ```matlab
> has_c = ~all(isnan(R.psi_set));
> ```
> 참일 때만 명령과 오차를 그리고, 거짓일 때 제목은
> `'(c) the heading,  no command on this rung'` 이다. **NaN 을 찍는 것보다 없다고
> 말하는 것이 정보가 많다.**

### 가구도 같은 기준으로 끈다 — 사용자가 물은 "왼편 위의 점들"

접안하지 않는 단에 안벽과 접근점을 그려 두면, 그 자국은 **내려진 적 없는 명령**을
가리킨다. 사용자가 그림에서 짚은 것이 바로 그것이었다. 실시간 화면이 이미 쓰던
기준을 인쇄 그림에도 같이 쓴다.

```matlab
berths = ~all(isnan(R.phase)) && any(R.phase > 0);
```

`W06_animate.m` 과 `W06_fig_rung.m` 이 **같은 한 줄**을 쓴다. 접안하는 단은 5 와 7
뿐이고, 나머지는 `konst_goto(m,'phase 0','0','phase',380)` 으로 0 을 흘린다.

### 자리를 고정하면 범례가 데이터 위에 앉는다

단마다 항적이 있는 사분면이 다르다. `'Location','southeast'` 는 어떤 단에서
항적을 덮었다. 데이터의 사분면이 단마다 바뀌는 칸은 **`'Location','best'`** 다.

### 추종의 숫자는 **첫 1 초를 뺀 평균**이다

$t = 0$ 에서 명령이 상한까지 뛰는데 선체는 아직 정지해 있다. 그 순간의 차는
**명령의 계단 자체**이고 추종 지연이 아니다. 전 구간 평균은 그 계단에 끌려간다.

```matlab
gd = R.t > 1 & ~isnan(R.u_d) & ~isnan(R.v_d);
```

4 단에서 실제로 잰 것 — `peak 0.800 at t=0.00 | mean after 1 s 0.0028 |
first below 0.02 at t=1.38`. 강의 §6-4 의 3 번 단계가 "안쪽 루프가 즉시
추종한다" 고 가정하는데, 이제 그 가정은 **첫 1.4 초 동안 틀리고 그 뒤로는 거의
맞는다** 고 수치로 적을 수 있다. **가정을 문장으로 남겨 두지 말고 그 가정의
오차를 재서 적는다.**

### `sim` 은 **base 작업공간에서** 돌려야 한다

`ReturnWorkspaceOutputs` 를 끄면 To Workspace 가 **부른 쪽의** 작업공간에 쓴다.
함수 안에서 `sim` 을 부르면 그 함수가 끝날 때 로그가 함께 사라지고, StopFcn 은
아무것도 못 본다. 로그 변수 이름은 `W06` 다 — `W06_log` 가 아니다.

```matlab
L = evalin('base','W06');  y = squeeze(L.signals.values);
if size(y,1) < size(y,2), y = y.'; end
```

### 끝내기 전에 **렌더해서 눈으로 본다 — 고친 뒤에도 다시**

이 절의 세 가지(패널 (c) 가드 · 가구 게이트 · 범례 자리)를 모두 **그림을 뽑아
보고** 찾았다. 코드를 읽어서는 "NaN 이 찍힌다" 도 "안벽이 남아 있다" 도 보이지
않는다. `CLAUDE.md` §4-6 의 "고친 뒤에도 다시 렌더해서 본다" 가 이 절에서 세 번
값을 했다.

### 집계 러너는 지우는 것이 아니다

예제별로 `.slx` · `.m` 을 나눈 뒤에도 `W06_J_ladder.m` 이 남아 있는 이유가 둘이다.
**(1)** 그것이 강의 §6-8 자체다 — 일곱 단을 **나란히 재는** 유일한 자리이고, 표
셋(미션 · 구동 · 자세)이 거기서 나온다. **(2)** 나눈 러너들은 그림을 저장하지
않으므로, 강의가 박아 넣는 여덟 PNG(`img/W06_r*.png` 일곱 + `img/W06_result_ladder.png`)
를 **만드는 곳이 거기뿐**이다. 지우려면 `W06_fig_rung`/`exportgraphics` 호출을
일곱 러너로 옮기고 §6-8 을 두 언어로 다시 써야 한다. **"뭉쳐 있다" 와 "집계한다"
는 다르다** — 나누는 것은 예제이고, 비교는 한 자리에 남는다.

## 15-72. 여러 절이 **같은 운항**을 쓰면 운항을 한 번만 하고, 절마다 파일을 낸다 — 2026-11-03

§15-15 는 절 스크립트의 실행 줄을 45 줄 이하로 못박았고 `vault_check.sh` §18 이 그것을
센다. W12 에서 이 둘이 부딪혔다 — 표 셋과 그림 하나가 **같은 여섯 번의 30 초 운항**을
읽는다. 절마다 스크립트를 하나씩 내면 배가 여섯 번이 아니라 스물네 번 돈다.

막다른 길 둘을 먼저 버렸다.

| 길 | 왜 버렸나 |
|---|---|
| 점검에 두께 예외를 더한다 | 점검 스크립트 주석이 "두께 예외는 지금 없다" 로 닫혀 있다. 하나를 열면 다음 주차가 그것을 근거로 연다 |
| 절마다 돌린다 | 같은 입력으로 네 번 더 도는 것이 강의에 보태는 것이 없다. 배는 여섯 번만 돌면 된다 |

남은 길이 **운항은 한 번, 절은 파일 하나**다. `W12_V_openloop.m` 은 21 줄로 줄어
순서만 적고, 각 절의 알맹이가 제 파일로 나갔다.

```
W12_V_openloop   여섯 번 돌리는 자리. 아래 넷을 순서대로 부른다
W12_cases        여섯 벌의 숫자 — 표 셋과 그림이 **같은 것**을 가리키게 한다
W12_tab_formula  §12-3  수식이 맞는가
W12_tab_reint    §12-6  모델이 그 수식인가 — 로그 여섯을 **되돌려 준다**
W12_tab_track    §12-4 · §12-5  그 힘이 만드는 운동. 돌리지 않고 로그를 다시 읽는다
```

`W12_tab_reint` 가 로그 여섯을 반환하므로 표 (3) 과 그림이 그것을 다시 쓴다.

### 점검을 피한 것이 아니다 — 점검이 세는 것이 무엇인지 보고 지었다

`vault_check.sh` §18 은 `W[0-9][0-9]_[B-Z]_*.m` 만 찾는다. `W12_` 다음이 **대문자**라야
걸린다. 그래서 `W12_cases` · `W12_tab_*` 는 세지 않는다 — 기존 `W12_read` · `W12_plot` ·
`W12_vars` 와 **같은 이름 규칙**이고, 절 스크립트가 아니라 **그 절이 부르는 것**이라는
뜻이 이름에 들어 있다. 이름을 `W12_W_...` 로 지었다면 새 절처럼 보여 §18 이 옳게 걸었을
것이다.

> [!important] 강의 `.md` 가 그 파일들을 가리켜야 끝이다
> Part 2 의 실행 순서 표는 절마다 **열어 볼 파일**을 적는 자리다. 운항이 하나로
> 묶였으면 표에 `W12_V_openloop → W12_tab_formula` 처럼 화살표로 적고, 왜 하나인지를

## 15-73. 이 환경에는 `pdftoppm` 이 없다 — PDF 쪽은 **그림으로 못 본다** — 2026-11-03

를 못박는다. 그런데 이 기계의 poppler 는 `pdftotext` **하나뿐**이고 `pdftoppm` ·

부르므로 같은 자리에서 멈춘다.

대신 세 갈래로 나누어 본다. 셋을 다 하면 §4-6 이 보려던 것을 덮는다.

| 무엇을 | 어떻게 |
|---|---|
| 수식이 조판되었는가 | `pdftotext -layout` 로 뽑아 **남은 `$`** 와 **살아남은 `\command`** 를 센다. 쪽수도 거기서 읽는다 |
| 개념도가 본문 폭에서 읽히는가 | `svgzoom.sh <svg> $((703/폭))` 로 **PDF 안의 크기 그대로** 띄워 본다. SVG 폭이 703 px 보다 **좁으면** PDF 안에서 커지기만 하므로 1:1 PNG 로 충분하다 |
| 러너 그림이 맞는가 | `img/*.png` 를 **직접** 읽는다. PDF 에서 되찾지 않는다 — 그 PNG 가 PDF 에 들어간 바로 그 파일이다 |

W12 에서 그렇게 했다 — 28 쪽, 남은 `$` 0, 남은 매크로 0; 두 개념도는 640 px · 529 px 라

결과 그림은 V3(초록)와 V6(빨간 점선)이 **정확히 겹치는 것**으로 서보 포화를 눈으로
확인했다.

## §15-74 그림은 설명 **옆**에 두고, 그림 해설 표는 W12 에서 **뺀다** (2026-11-03)

사용자가 12주차 PDF 두 쪽을 캡처해 보내며 말했다.

> "이런 설명이 잇다면 그림이 바로 옆에 잇어서..설명을 이해하는데 도와주면 좋을 것 같아
>  ...그리고 설명 들이 다 너무 길어..2번재 그림과 같은 그림 설명을 표로 한 것은
>  이번 week에서 삭제해줘..너무 설명이 길어.."

지시는 둘이고, 둘째는 **`CLAUDE.md` §4-5 를 덮는다.**

| | 무엇을 | 어떻게 |
|---|---|---|
| 하나 | 그림을 **그 그림이 설명하는 줄 옆**에 둔다 | 유도 목록 **중간에** 그림을 끼운다. `marked` 가 `<ol start="N">` 을 내므로 목록이 끊겼다가 다음 번호로 **이어진다** — §12-4 는 7번 바로 뒤에 `w12-why-symmetry-yaws.svg` 를 넣고 8번으로 계속한다 |
| 둘 | **`\| In the figure \| Meaning \|` 꼴의 그림 해설 표를 W12 에서 전부 지운다** | 그림 안의 글자를 표로 옮겨 적은 것이라 같은 말을 두 번 읽힌다. 지우고 그 자리에 아무것도 넣지 않는다 |

> [!important] `CLAUDE.md` §4-5 와의 관계
> §4-5 는 "그림마다 뒤에 reading the figure 표를 붙인다" 였다. 이 지시로 그것은
> **그림 안의 글자를 옮겨 적는 표**에는 적용되지 않는다. 남는 것은 **결과 그래프**의
> 표다 — 그것은 그림의 글자가 아니라 **어느 곡선이 유도의 어느 줄을 예측하는가**를
> 적으므로 설명을 더한다 (`| Where to look | What is there | Which line predicts it |`).
> 그래서 12주차에는 실험 절의 그 표만 남았고, 개념도 뒤의 범례 표는 하나도 없다.

판정은 기계로 한다 — **새로 쓰거나 고치는** 주차 문서에서 `| In the figure |` 를
grep 해 0 이어야 한다.

## §15-75 · 행렬의 **기호 꼴**을 싣고, 밖에서 온 행렬은 **부호를 먼저 맞춘다** (2026-11-04)

사용자 지시: "여기 B 행렬에 숫자가 들어가기 보다는....마지막 행 부분만 말이야..
그 부분에 기호로 표시하고...각 길이가 어떤 moment arm인지를 설명해줘봐.....
그리고 각 시나리오가 진짜 맞는 것인지도...더블 체크 해줘"

### 1. 배치 행렬의 **마지막 행은 숫자가 아니라 기호**로 싣는다

`B` 의 앞 두 행은 장착 부호뿐이므로 ±1·0 으로 둔다. **3행은 전부 모멘트암**이고,
숫자로만 쓰면 `0.395` 와 `1.500` 이 **어느 길이인지** 사라진다. 그래서

1. `B` 를 기호로 쓴다 — 3행 = `[ d_1  l_f  -d_2  l_f  -d_3  l_a  d_4  l_a ]`
2. 바로 아래에 **열 ↔ 모멘트암 표**를 둔다: 어느 열이 무엇을 곱하고, 그 암이
   **무엇에서 무엇까지의 거리**인가 (`cos` 열 → 중심선에서 폰툰까지 `d_i`,
   `sin` 열 → 중앙(CO)에서 추력 위치까지 `l_f`·`l_a`)
3. "모멘트암은 **그것이 곱하는 힘에 수직**으로 잰다" 를 한 줄로 적는다 — 그래서
   한 추진기의 두 암이 **서로 다른 길이**다
4. `d_i` 가 다 같을 때의 축약과 **그 다음에** 수치를 낸다
5. 항별 전개를 하나 싣는다 — `N = (d_1 f_1x - d_2 f_2x - ...) + l_f(f_1y+f_2y) + l_a(f_3y+f_4y)`.
   기동이 틀렸을 때 읽는 꼴이 이것이다
6. 기호에서 바로 읽히는 것을 불릿으로 적는다. W12 에서는 **`sin` 항 넷이 모두 양수**인
   것이 그렇다 — 선미에서 장착 뒤집힘($s=-1$)과 음의 위치($x=-l_a$)가 **상쇄**된다

치수선이 이미 그려진 개념도를 **이 설명 옆**으로 옮기고, 캡션이 "치수선으로 그린 암"
임을 말하게 한다. 같은 그림을 한 절에 두 번 넣지 않는다 — 옮기다 그렇게 됐다.

### 2. 밖에서 온 `B` 는 **부호 규약부터** 대조한다 — 그림이 아니라 **돌아가는 코드**와

사용자가 참조로 준 PPT 슬라이드의 `B` 는 이 강의의 `B` 와 **전 성분 부호가 반대**였다.
판정은 그림끼리 견주어서는 나지 않았다. **사용자 자신의 MILS 코드**
(`MILS/otter_model_tilt4_Control_Scripts_r2.m` 11~17행) 가 이 강의의 `B` 를
**한 글자도 다르지 않게**, 그것도 3행을 `d, lf,-d,lf,-d,la,d, la` 로 **기호로** 박아
두고 있었다. 돌아가는 쪽이 코드이므로 볼트는 코드를 따랐다 — 사용자 확인(2026-11-04)
**"코드 기준 유지"**.

다만 **어느 규약이 옳은 것은 아니다.** 사용자가 바로 이어 못박았다 —
**"부호는 일관되기만 하면 되어…"**. 슬라이드는 틀린 그림이 아니라 **영점을 반대로
붙인 다른 표기**이고, 틀린 것은 **둘을 섞는 것**이다. 그래서 규칙은 "코드가 진실"
이 아니라 **"볼트 전체가 한 규약을 쓴다"** 이며, 그 하나를 `otter_config.m` 의
`mount` 필드에 두고 `otter_B.m` 이 거기서 `B` 를 만들게 해 둘이 어긋날 수 없게 한다.
주차 문서에도 **규약은 선택이고 요건은 일관성**이라고 한 문단으로 적는다
(W12 §12-1, `mount` 를 가리키는 문단).

```
열규칙 loop  vs  MILS 코드 : 0.0e+00
열규칙 loop  vs  otter_B   : 0.0e+00
열규칙 loop  vs  PPT       : 3.0e+00   (-PPT 와는 0.0e+00)
```

- 부호 규약은 행렬에 있지 않고 **$s_i$ 의 선택**에 있다. 선수 영점이 뒤를 밀면
  $s = [-1,-1,+1,+1]$ 이고 그 결과가 정확히 $-B$ 다
- 그래서 **부호 규약이 다른 출처가 셋이 되었다.** 기존 둘(`otter4_B.m` 과
  `otter_params.m` 41행)에 **참조 슬라이드**가 더해졌다 → 스킬 §3 의 경고.
  어느 것도 틀리지 않았고, **가져와 섞는 것**이 틀린 것이다
- 주차 문서의 Troubleshooting 에 한 줄로 남긴다 — 학생이 연구실 슬라이드와
  견주다 반대 부호를 가져오면 명령한 기동이 **전부 뒤집힌다**

### 3. "더블 체크" 는 **쓴 함수를 쓰지 않고** 다시 계산하는 것이다

`W12_tau.m` 과 `otter_B.m` 을 불러 맞으면 그것은 **같은 코드가 같은 답을 낸 것**이고
검산이 아니다. 스크래치패드에 독립 스크립트를 짜서

1. 열 규칙을 **루프로 다시** 써서 `B` 를 만들고 세 출처와 대조
2. 여덟 τ 를 **항별 전개로** 다시 계산해 강의 표의 인쇄값과 차이를 찍고
3. 시나리오 **이름**이 `sign(τ)` 와 맞는지, 거울쌍(S1/S2, S3/S4)과 포화쌍(S5/S8)이
   정확히 상쇄되는지 보고
4. 30 s 를 **직접 쓴 RK4** 로 적분해 궤적 표(U·crab·r·반경)와 대조한다

W12 는 전 항목 통과했다. 남는 차이 1e-04~1e-03 은 **강의 표의 인쇄 자리수**(소수
3자리·2자리)이고 불일치가 아니다 — 보고할 때 그것을 밝힌다.

## §15-76 · 배분(allocation) 절을 쓸 때 — 네 가지 (2026-11-04, W12 §12-7~§12-11)

사용자 지시: "최대한 쉽게 ...개념부터..control allocation이 먼지...제약 조건을 어떻게
고려해야 하는지...Weight matrix는 어떤 개념이고..어떻게 튜닝하는지", "mathworks 링크도
넣고", "입력과 출력의 정의도 정리해주고", "RPI는 일단 빼보자..나중에 하자".

### 1. 가중행렬이 **할 수 없는 것**을 먼저 재고 쓴다

참조 코드가 `W = diag([1 1000 ...])` 로 틸팅을 줄이려 한 것은 이 형상에서 **틀렸다.**
$B$ 둘째 줄이 $[0\,1\,0\,1\,0\,{-1}\,0\,{-1}]$ 이므로 $Y$ 는 $f_y$ 열만이 내고,
따라서 $\sum\lvert f_y\rvert$ 는 요구가 **못박은 값**이다 — 쓸어도 30.00 N 에서
움직이지 않는다. 값을 올리면 요에 쓰는 팔이 긴 쪽(1.5/1.0 m)에서 짧은 쪽(0.395 m)으로
옮겨가 $f_x$ 가 쏠리고 최대 각이 **오히려 커진다**(26.88° → 31.73°).

> 절을 쓰기 전에 **$B$ 의 행 구조에서 어느 합이 묶여 있는지** 손으로 본다.
> 그러고 나서 쓸어서 확인한다. 값표로 되는 것은 **누가 몫을 지는가**(뒤 두 대 몫
> 48.9 % → 17.5 %)이고, 한계는 값이 아니라 **제약**으로 걸어야 한다.

### 2. 짐작한 조각 하나로 푼 QP 는 **exit flag 를 읽지 않으면 거짓말을 한다**

$\lvert\delta_i\rvert\le\alpha_{\max}$ 는 추력 부호 $\sigma_i$ 를 정하면 직선 둘이지만,
양쪽 반콘을 합친 것은 **볼록하지 않다.** 가중 최소노름이 가리킨 조각에서 풀면
`quadprog` 가 exit $-2$ 를 내면서도 그럴듯한 각과 오차를 **같이** 돌려준다.
네 유닛이면 조각이 $2^4=16$ 개이고 그것이 집합을 **정확히** 덮는다.

- 법칙 하나를 더 둔다 — `'wls16'`: 열여섯을 다 풀고 최선을 고른다 (0.020 N 대 해 없음)
- **모든 통계를 `info.exit > 0` 에서만** 낸다. 궤적 201 점에서 `qp` 는 85.6 % 만 풀렸다
- 그림에서 해가 없는 순간은 곡선을 `NaN` 으로 끊고 바닥에 표식을 찍는다
- 주차 Troubleshooting 과 과제 검증표에 `info.exit` 를 **먼저 읽으라**고 적는다

### 3. 같은 기호가 두 주차에서 **다른 것**을 가중하면 경고 콜아웃을 둔다

W07 §7-7 의 $\mathbf W$ 는 **힘 오차** $\mathbf{BT}-\boldsymbol\tau_d$ 를, W12 §12-9 의
$\mathbf W$ 는 **노력** $\mathbf f$ 를 가중한다. 둘이 한 절(§12-10)에 같이 나오므로
오차 가중을 $\mathbf Q$ 로 쓰고, §12-9 에 `[!warning]` 로 둘의 차이를 적었다.
**다른 주차에서 쓴 기호를 다시 쓰기 전에 그 주차를 grep 한다.**

### 4. 시간 측정은 **재현되지 않는다** — 자릿수가 논거다

§12-11 의 시간 측정을 세 번 돌려 세 벌의 숫자가 나왔다. 그래서
① **마지막 실행값**을 싣고 ② "한 기계·한 부하의 측정" 이라는 콜아웃을 붙이고
③ 순서와 자릿수가 논거라고 못박고 ④ Troubleshooting 에 한 줄 남긴다.
미리 만든 $8\times3$ 행렬 하나(0.52 µs, 곱셈 24 번) 대 `fmincon` 최악
(20 056 µs > 20 000 µs 예산) — 이 **비교**는 어느 실행에서도 뒤집히지 않는다.

## §15-78. 포화가 둘이면 **벽도 둘**이다 — 하나만 넣은 최적화는 거짓말한다 (2026-11-04)

사용자 지시: "각 n rpm값의 saturation과 서보 각도의 saturation도 고려해야 하고....
그리고 실제 제어기에서 나온 힘과 실제 control allocation을 거쳐서...동역학 모델에서
계산된 힘도 같이 plot 해야 하지 않아?"

W12 §12-10 은 서보 벽($|\delta_i|\le 45^\circ$)만 QP 안에 넣고 추력 캡은 **풀고 나서**
스칼라 $\rho$ 로 깎았다. 그래서 모든 $\delta_i$ 가 벽 안에 있으면서도 3번 축이
$-115$ rad/s 를 요구했고, 플랜트가 201 점 중 **41.8 %** 에서 그것을 잘라냈다.
배분기가 보고한 힘과 선체가 받은 힘이 달랐다 — **그런데 아무 숫자도 그것을 말하지
않았다.** 다섯이 규칙이다.

### 1. rpm 포화는 **따로 있는 제약이 아니라 추력 캡**이다

$T = k\,n|n|$ 이므로 $|n_i|\le n_{\max} \iff |T_i| \le k_i n_{\max}^2$ 다. 같은 벽을
곡선을 통해 본 것이다. **정·역의 $k$ 가 다르므로 캡 높이가 둘**이다 —
`quad_tilt` 에서 전진 $0.011080\times103.93^2 = 119.682$ N, 후진
$0.006445\times101.74^2 = 66.708$ N 으로 후진이 전진의 **56 %** 이고,
순수 전진 요구에서 묶는 쪽은 **작은 후진 캡**이다. 두 캡을 손으로 베끼지 말고
`otter_config` 에서 계산한다.

### 2. 한 단위의 실현 가능 영역은 **원의 부채꼴**이다 — QP 는 원호를 못 받는다

서보 벽은 직선 둘, 추력 캡은 2차식 하나다. 각을 $M$ 등분한 **내접 현** $M$ 개로
바꾼다 — 이웃한 현은 반지름 $R$ 의 원 **위**에서 만나므로 다각형은 캡을 절대
넘지 않고, **중점에서만** $1-\cos(\alpha_{\max}/M)$ 만큼 보수적이다
($M=1$ → 29 %, $M=3$ → 3.41 %, $M=6$ → 0.86 %). 단위마다 행이 $2+M$ 개,
넷이면 20 개다. $M$ 은 **데이터보다 고운 근사를 하지 않는다** —
$k_{\mathrm{pos}}$ · $k_{\mathrm{neg}}$ 가 회귀계수이므로 $M=3$ 에서 멈춘다.

### 3. 풀고 나서 깎는 스칼라 $\rho$ 는 **방향만 살리고 크기를 버린다**

$\mathbf B$ 가 선형이라 $\mathbf B(\rho\mathbf f)=\rho\boldsymbol\tau$ — 방향은 남지만
**한 단위가 캡에 닿으면 넷이 다 끌려 내려간다.** 캡 행을 QP 안에 넣으면 나머지 셋이
그 짐을 받는다. $\boldsymbol\tau=[300\,0\,0]$ 에서 측정: $\rho$ 는 **16.584 N** 오차,
현을 넣으면 **0.009 N**. 즉 캡을 안에 넣는 값은 단위마다 $M$ 행이고, 그 값은
시간으로 재서 적는다 — $2699.5 \to 3888.4$ µs (44 % 증가, 오차는 600 배 작아짐).

### 4. 오차는 **배분기가 아니라 운동모델에서** 꺼낸다

$\lVert\mathbf B\mathbf f-\boldsymbol\tau_d\rVert$ 는 배분기 안의 숫자이고, 하드웨어
한계가 아직 걸리지 않은 자리의 숫자다. 그래서 **같은 상태에서 플랜트를 두 번** 부른다
— 추진기를 켠 채, 그리고 `n = 0` 으로 — 그 가속도 차에 질량을 곱해
$\boldsymbol\tau_{\mathrm{act}} = \mathbf M(\dot{\boldsymbol\nu}_{\mathrm{on}}
-\dot{\boldsymbol\nu}_{\mathrm{off}})$ 의 1·2·6 행을 읽는다. 플랜트가 가속도를
돌려주고 `n`·`δ` 를 **안에서** 자르기 때문에 이것 말고는 방법이 없다.
요구와 실측을 **한 그림에 겹쳐 그리고**, 포화 그림에는 두 한계선을 함께 긋는다.

### 5. 배분기에서 자르는 것과 하드웨어가 자르는 것은 **같은 힘**이다

`wpinv` 의 $\delta=89.76^\circ$ 를 플랜트가 $45^\circ$ 로 자르고, `clip` 은 같은 자리에
놓는다 — 그래서 둘의 달성 힘이 **한 자리도 다르지 않다**(평균 9.049 N, 최대
31.452 N). 이것은 버그가 아니라 **유도가 낳은 측정 가능한 예측**이고
(`CLAUDE.md` §4-9-1), Troubleshooting 에 "똑같이 나오는 것이 맞다" 로 적는다.
자르는 일 자체가 값을 버는 것이 아니라, **잘린 한계가 최적화 안에 있을 때** 번다.

## §15-79. 수식과 그 그림을 **같은 쪽에** 두려면 상자 하나로 묶는다 (2026-11-05)

> "W06_Bow_Thruster_Position_Control_and_Berthing 도 수식과 기하 그림을 같은 page에
> 해줘", 그리고 그 앞의 "8 페이지 그림과 7페이지 수식은 같은 페이지에 잇도록"

### 1. 원인 — Chrome 인쇄는 `break-inside: avoid` **하나만** 지킨다

`pdf-template.html` 에는 `h1..h4 { break-after: avoid }`, `p:has(> img) { break-after:
avoid }`, `p:has(> img) + table { break-before: avoid }` 가 오래 들어 있었다. **이 셋은
Chrome 헤드리스 인쇄에서 아무 일도 하지 않는다.** Chrome 의 쪽 나누기는 `break-before`
와 `break-after` 의 `avoid` 를 구현하지 않았고, `break-inside: avoid` 만 구현했다.
그래서 "떨어지지 말라" 고 쓴 규칙은 전부 장식이었고, W06 의 $B$ 행렬은 7쪽 밑에,
그 행렬의 길이를 그린 그림은 8쪽 위에 남았다.

판정법: 규칙을 추가했는데 쪽 나누기가 **한 줄도** 달라지지 않으면 그 규칙은
Chrome 이 무시한 것이다. CSS 를 더 쓰지 말고 **DOM 모양**을 바꾼다.

### 2. 고치는 방법 — 둘을 **하나의 블록**으로 만든다

떨어뜨리지 말라고 **부탁**하는 대신, 쪼갤 수 없는 상자 하나로 **만든다.**
`pdf-template.html` 이 `marked` 가 낸 HTML 에서 "수식 문단 바로 뒤의 그림 문단" 을
찾아 `div.keep` 하나로 감싼다 — 조판 **전**, 문자열 단계에서.

```js
html = html.replace(
  /<p>(\$\$[\s\S]*?\$\$)<\/p>\s*<p>(<img\b[^>]*>)<\/p>/g,
  function (_, eq, img) {
    return '<div class="keep"><p>' + eq + '</p><p>' + img + '</p></div>';
  });
```

```css
.keep { break-inside: avoid; page-break-inside: avoid; }
.keep p { margin-top: 0; }
```

- **문자열 단계에서 한다.** 처음에는 MathJax 조판이 끝난 뒤 DOM 을 고치려 했고
  (`#out p > mjx-container[display="true"]` 를 찾아 감싸는 함수), **PDF 가 한 바이트도
  달라지지 않았다.** 조판 뒤의 DOM 모양에 기대지 않는 쪽이 짧고 확실하다
- **상자는 한 쪽에 들어가야 한다.** 쪽의 본문 높이는 270 mm = 765 pt 다. 수식 ~70 pt
  에 그림을 더해 그보다 크면 Chrome 은 `avoid` 를 포기하고 그냥 쪼갠다. 이 볼트에서
  수식 바로 뒤에 오는 그림은 넷뿐이고 (`w03-why-T` 290 pt · `w05-ref-heading-form`
  CSS 로 112 mm 로 눌림 · `w06-alloc-geometry` 593 pt · `w12-tilt-geometry` 375 pt)
  모두 들어간다. 새 그림을 수식 뒤에 둘 때 **높이를 먼저 센다**

### 3. 확인하는 방법 — 이 컴퓨터에는 `pdftoppm` 이 없다

`Read` 로 PDF 쪽을 그림으로 볼 수 없다 (`pdftoppm`·Ghostscript·`pypdf` 전부 없음).
`pdftotext` 는 xpdf 4.06 이라 `-bbox` 도 없다. 그래서 **빈 줄의 길이로** 재고,
수식(MathJax SVG)과 그림(SVG path)은 글자를 내놓지 않는다는 것을 이용한다.

```bash
pdftotext -lineprinter -linespacing 12 -f 7 -l 9 lectures/W06_*.pdf - \
  | awk 'BEGIN{p=7;n=0} /\f/{p++;n=0;next} {n++; if($0~/[^ \t]/) printf "p%d L%02d: %s\n",p,n,substr($0,1,60)}'
```

- 수식과 그림이 **한 쪽 안의 연속된 빈 줄 하나**로 나타나고, 그 위아래가 **같은 쪽의
  글자**면 붙어 있는 것이다. W06: 8쪽 L15 "4. Assembling the three columns" 다음
  L16~L69 가 비고 (≈ 648 pt = 수식 70 + 그림 593), 범례 표는 9쪽에서 시작한다.
  W12: 7쪽 L18 다음 L19~L63 이 비고 (≈ 540 pt), L64 에서 본문이 이어진다
- 고치기 **전**에도 쪽 나누기를 같은 방법으로 재 둔다. 안 그러면 "달라졌다" 를
  판정할 기준이 없다 — 실제로 바이트 크기만 보고 "같다" 를 두 번 잘못 읽었다

### 4. HTML 템플릿도 `Edit` 로 고친다

`.md` 의 LaTeX 에 `sed` 를 쓰지 않는 이유(§5-1)가 `pdf-template.html` 에도 그대로
걸린다 — 안에 든 것이 CSS 와 JS 의 정규식이고, 역슬래시가 들어 있다. 그리고 CSS
주석을 고칠 때 `*/` 를 중간에 남겨 주석이 두 번 닫힌 적이 있다. **고친 뒤 템플릿
한 조각을 다시 읽어 주석이 한 번만 닫혔는지 본다.**

## §15-80. 절 스크립트 다섯을 진입점 하나로, 모델 넷을 모델 하나로 (2026-11-05)

| 전 | 후 |

### 2. 이것은 §2 의 예외이고, 예외의 조건이 있다

절 하나에 스크립트 하나를 깨도 되는 경우는 **절 넷 이상이 같은 설정을 세우고 같은

`W12_2_build_alloc` → `W12_0_setup` 뒤에 `law` 를 바꾸는 것까지 적었다.

### 3. 솔직하게 — 합친 파일은 `vault_check.sh` §18 이 재지 않는다

§18 의 글로브는 `W[0-9][0-9]_[B-Z]_*.m` 이다. `W12_CA.m` 은 **거기에 걸리지

전부 함수로 빠져 있다 — **진입점은 분배만 한다**가 두께를 대신하는 기준이다.
