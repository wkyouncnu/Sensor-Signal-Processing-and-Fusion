### 15-31. 선은 **가로 아니면 세로**다 — 대각선은 0 (2026-10-13, 사용자 지적)

사용자: *"여전히 시뮬링크 곳곳에 선들이 평행하지 않고, 대각선으로 꺾인 부분들이 많아...
꺾일 필요가 없는 부분들은 다 직선으로 수정해줘"*

겹침(`check_overlaps`)만 세고 있었다. **비스듬한 선은 따로 센다** — 도구가 없으면
"많이 고쳤다" 로 끝나고 다음 주차에 다시 생긴다.

| 도구 | 하는 일 |
|---|---|
| `_tools/check_diagonals.m` | 이웃한 두 점이 x 와 y 둘 다 바뀌는 구간을 센다. **0 이어야 끝** |
| `_tools/straighten_lines.m` | 끝을 포트에 당겨 붙이고, 남은 대각선마다 직각 모서리 하나를 끼운다 |
| `_tools/compact_layout.m` | 블록도 주석도 선도 없는 **빈 복도**를 좁혀 블록을 모은다 |

**빌더의 끝은 이 순서다.** 순서가 틀리면 고친 것이 도로 틀어진다.

```matlab
mss_style(m);          % 블록 크기 먼저 — 포트가 여기서 움직인다
compact_layout(m, 60); % 그 다음 빈 복도
straighten_lines(m);   % 마지막에 선
save_system(m, out);
```

> [!important] 대각선이 생기는 네 가지 원인 — 전부 실제로 밟았다
> 1. **`mss_style` 이 선을 그린 뒤에 블록 크기를 바꾼다.** 포트가 2~5 px 움직이고
>    모든 선 끝이 포트를 비껴간다. 55 개 모델에 171 개가 있었던 주된 원인이다.
> 2. **가지선이 어미선의 분기점을 품고 있다.** `[포트; 분기점; …]` 로 저장되어
>    첫 구간이 비스듬해진다. 이웃이 이미 나란하면 그 가운데 점을 **뺀다**.
> 3. **어미선이 포트에서 곧장 위아래로 떠난다.** Simulink 가 저장할 때 분기점을
>    포트 위에 다시 적어 **가지마다** 대각선이 생긴다. 어미선에 가로 토막을 붙이되,
>    그 토막의 x 는 **가지들이 갈라지는 x** 여야 한다 (A1 의 x 분배, 여섯 개).
> 4. **둥근 합산점의 둘째 입력은 아래쪽에 달려 있다** (MSS 식 `'|++'`). 그 포트는
>    세로로 들어가야 한다. 포트에 Orientation 파라미터가 없으므로 **포트 좌표를
>    블록의 네 변과 견주어** 어느 변인지 본다.

> [!warning] 좁히면 겹칠 수 있다
> `compact_layout` 은 복도를 하나 좁힐 때마다 **겹침을 다시 세고, 늘었으면 그 복도만
> 되돌린다.** 세로선이 지나는 복도는 아예 건드리지 않는다 — 나란히 내려가던 선들이
> 한 자리에 몰려 **겹침 29 쌍**을 만든 적이 있다.

> [!warning] MATLAB Function 블록을 `mss_style` 에서 줄이지 않는다
> 100x50 으로 줄였더니 포트 여섯인 `guidance` 의 입력선이 한 점에 몰렸다. 크기는
> **빌더가 블록을 만들 때** 정한다 — 그래야 `port_xy` 가 최종 좌표를 읽는다.

끝낼 때 **디스크의 파일로 다시 센다.** `save_system` 이 선을 다시 쓰기 때문에,
메모리에서 0 이어도 파일에서는 0 이 아닐 수 있다 (그 반대도 있다).

```matlab
load_system(f); check_diagonals(mdl); check_overlaps(mdl); close_system(mdl,0);
```

### 15-32. 되먹임은 **한 줄의 통로**에 놓고, 그 통로의 블록은 왼쪽을 보게 한다 (2026-10-13, 사용자 수정)

사용자가 속도 루프의 안티와인드업을 직접 고쳐 보내 왔다. *"가독성이 높도록...
(선들이 꺾이는 것을 최소화)"*

| 전 | 후 |
|---|---|
| 뺄셈이 본선 **오른쪽 아래**, Kb 가 더 아래. 선이 내려갔다 돌아 나왔다 다시 내려간다 | 뺄셈과 Kb 가 **맨 아래 한 줄**에 나란히, 둘 다 `Orientation`=`left` |
| 꺾이는 곳 여덟 | 넷 — 각 신호가 **곧장 아래로** 떨어지고, 통로를 따라 왼쪽으로 가고, 한 번 올라간다 |

```matlab
add_sum(s, 'X - X raw', '-+', [640 460]);
set_param([s '/X - X raw'], 'Orientation','left');   % 입력이 오른쪽에 온다
gain(s, 'Kb', kbName, [520 442 570 478]);
set_param([s '/Kb'], 'Orientation','left');
```

**규칙으로**: 신호가 오른쪽에서 왼쪽으로 돌아가야 하면 그 경로의 블록을 전부
왼쪽으로 돌려 **한 줄에 세운다.** 그러면 선은 세로 둘과 가로 하나가 된다.

사용자: *"시뮬링크만 돌려도 animation 기능 추가해서 왼쪽에는 궤적(선박 모양 추가 -
헤딩도 표시...), 오른쪽에는 속도제어 명령과 실제 값, 헤딩 제어 명령값과 실제 값...
waypoint index가 하나씩 올라는 것.. cross track error ... 마지막은 n_R, n_L"*

`_tools/live_guidance.m` 이 그 화면이다. 줄의 순서는 사용자가 말한 그대로다.

| 줄 | 무엇 | 왜 |
|---|---|---|
| 왼쪽 | 경로 · 웨이포인트 · 궤적 · **선체와 선수 방향** | 궤적선만으로는 크랩각이 보이지 않는다 |
| 1 | `u_d` 와 `u` | 안쪽 속도 루프가 명령대로 가는가 |
| 2 | `psi_d` 와 `psi` [deg] | 안쪽 선수각 루프가 명령대로 가는가 |
| 3 | waypoint k (계단) | 전환이 **언제** 일어났는가 |
| 4 | `y_e` | 유도가 되고 있는가 |
| 5 | `n_L` 과 `n_R` | 그것을 만들려고 두 축이 무엇을 하는가 |

**명령과 실제는 같은 칸에 겹쳐 그린다.** 다른 칸에 두면 눈이 두 축을 오가며 비교해야
하고, 그 비교가 이 화면의 전부다.

**Run 만 눌러도 떠야 한다**: Animate 블록이 매 스텝 부르고, `animate` Constant 가 0 이면
아무것도 하지 않는다 (블록을 빼지 않는다, §15-20). 강의자료에는 그 창을 **그대로 뽑아**
싣는다 — 학생이 Run 을 눌렀을 때 보는 것과 같은 그림이어야 하기 때문이다.

### 15-36. 임무의 끝, 그리고 수치를 재는 **구간** (2026-10-13, 사용자 지시)

사용자: *"W05에서 마지막 웨이포인트 도달하면 멈추도록 하는 것 추가해줘"*

유도는 **전환 판정을 그대로** 쓴다. 마지막 다리에서 `(d - x_e) < R_switch` 가 참이면
넘어갈 다리가 없으니 임무가 끝난 것이다. 그때 둘을 한다.

| 무엇 | 어디에 | 왜 거기에 |
|---|---|---|
| 속도 명령을 0 으로 | 캔버스의 `u_d x gate` **Product** | 임무의 끝은 **그림에 보여야** 한다. 유도 블록 안에 숨기면 왜 섰는지 도면이 말하지 않는다 |
| 실행을 끝낸다 | `Stop Simulation` 하나, `stop` 출력이 먹인다 | 8주차의 임무 상태기계를 앞당겨 만들지 않는다 |
| 끄는 스위치 | `stop_at_end` Constant | 다른 모델은 0 이라 예전처럼 마지막 다리를 연장해 간다 |

> [!warning] 멈추면 **평균이 거짓말을 한다**
> "속도 루프가 1.000 m/s 를 지켰다" 는 수치는 감속 구간까지 넣으면 0.935 가 된다.
> 재는 구간을 **임무가 진행 중이던 동안**으로 좁힌다. 그러려면 로그에 **명령 자체**가
> 있어야 한다 — `u_d_eff` 를 13번째 열로 넣고 `R.u_d > 0` 으로 거른다.
> 평균을 낼 때마다 "**이 평균의 구간은 무엇인가**" 를 적어 두는 것이 규칙이다.

끝낸 뒤 `verify_…` 에 검사를 하나 더 단다: 실행이 T_final 보다 일찍 끝났는가,
마지막 위치가 마지막 웨이포인트에서 R_switch 안인가, 명령이 0 이 된 뒤 stop_hold 만큼
더 돌았는가. 세 가지가 모두 수로 나온다.

### 15-37. 사용자의 **기존 강의자료(PPT)** 를 녹여 넣을 때 (2026-10-13, 사용자 지시)

사용자: *"이 PPT의 59-71 페이지의 내용을 최대한 이해해서 강의 자료에 추가해줘... 기존
강의 자료 부분에....잘 내용을 녹여서 넣어줘"*

**새 절을 만들지 않는다.** 이미 그 주제를 다루는 절의 **유도 안으로** 넣는다. 5-5 절은

| PPT 가 말하는 것 | 강의자료의 어디로 |
|---|---|
| course 와 heading 의 구별, 두 블록도 | 5-5 절 6번(오차의 운동방정식) 바로 뒤 콜아웃 — `chi = psi + beta_c` 가 거기서 처음 나오므로 |
| 크랩각을 **직접 재는** 대안과 그 한계 | 10b 번. 적분이 왜 이기는지를 말하는 자리 |
| 보통 적분 대 비선형 적분 | 9b 번 + 새 실험 5-5c |
| 쪽 번호·저자·증명 쪽수 | 그 절의 Sources 에. **DOI 까지** (§7) |

읽는 법: `python-pptx` 로 글자를 뽑으면 **수식은 그림이라 빠진다.** 사용자가 올린
슬라이드 이미지를 함께 읽어야 식이 보인다. 뽑은 글자만으로 요약하지 않는다.

**PPT 의 수치를 그대로 싣지 않는다.** 그 수는 다른 배(와 다른 조류)의 것이다.
같은 주장을 **이 강의의 Otter 로 다시 재서** 싣고, PPT 는 출처로 적는다 —
5-5c 의 3.85 / 23.73 / 13.48 m 가 그렇게 나왔다.

**공평하게 비교한다.** 교과서형 적분을 비선형 쪽 이득(κ = 0.3)으로만 돌리면 발산해서
"교과서형은 못 쓴다" 는 과장이 된다. 그 법칙을 **그 나름대로 튜닝한** 경우(κ = 0.05)를
함께 돌려야 결론이 선다 — 그러고도 비선형이 과도 구간에서 낫다는 것이 요점이다.

### 15-39. "제대로 적용된 것인가" 는 **로그로 식을 다시 계산해서** 답한다 (2026-10-13, 사용자 질문)

사용자: *"알고리즘이 적용된 제어 성능이 expected 된 값하고 맞는가가 궁금한거야.. 제대로
적용된것인지.."*

검사에는 두 종류가 있고, 지금까지는 **첫 번째만** 있었다.

| | 무엇을 보는가 | 예 |
|---|---|---|
| 성질 검사 | 결과가 이론이 말한 **성질**을 갖는가 | 정상상태 오차 = Δ tan β, 적분이 그것을 없앤다, 한계가 추력에 닿는다 |
| **구현 검사** | 블록 안의 코드가 **강의에 적힌 그 식**인가 | 로그의 위치만으로 ψ_d 를 다시 계산해 모델의 ψ_d 와 대조 |

구현 검사의 방법은 하나다. **모델을 부르지 않는다.** 강의 본문의 수식을 검사 파일에
손으로 옮겨 적고, 로그에서 **입력만** 가져와 처음부터 다시 돌린 뒤 출력끼리 뺀다.
모델의 함수를 부르면 같은 코드를 두 번 부르는 것이라 아무것도 검사하지 못한다.

```matlab
R = W05_read('W05_F_ILOS', 'law', 3, 'V_c', 0.3);   % 로그: 위치와 psi_d
for i = 1:numel(R.t)
    ... 5-2 의 회전, 5-4 의 전환, 5-5 의 적분을 **여기에 다시 적는다** ...
end
e = max(abs(ssa(psid_recomputed - R.psi_d)));        % 0 이어야 한다
```

W05 에서 0.0e+00 deg 가 나왔다 — 전환과 적분까지 포함한 전 구간에서. 이 한 줄이
"문서와 모델이 같다" 를 말로가 아니라 수로 말한다.

> [!important] 문헌의 수치를 그대로 기대하지 않는다
> 사용자의 2025년 자료는 mean|χ−ψ| 가 1.38 / 13.63 도다. 이 강의의 Otter 는 0.098 /
> 23.0 도가 나온다 — **시나리오가 다르기 때문**이다 (다리가 조류를 가로지르고, 대지속도가
> 0.77 m/s 다). 맞춰야 하는 것은 **수가 아니라 관계**다: χ = ψ + β_c 가 성립하는가,
> 그 β_c 로 계산한 Δ tan β 가 LOS 가 남긴 오차와 같은가. 23.0 도와 2.107 m 가 1 % 안에서
> 서로를 설명하는 것이 "제대로 적용되었다" 의 뜻이다.

### 15-40. 성능을 **판정**한다 — "맞게 구현했다" 와 "잘 동작한다" 는 다른 질문 (2026-10-13, 사용자 지시)

사용자: *"알고리즘이 제대로 적용된 것은 수식이 맞는지만 보는게 아니라... expect 한
결과와 성능이 맞는지....판단하라는 거야"*

§15-39 의 구현 검사는 "블록이 그 식인가" 를 본다. 그것만으로는 **잘 도는지** 모른다.
절마다 **성능 판정 표**를 하나 둔다. 규칙은 하나 — **수를 읽기 전에 예측을 적는다.**

| 칸 | 무엇을 적나 |
|---|---|
| 무엇이 일어나야 하는가, **왜** | 제어기가 아니라 **배**에서 나오는 근거로 (선회반경, 한계, 시간척도) |
| 예측 | 숫자 하나. 범위가 아니라 값 |
| 측정 | 러너가 낸 값 |
| 판정 | as expected / 경계 / 예상 밖 — **세 번째가 나오면 그것이 그 절의 내용이다** |

W05 에서 이렇게 해서 나온 것들:

- 직선 구간: 선수각 오차 0.38°, 횡방향 0.411 m → Δ/10 보다 작다. 기대대로.
- 한계: |N| 47.15 / 47.15, X 120.00 / 120.00, n 103.93 / 103.93. **정확히 닿고 넘지 않는다.**
- 코너: 모멘트가 포화하므로 벗어남은 **유도가 아니라 선회반경**이 정한다.
  r_max 15.1 deg/s · U 1 m/s → R = 3.8 m, 측정 2.86 m (전환을 3 m 앞에서 시작하므로 더 작다).
- 시간척도: 작은 신호에서는 분리가 성립하지만 **코너에서는 깨진다** — 62° 명령에
  안쪽 루프가 8.4 s, 바깥의 Δ/U 는 5.0 s. 이것이 그 주차 성능의 **구속 조건**이다.

마지막 줄이 중요하다. 성능 판정은 "좋다"로 끝나면 안 되고, **무엇이 한계를 정하는지**로
끝나야 한다. 그래야 다음 주차가 왜 필요한지가 수로 설명된다 (6주차: 모멘트를 더,
8주차: 임무가 직각을 요구하지 않게).

### 15-41a. 한글본을 **만드는 방법** — 조각으로 쓰고, 해시로 확인한다 (2026-10-13)

한 주차가 1,000~2,700 줄이므로 한 번에 쓰지 않는다. 절 경계에서 끊어
스크래치패드에 조각 파일로 쓰고 `cat` 으로 이어 붙인다. **`sed`·`awk` 로 `.md` 를
고치지 않는다** (§5-1). 앞머리 콜아웃 40 줄은 주차마다 같으므로 조각 하나
(`ko_boiler.md`) 를 만들어 재사용한다 — W02 만 영상 표가 하나 더 들어가고,
W02 의 git 콜아웃 마지막 줄은 "이번 주는 필요하지 않다" 로 끝난다.

> [!warning] 조각 경계가 `$$` 줄에 떨어지면 수식이 조용히 깨진다
> 원문을 `sed -n 'a,bp'` 로 겹쳐 읽으면 경계의 `$$` 가 **두 조각 모두**에 들어간다.
> 이어 붙이면 `$$` 가 둘이 되어 블록이 즉시 닫히고, 그 뒤 **파일 끝까지** 수식
> 안팎이 뒤집힌다. 화면에는 멀쩡해 보이고 PDF 에서만 드러난다. 실제로 5주차에서
> 두 군데 그랬다. 경계는 `##` 제목이나 빈 줄에 둔다.

끝내기 전에 **영어본과 세 가지를 해시로 대조한다.** 하나라도 다르면 번역이 아니라
내용을 건드린 것이다.

```bash
F=lectures/W05_Waypoint_Following_and_LOS_Guidance
for f in ${F}.md ${F}_KO.md; do
  awk '/^\$\$.*\$\$$/{print; next} /^\$\$/{d=!d; next} d{print}' "$f" | md5sum   # 수식
  awk '/^```/{d=!d; next} d{print}' "$f" | md5sum                                # 코드 블록
  grep -o '](\.\./figures[^)]*\|](W05_simulink[^)]*' "$f" | sort | md5sum        # 그림 경로
done
```

첫 줄의 `^\$\$.*\$\$$` 분기를 빼면 안 된다. 1주차에는 `$$...$$` 가 **한 줄에 다 들어간**
수식이 둘 있고(§1-11, §1-12 의 "What the figure says"), 그것을 토글로 세면 그 뒤가
전부 어긋난 것처럼 보인다. 실제로 그렇게 한 번 헛다리를 짚었다.

> [!warning] `fitz` 가 있던 환경의 이야기다
> 2026-10-27 의 세션에는 Python 도 poppler 도 ImageMagick 도 없었다. 그때는
> **§15-54 의 탐침 쪽**으로 돌아서 본다. 쪽수는 세지 못하므로 세었다고 쓰지 않는다.

PDF 는 만든 뒤 `fitz` 로 본다 — `$` 가 남았는지(0 이어야 한다), 한글 글자 수가 있는지,
`�` 대체 문자가 있는지(0 이어야 한다). 쪽수는 영어본보다 조금 줄어든다:
W01 72쪽, W02 51쪽, W03 30쪽, W04 44쪽, W05 60쪽.

### 15-42. 블록의 상태는 `persistent` 이 아니라 **Unit Delay** 가 들고 있는다 (2026-10-13, 사용자 지시)

사용자: *"일곱 모델 다 unit delay로 바꿔줘"*

`persistent` 은 블록 안에 숨는다. 그래서 그 주차의 **주제인 상태**가 도면에 한 획도
나타나지 않는다 — 5주차의 ILOS 적분이 그랬다. §15-23 이 제어기를 서브시스템으로
그리게 한 것과 같은 이유로, 상태도 밖으로 꺼낸다.

| | `persistent` | Unit Delay |
|---|---|---|
| 상태가 보이는 곳 | 블록을 더블클릭해야 | **도면 위에 이름 붙은 포트와 선** |
| 초기값 | `if isempty(k), k = 1; end` | 블록 파라미터 `[1;0;0]` |
| 실행마다 초기화 | 언어가 알아서 | Unit Delay 가 첫 스텝에 초기값을 낸다 — 같다 |
| 샘플시간 | `set_mlfcn(..., 'h')` 가 **필수** | 함수와 Unit Delay 둘 다 `h` |

> [!important] 같아지는 조건은 **계산 순서** 하나다
> 한 스텝의 **모든 출력이 (입력, 직전 상태) 만의 함수**여야 한다. 5주차 유도가
> 그랬다 — $\pi_p$·$y_e$·$\psi_d$ 는 **옛** 상태로, `wp` 와 `gate` 는 갱신한 **새**
> 상태로 구한다. 그 순서를 지키면 함수를 무상태로 바꾸고 상태를 Unit Delay 로
> 돌려도 **비트 단위로 같다.** 순서를 흐트러뜨리면 한 스텝씩 어긋난다.

상태가 셋 이상이면 Unit Delay 를 여러 개 두지 않는다 — **뒤로 가는 선이 그만큼
늘어나고** CLAUDE.md §5 는 두 개 이하다. `Mux → Unit Delay → Demux` 로 통로를
하나로 묶되 포트 이름은 셋으로 남긴다. 통로는 캔버스 맨 아래로 내린다.

신호로 들어온 지표(`k`)는 `round` 하고 범위로 가둔다. 블록이 혼자 들고 있을 때는
필요 없던 것이고, 도달 가능한 값 위에서는 항등이라 결과를 바꾸지 않는다.

> [!warning] 바꾸기 **전에** 기준선을 뜬다
> 일곱 모델 × 네 법칙의 로그를 `.mat` 에 저장해 두고, 바꾼 뒤 `max|diff|` 를 센다.
> 0 이 아니면 바꾼 것이 아니라 **망가뜨린** 것이다. 2026-10-13 에 28 실행 전부
> 0.000e+00 이었다. 절 스크립트 재실행과 `vault_number_audit` 은 그 다음이다.

### 15-43. 알고리즘은 **하나에 MATLAB Function 하나**, 고르는 것은 **외부 플래그** (2026-10-14, 사용자 지시)

### 15-44. MATLAB Function 의 상수는 **파라미터가 아니라 포트** (2026-10-14, 사용자 지시)

사용자: *"matlab function은 가능하면 h 값 (샘플링 타임도) 다 constant 값으로
외부에서 입력할 수 있도록 지금은 파라미터가 된것 같아"*

`h`·`Delta`·`kappa`·`y_pont`·`n_max` 가 함수 서명의 파라미터면 도면에 **한 획도**
나타나지 않는다. 학생은 블록을 더블클릭해서야 그것이 있는 줄을 알고, 그래서
"이 모델이 무엇을 지시받았는가" 를 그림에서 읽을 수 없다.

| 무엇 | 어디에 | 왜 |
|---|---|---|
| 샘플링 시간 `h` | **입력 포트.** 캔버스의 Constant | 블록이 이산이면 그 스텝이 도면에 있어야 한다 |
| 명령 (`Delta`·`R_switch`·`kappa`·`u_d`·웨이포인트) | **입력 포트.** 캔버스의 Constant | CLAUDE.md §5 "명령 대 계수" |
| 선체 상수 (`y_pont`·`k_pos`·`n_max`) | **입력 포트** | 선체가 바뀌면 코드가 아니라 Constant 가 바뀐다 |
| 게인 | `Gain` 블록의 **값** (변수 이름) | 계수는 블록이 들고, 신호가 아니다 |

전부 작업공간을 읽으므로 Command Window 의 한 줄 다음 Run 이 수정의 전부인 것은
그대로다. 달라지는 것은 **도면이 무엇을 보이는가** 뿐이다.

### 15-45. 두 판본은 **재서** 맞춘다 — 읽어서 맞추지 않는다 (2026-10-14)

사용자: *"너가 이 강의자료를 그대로 읽었을 때 이해가 되는지..잘 생각해봐…
이해가 잘 여전히 않돼...숫자는 많고..테이블은 많은데..먼가 설명이 난잡해"*

영문을 줄이고 한글본을 "같이 줄였다" 고 믿는 것은 **거의 틀린다.** W05 에서
영문 §5-7 은 174 줄·표 3·행 21 이었고 한글은 178/3/25, 실험 5-7 은 영문 151/7/46
한글 202/11/88 이었다. 읽어서는 그 차이가 보이지 않는다. **재면 보인다.**

```bash
awk '/^#+ /{if(h!="")printf "%-52s lines %4d  tables %2d  rows %3d\n",h,NR-s,t,r;
            h=$0; s=NR; t=0; r=0; inT=0}
     /^\|/{r++; if(!inT){t++; inT=1}} !/^\|/{inT=0}
     END{printf "%-52s lines %4d  tables %2d  rows %3d\n",h,NR-s,t,r}' <파일.md>
```

두 판본에 돌려 나란히 놓고, **절마다 세 수가 같아질 때까지** 고친다. 끝나면
숫자 집합도 대조한다 — `grep -o '[0-9]\+\.[0-9]\+' | sort -u` 가 한쪽에만 있는
수를 내놓으면 한 판본이 다른 쪽에 없는 주장을 하고 있는 것이다.

> [!note] 1~2 줄 차이는 남겨 둔다
> 머리말의 참고자료 콜아웃은 언어마다 길이가 다르다. 본문 절에서 세 수가 같으면 된 것이다.

**산문을 줄이는 규칙 여섯.** 사용자가 "난잡하다" 고 한 것은 분량이 아니라 **형식**이었다.

| 증상 | 고치는 법 |
|---|---|
| 읽기 표가 다섯 줄을 넘는다 | **네 줄까지.** 이웃한 칸·열은 한 줄로 합친다 (`1번과 2번 칸`) |
| 표의 머리가 비어 있다 | 그것은 표가 아니라 **목록**이다. 불릿으로 바꾼다 |
| 그림·콜아웃이 유도 중간에 있다 | 그 그림이 **여담**의 것이면 여담으로 내린다. 유도는 끊지 않는다 |
| 번호가 `9b`·`10b` 로 간다 | 번호는 단조로워야 한다. 다시 매기고, **모든 판본**에서 `N 줄`·`line N`·`9b`·`10b` 를 grep 한다 |
| 출처가 측정 결과보다 앞에 있다 | 절의 **마지막**이 출처다. 유도가 예측한 수를 먼저 보인다 |
| 앞 주차의 유도를 다시 쓴다 | **§번호로 가리킨다.** W05 의 안티와인드업은 3주차 §3-F 한 문장으로 끝낸다 |

맨 아래 줄이 특히 값을 번다. 영문 실험 5-7 의 안티와인드업은 식 하나·기호표·측정표
없이 **한 문단**이고, 그 문단이 "왜 여기서는 거의 보이지 않는가" 까지 말한다 —
3주차에서 유도한 것을 다시 유도하지 않기 때문에 그만큼이 들어갈 자리가 생긴다.

> [!warning] 지운 표에 **살아 있는 유일한 수**가 있었는지 본다
> 한글본의 안티와인드업 표에는 `0.66`·`0.92` s 가 있었고 러너는 `0.68`·`0.94` 라고
> 말한다. 표를 지우면서 틀린 수도 사라졌다 — 운이 좋았다. 표를 지우기 전에 그 안의
> 수가 본문이나 다른 판본에도 있는지 확인하고, 없으면 **본문 문장에 옮긴 뒤** 지운다.
