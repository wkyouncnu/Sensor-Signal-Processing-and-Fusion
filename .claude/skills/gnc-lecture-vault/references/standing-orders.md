# 상시 지침 — 사용자가 못박은 것들

이 문서는 **사용자가 대화 중에 준 지침을 누적하는 곳**이다.
새 지침이 오면 여기에 먼저 적고, 그 다음에 자료를 고친다.

---

## 0. 새 지침이 오면 — 자동으로 하는 일

> 사용자 원문: **"항상 나중에 새로운 지침이 오면 계획도 업데이트 해주고, 스킬도
> 업데이트 해주고, 내용이 바뀌면 md와 PDF로 업데이트 해줘"**
> 그리고 **"새로운 지침이 오면 항상 스킬에 추가 자동으로 해줘"**

지침을 받으면 **묻지 않고** 다음을 전부 한다.

| # | 하는 일 | 어디에 |
|---|---|---|
| 1 | 지침을 **한 줄로 요약해 이 문서에 추가** | `references/standing-orders.md` §4 |
| 2 | 해당하는 규칙 문서를 고친다 | `difficulty.md` · `results-and-figures.md` · `figures-svg.md` · `model-layout.md` · `lecture-md.md` |
| 3 | 형식 계약을 고친다 | `CLAUDE.md` |
| 4 | **계획을 고친다** | **`PLAN.md`** — 볼트 루트. 다른 곳에 계획을 두지 않는다 |
| 5 | **이미 나간 자료를 고친다** | 해당 `.md` 전부 |
| 6 | **PDF 를 다시 뽑는다** | `bash _tools/md2pdf.sh <바뀐 파일>` |
| 7 | 점검 | `vault_check.sh` → 0 건 |
| 8 | **바로 올린다** | `bash _tools/git_autopush.sh` — 세션 끝을 기다리지 않는다 |

> 사용자 원문: **"수정된 사항이 있으면 항상 푸쉬해"** (2026-09-06)
>
> SessionEnd 훅에 맡기지 않는다. **고친 것이 있으면 그 자리에서 push 한다.**
> 세션이 끊기거나 방향이 바뀌면 훅이 돌지 않고, 고친 것이 로컬에만 남는다.
> 실제로 이 지침은 "여기가 아니었다" 로 방향이 바뀐 직후에 나왔다 — 그때
> 볼트에는 안 올라간 수정 3건이 남아 있었다.

> [!important] "항상 push" 와 "`vault_check` 0 건에서만 push" 가 부딪힐 때
> **push 는 한다. 그리고 같은 세션 안에서 0 건까지 고친다.**
> 두 지침의 목적이 다르다 — 앞의 것은 *잃어버리지 않기*, 뒤의 것은 *깨진 상태를
> 기록으로 남기지 않기*다. 올려 두고 고치면 둘 다 지켜진다. 고치지 않고 넘어가면
> 뒤의 것을 어긴 것이다. 실제로 2026-09-08 에 13 건인 채로 올라갔고, 그중 12 건은
> **벤더링한 MSS 의 README** 를 우리 문체 규칙으로 잰 허위 지적이었다. 검사기를
> 고쳐서(`vault_check.sh` 의 `VENDOR`) 0 건으로 되돌렸다.
>
> **검사기가 남의 파일을 고치라고 말하기 시작하면 검사기를 못 믿게 된다.**
> 볼트 안에 남의 코드를 두면 검사에서 빼는 것까지가 한 벌이다.

**6번을 빠뜨리지 않는다.** MD 만 고치고 PDF 를 두면 학생이 보는 것은 옛날 것이다.

### 0-0. **새 작업 방식은 스스로 훅을 걸어 스킬로 남긴다**

> 사용자 원문: **"새로운 업무 스타일은 항상 스스로 훅을 걸어서 스킬로 저장해주는
> 습관을 들여줘"** (2026-09-06)

지침이 "이렇게 해라" 라고 말로 오지 않아도 된다. **일하다가 방식이 하나 생기면**
— 새 도구를 만들었든, 확인 절차를 하나 늘렸든, 같은 실수를 두 번 째 밟았든 —
그 자리에서 스킬에 적는다. 다음 세션의 나는 이 대화를 기억하지 못한다.

| 언제 | 무엇을 남기나 |
|---|---|
| 새 도구·스크립트를 만들었다 | 쓰는 법 한 줄 + **왜 만들었는지**(어떤 실패가 계기였는지) |
| 확인 절차를 하나 늘렸다 | 그 절차를 `CLAUDE.md` §4 의 번호 규칙으로, 근거는 스킬로 |
| 같은 지뢰를 또 밟았다 | 증상·원인·고침 세 칸 표에 **한 줄 추가**. 이미 있으면 사례를 덧붙인다 |
| 기계로 거를 수 있는 규칙이 생겼다 | `scripts/vault_check.sh` 에 절을 하나 추가한다 — 말로만 두지 않는다 |

**"나중에 정리하겠다" 를 하지 않는다.** 실제로 `sed` 가 역슬래시를 먹는다는 것을
스킬에 적어 놓고도 같은 세션에서 두 번 더 밟았다(§5-1 · `results-and-figures.md` §2-9).
적는 것만으로는 모자라니, **거를 수 있는 것은 `vault_check.sh` 로 내린다.**

### 0-1. 지침이 없어도, **새 작업을 하면** 같은 것을 갱신한다

> 사용자 원문: **"계획 파일도 최신화 스킬도 최신화 claude.md 도 최신화 다 해줘...
> 새로운 작업 하면 항상 최신화 하는 것을 스킬에 넣어줘"**

새 지침을 받았을 때만이 아니다. **모델을 하나 만들었거나, 절을 하나 추가했거나,
그림을 하나 그렸거나, 폴더를 옮겼으면** 그 작업이 끝나기 전에 셋을 갱신한다.

| 무엇을 했든 | 반드시 손대는 곳 넷 |
|---|---|
| 새 주차·절·모델·그림·스크립트 | ① `PLAN.md` ② 이 스킬 ③ `CLAUDE.md` ④ **GitHub 에 push** |

- `PLAN.md` — §2 진행 상황 표의 상태, §3 다음에 할 일, 새로 생긴 산출물
- 스킬 — 새 관용구·함정·규칙이 생겼으면 해당 `references/*.md`, 그리고 §4 누적 대장 한 줄
- `CLAUDE.md` — 폴더·파일 목록이 바뀌었거나 형식 규칙이 생겼으면
- **GitHub** — SessionEnd 훅이 `_tools/git_autopush.sh` 로 알아서 올린다.
  손으로 올리려면 같은 스크립트를 부른다 → `git-and-history.md`

**"나중에 한꺼번에" 는 하지 않는다.** 대화가 길어지면 무엇을 만들었는지 잊고,
다음 세션은 옛날 계획을 읽는다.

## 1. 모든 강의자료 첫머리 — Reference material 콜아웃

> **"이 링크를 첫장에 모든 강의 슬라이드에 강조해줘 ... 가장 처음에"**, 그리고
> **"결국 3개의 강의와 시뮬링크 온램프와 시뮬링크 강의는 항상 첫장에 작은 글자로
> 링크 타고 들어갈 수 잇게 요약해줘 ... 이것이 reference material이고 내 강의엿다는 것을
> 강조해주고 ... 선수 지식이 부족한 사람들은 추가해달라고 ... 모든 슬라이드에 동일하게"**

모든 주차·부록 `.md` 의 **H1 바로 다음, 다른 무엇보다 먼저** 이 콜아웃이 들어간다.
**원본은 `_templates/week.md`** 에 있으니 거기서 복사한다. 문구를 주차마다 바꾸지 않는다.

내용은 두 덩어리다.

**① 사용자 본인의 강의 다섯** — **기초부터** 순서를 지킨다. "내 강의였다"는 것을 반드시 밝힌다.

### 1-1. 바로 뒤에 — 강의자료를 받고 최신으로 맞추는 법 (Windows) — 2026-09-21

> **"이 깃헙을 윈도우에서 항상 git clone 하고 git pull? ... 매번 수업 전에 수정된 부분만
> 다운로드 하는 방법을 첫장에 정리해서 항상 넣어줄래?"**

Reference material 콜아웃 **바로 뒤**, 모든 주차·부록에 같은 문구로
`[!tip] Getting the course files, and keeping them current (Windows)` 를 둔다. 원본은
`_templates/week.md`. 저장소 첫 화면인 `README.md` 맨 위에는 같은 내용을 한국어로 둔다.

| 들어가는 것 | 왜 |
|---|---|
| `winget install --id Git.Git -e` | Windows 에서 Git 을 까는 한 줄 |
| 처음 한 번 `git clone https://github.com/wkyouncnu/Sensor-Signal-Processing-and-Fusion.git` | HTTPS — 학생 PC 에는 SSH 키가 없다 |
| 수업 전마다 `git pull` | 바뀐 파일만 받는다. 이것이 사용자의 요구 그 자체 |
| `Already up to date.` 를 판정 기준으로 | 돌려 볼 수 없는 학생 환경의 출력은 지어내지 않고 기준만 적는다 (§8) |
| 비공개 저장소 — 강사가 권한을 준 계정으로 로그인 | 권한이 없으면 clone 이 인증에서 멈춘다 |
| 복사본에서 실험, 충돌하면 `git stash` → `git pull` → `git stash pop` | 학생이 고친 파일 때문에 pull 이 거부되는 것이 가장 흔한 사고 |
| MSS 는 저장소에 없다, `Tools\MSS` 에 둔다 | `.gitignore` 가 MSS 를 뺀다. `mss_path` 가 `<강의폴더>/Tools/MSS` 를 찾는다 |

> [!warning] 사용자에게 알려야 할 것 — 저장소가 비공개다
> 학생이 clone 하려면 **Collaborator 로 초대하거나 저장소를 공개**해야 한다. 공개로 바꾸는 것은
> 사용자의 결정이다(상위 폴더의 출석부는 애초에 저장소 밖이다). 이 볼트에서 임의로 바꾸지 않는다.

### 1-2. 그 주차에만 해당하는 핵심 외부 자료 — 2026-09-21

> **"위 유투브 링크도 2주차에만 첫장에 추가해주고....중요한 강의 reference라고.."**

외부 영상·문서가 **한 주차의 뼈대**가 되면, 그 주차 첫 장(위 두 콜아웃 다음)에

영상 내용은 **자막을 실제로 받아 읽고** 쓴다. 제목만 보고 요약하지 않는다. 자막 받는 법은

## 2. 설명은 간결하고, 최대한 쉽게

> **"항상 설명은 간결하고 이해하 최대한 쉽게"**

- 한 문단 3~4줄. 넘으면 불릿으로 쪼갠다
- 한 문장에 주장 하나
- 어려운 것은 **깊이**에서 나와야지 **밀도**에서 나오면 안 된다
- 곁가지는 `[!note]` 하나로, 그 이상은 부록으로
- 쪽수는 세지 않는다 → `difficulty.md`

## 3. 그림이 있어야 설명이 좋아진다

> **"그림이 있어야 설명이 좋아져"**, **"기존의 그림들을 캡처해서 넣어도 좋고 너가 만들어도 좋고"**

- 새로운 개념·좌표계·각도·배치를 설명할 때는 **글보다 그림을 먼저** 생각한다
- 그림은 직접 그린 SVG 를 우선한다 — 벡터라 확대해도 깨지지 않고, 하우스 스타일이 통일되고,
  출처 문제가 없다. `figures/` 에 둔다
- 그림마다 **"reading the figure" 표**를 붙인다 → `results-and-figures.md`

### 3-1. 그림과 수식은 완성 후 반드시 더블 체크

> **"그림을 완성하면 수식도 마찬가지인데 항상 그림의 기호나 방향 선들이 겹치는지
> 제대로 표현되었는지 더블 체크 해줘"**

**렌더링해서 눈으로 본다.** 브라우저 패널에 SVG 를 띄우거나, PNG 를 Read 로 연다.

| 검사 | 무엇을 보는가 |
|---|---|
| 겹침 | 라벨끼리, 라벨과 선, 라벨과 도형이 겹치는가 |
| 방향 | 화살표가 맞는 쪽을 가리키는가. NED 에서 +yaw 는 시계방향인가 |
| 기호 | 본문 수식의 기호와 그림의 기호가 **같은 글자**인가 |
| 부호 | 그림의 부호가 본문의 부호와 같은가 (z 아래, pitch 는 bow-up) |
| 잘림 | viewBox 밖으로 나간 요소가 없는가 |
| 수치 | 그림에 적힌 숫자가 러너 출력과 같은가 |

수식도 같다. **PDF 로 뽑은 뒤** 렌더된 본문에 `$` 가 남았는지, 첨자·행렬이 깨지지 않았는지 본다.

### 3-2. 3차원 그림은 **사영으로 계산해서** 그린다 — 눈대중 금지

> 사용자 원문: **"회전 롤링 모멘트, 피칭 모멘트, 요잉 모멘트의 원 화살표가 축하고 맞지 않아 ...
> 그림은 항상 더블 체크해서 검토해야해 ... 3차원에서 보고 잘 검토해줘"**

3차원 그림(선체 + 축 + 모멘트, 좌표계 회전, 추진기 배치)에서 **원·호를 손으로 놓으면 반드시 틀린다.**
축 옆에 떠 있는 동그라미는 "그 축 둘레의 회전"으로 읽히지 않는다.

**규칙 — 진짜 정사영을 하나 정하고, 모든 요소를 그 사영으로 계산한다.**

화면 오른쪽 $\hat r$ 과 화면 아래 $\hat d$ 를 3차원에서 **서로 직교하는 단위벡터**로 잡으면
점 $v$ 는 $(v\cdot\hat r,\; v\cdot\hat d)$ 에 찍힌다. 한 매개변수 쌍이면 충분하다.

```
r = ( cos a,          sin a,          0     )
d = (-sin b * sin a,  sin b * cos a,  cos b )
=> P(x) = ( cos a, -sin b sin a )   P(y) = ( sin a, sin b cos a )   P(z) = ( 0, cos b )
```

| 검사 | 무엇을 보는가 |
|---|---|
| **모멘트 호** | 축 $\hat a$ 둘레의 모멘트는 $\hat a$ 에 **수직인 평면 위의 원**이다. 사영하면 타원이고, **타원 중심이 반드시 축선 위에 있어야 한다.** 원의 매개변수는 켤레 반지름 두 개로 $p(t)=C+\cos t\,\hat u+\sin t\,\hat w$, 꺾은선으로 뽑는다 |
| **회전 방향** | 오른손 법칙은 $x$ 둘레 $y\to z$, $y$ 둘레 $z\to x$, $z$ 둘레 $x\to y$. 매개변수를 그 순서로 증가시키면 화면상 방향은 저절로 맞는다 |
| **앞뒤** | 화면 안쪽 $\hat n=\hat r\times\hat d$. $\hat n\cdot\hat m>0$ 인 면은 **보이지 않는다.** 보이는 면만 폴리곤으로 그린다 |
| **축소율** | 세 축의 3차원 길이가 같으면 화면 길이는 $|P(\hat x)|,|P(\hat y)|,|P(\hat z)|$ 비율로 **달라야** 한다. 셋을 같은 픽셀 길이로 그리면 틀린 그림이다 |
| **연결** | 축선을 모멘트 타원 중심까지 **점선으로 연장하고 중심에 점을 찍는다.** 그래야 "이 축 둘레"가 보인다 |

계산은 `_tools/` 에 **재현 가능한 스크립트**로 남긴다 — 예: `_tools/w01_6dof_arcs.awk` 가
`figures/w01-6dof.svg` 의 세 호를 계산한다. 손으로 좌표를 고치지 않는다.

그리고 **고친 뒤 다시 렌더해서 눈으로 본다.** 한 번 고쳤다고 끝이 아니다.

## 3-3. 모든 수식은 **유도 과정**을 보여준다. 그리고 검증한다

> 사용자 원문: **"너무 복잡한 내용들은... 특별히 surge 제어에서 첫번째 나오는 수식들이
> 어떻게 3자유도 full 모델에서 유도가 되는지... 모든 수식들이 바로 나오는게 아니라..
> 그 전체 수식에서 유도되는 과정도 넣어줘"**, **"heading control에서 나오는 heading
> 2차 미분 방정식도 어떻게 유도되는지 운동모델로부터"**, **"너가 작성한 수식들이 정말
> 옳은 것인지도 항상 검증해주고"**, **"어디서 가지고 왔는지 언급도 해주고"**

### 규칙 하나 — 수식을 **떨어뜨리지** 않는다

절의 첫 수식이 하늘에서 내려오면 안 된다. **전체 모델에서 시작해서, 무엇을 버렸는지
밝히고, 남는 것을 쓴다.** 대학원생이 못 따라올까 봐가 아니라, 버린 항이 나중에
돌아오기 때문이다.

```
6자유도 Mν̇ + C(ν)ν + D(ν)ν + g(η) = τ
   ↓  무엇을 왜 버리는가 (표로)
3자유도 수평면 M ν̇ + C(ν)ν + D(ν)ν = τ,  ν = [u v r]ᵀ
   ↓  어느 행을 보는가, 나머지 행의 결합항은 왜 무시되는가
1자유도 (m − X_u̇)u̇ = X + X_u u
```

| 요구 | |
|---|---|
| **출발점** | 항상 전체 모델. 3자유도 `M`·`C`·`D` 를 **성분까지 써 놓고** 시작한다 |
| **버린 것** | 버린 항마다 한 줄 근거. "작다" 로는 부족하다 — 얼마나 작은지, 언제 커지는지 |
| **한 단계씩** | 한 줄에 조작 하나. `\begin{aligned}` 로 세로로 쌓는다 |
| **출처** | Fossen Handbook §번호, MSS 파일명·행 번호, 논문. **"어디서 가져왔는지" 를 반드시 쓴다** |
| **되돌아보기** | 절 끝에 "버린 항이 언제 돌아오는가" 를 한 줄 |

### 규칙 둘 — 쓴 수식을 **검증한다**

문서에 실린 수식은 전부 다음 중 하나로 확인한 것이어야 한다. 확인하지 않은 수식은 싣지 않는다.

| 검증 | 어떻게 |
|---|---|
| **차원** | 항마다 단위를 맞춰 본다. 가장 싸고 가장 많이 잡아낸다 |
| **극한** | 계수를 0 이나 ∞ 로 보내면 아는 답이 나오는가 |
| **부호** | 감쇠는 음수, 복원은 복원하는 방향인가. NED 에서 z 아래 |
| **수치** | MATLAB 으로 **실제로 계산**해 본다. 전달함수라면 `tf`·`step`·`pole` 로 시뮬레이션 결과와 대조 |
| **출처 대조** | Fossen Handbook / MSS 소스와 항 대 항으로 맞춰 본다. `otter.m` 이 최종 심판이다 |

- **수치 검증을 러너 안에 남긴다.** 손으로 유도한 값과 시뮬레이션 값을 나란히 찍고,
  일치하는 자릿수를 문서에 쓴다. 그것이 "검증했다" 의 유일한 증거다
- 유도가 근사면 **근사라고 쓴다.** 어긋나는 조건도 함께 쓴다

**계수는 `_tools/verify_constants.m` 이 검증한다.** `otter.m` 55~120행을 그대로 다시 세워
`M` 을 읽고, 강의가 인용하는 16개 값을 전부 대조한다. MSS 가 바뀌면 이것이 먼저 알아챈다.

> [!caution] 유한차분으로 `M(1,1)` 을 재려고 하지 말 것 — 그럴듯하게 틀린다
> "힘을 주고 가속도를 재서 나눈다" 는 검증은 여기서 **틀린 값**을 준다.
> `otter.m` 은 `nu_dot = M \ (tau - ...)` 를 적분하는데 6×6 `M` 이 블록대각이 아니다
> (CG 오프셋이 surge 를 heave·pitch 와 묶는다). 그래서
>
> ```
> udot = [inv(M)]_11 * X      not      X / M(1,1)
> ```
>
> 이고, `X/udot` 은 `1/[inv(M)]_11 = 76.71` kg 을 돌려준다. 진짜 `M(1,1)` 은 85.50 kg 이다.
> **10% 가 어긋나는데 숫자만 봐서는 잘못된 양이라는 표시가 없다.** 실제로 이 함정에
> 한 번 걸렸다. 행렬 성분이 필요하면 **행렬을 다시 세워서 읽는다.**

### 규칙 셋 — 표준 모델을 빼먹지 않는다

그 분야에 이름 붙은 모델이 있으면 **반드시 언급한다.** 학생이 논문을 읽을 때 만나기 때문이다.

- 선수각 → **Nomoto 1차·2차 모델**. 2차에서 1차로 어떻게 줄어드는지, 시간상수 `T = T₁ + T₂ − T₃`
- 조종성 → Norrbin, 비선형 Nomoto
- 그 모델이 이 강의의 플랜트와 어떻게 다른지도 한 줄

### 규칙 넷 — **고급 알고리즘은 파라미터 유도까지 간다**

> 사용자 원문: **"ILOS ALOS 의 경우는 모든 수식과 각 파라미터 유도과정까지 더 자세히
> 들어가야 해...고급 알고리즘인 경우 이렇게 해줘"**

기본 알고리즘(P 제어, LOS)은 결과 수식과 극한 셋이면 족하다. **적응·최적·관측기처럼
이름 붙은 고급 알고리즘**은 다르다. 학생이 논문을 읽고 자기 문제에 옮기려면
**왜 그 항이 그 모양인지**를 알아야 하고, 그것은 파라미터 하나하나의 유도에 들어 있다.

어떤 것이 고급인가 — ILOS · ALOS · 적응제어 · 칼만/관측기 · MPC · 최적배분(WLS·QP) ·
파랑필터. 아래 **여섯 가지를 전부** 싣는다.

| # | 무엇을 | 왜 |
|---|---|---|
| 1 | **오차 동역학부터** 세운다 | 알고리즘은 무엇을 0으로 만들려 하는가. $\dot y_e = U\sin(\chi-\pi_p)$ 같은 한 줄이 없으면 뒤가 전부 공중에 뜬다 |
| 2 | **Lyapunov 함수를 고른 이유** | $V$ 를 던져놓지 않는다. 각 항이 어느 오차를 재는지, **가중치가 왜 그 값인지**($U/2\gamma$ 의 $\gamma$ 가 왜 거기 있는지) |
| 3 | **$\dot V$ 를 손으로 전개** | 중간 줄을 생략하지 않는다. $\sin(a-b)$ 전개, $\cos b = \Delta/\sqrt{\Delta^2+y_e^2}$ 대입까지 |
| 4 | **적응법칙이 "강제"되는 지점** | 갱신식은 고른 것이 아니라 **교차항을 소거하려면 그것뿐**이라는 것을 보인다. 이것이 이 규칙의 핵심이다 |
| 5 | **파라미터마다 표** — 기호 / 역할 / **단위** / 크기를 정하는 근거 | $\gamma$ 의 단위가 rad/(m·s) 라는 것을 알아야 0.02 가 왜 큰지 안다 |
| 6 | **가정과 그 한계** | USGES 인가 GES 인가, 준전역인가 전역인가. 어떤 가정이 깨지면 무너지는가 |

그리고 **검증**은 규칙 둘대로 하되 두 가지를 더한다.

- **파라미터 스윕을 실제로 돌려** 그 값이 최선임을 표로 보인다. "경험칙이라서"는 근거가 아니다
- **$V(t)$ 를 시뮬레이션에서 그려본다.** 단조감소가 아니면 **왜 아닌지를 쓴다** —
  대개 유도가 내부 루프를 무한히 빠르다고 가정했기 때문이고, 그것을 숨기지 않는다

> [!warning] 출처를 읽을 수 없으면 그렇게 쓴다
> 논문 PDF 에서 수식을 추출하지 못했으면 **유도해서 싣고, 유도했다고 밝힌다.**
> 읽지 않은 식을 원저자의 것으로 인용하지 않는다. W05 §5-9 의 ALOS 가 그 예다.

## 3-4. Simulink 그림도 가독성이 규칙이다

> 사용자 원문: **"모든 시뮬링크 파일 안에 잇는 subsystem 도 선들이 겹치지 않는지
> 정리해주고, error 계산할때 +- 하는 부분의 동그라미도 너무 커... mss 보면서 잘 정리해줘...
> 작고... 가독성 좋게"**

| 항목 | 규칙 |
|---|---|
| **Sum 블록** | `IconShape = 'round'`, 크기 **20×20**. 기본값은 너무 크다. MSS 데모가 그렇게 쓴다 |
| **선 겹침** | **`check_overlaps(mdl)` 이 0** 이어야 한다. 최상위와 **모든 서브시스템**. 눈으로만 보지 않는다 |
| 선 교차 | 블록을 옮겨서 없앤다. 어쩔 수 없으면 이유를 댈 수 있어야 한다. **교차는 괜찮고 겹침은 안 된다** |
| 포트 정렬 | `row_feed` 로 소스를 **자기 포트 높이**에 놓는다. 직선은 겹칠 수 없다 |
| 꺾이는 선 | `lane_line` 으로 **이름 붙인 수직 통로**를 준다. autorouting 에 맡기지 않는다 |
| 포트 높이 | `port_xy` 로 **읽는다.** 공식으로 계산하면 몇 픽셀씩 틀려 사선투성이가 된다 |
| 행 간격 | **52 px 이상.** 30 px 블록 + 그 아래 이름이 들어갈 최소값 |
| 확인 | `print('-s<모델>','-dpng')` 로 뽑아 **눈으로 본다.** 서브시스템도 각각 뽑는다 |

> [!important] 순서가 중요하다
> 1. 행을 정의하는 Mux · Demux · 큰 함수 블록을 **먼저** 만든다
> 2. `port_xy` 로 행 높이를 **읽는다**
> 3. 나머지 블록을 그 행에 놓고 잇는다
>
> 자세한 것은 `simulink-gnc-models/references/model-layout.md` 의
> **"선이 겹치면 안 된다 — 규칙 셋과 도구 넷"**.

## 5. 도구 사용 사고 — 반복하지 말 것

### 5-1. `.md` 안의 LaTeX 에 `sed`·`awk`·`perl` 을 쓰지 않는다

2026-09-05, `\|` 를 `\lvert` 로 바꾸려던 `perl -pi -e` 한 줄이 **W01 전체를 망가뜨렸다.**

무엇이 어떻게 터졌나:

| 문제 | 결과 |
|---|---|
| 셸 따옴표 안에서 `\|` 가 **정규식 교대(alternation)** 가 됐다 | 역슬래시 하나에 매치 |
| 치환문의 `\r` 이 **캐리지 리턴**으로 해석됐다 | 파일에 CR 2190개 |
| `-p` 가 **모든 줄**에 적용됐다 | 1094줄에 쓰레기 삽입, 줄 첫 역슬래시 97개 소실 |

같은 날 `awk` 도 `\l`·`\m` 을 "escape sequence treated as plain" 으로 먹었고,
`sed` 는 치환문의 `\` 를 다르게 셌다.

> [!caution] `.md` 의 수식은 **Edit 도구로만** 고친다
> 세 도구 모두 역슬래시를 자기 방식으로 해석한다. LaTeX 은 역슬래시가 전부다.
> `replace_all` 이 필요하면 Edit 도구의 그 옵션을 쓴다.
> `sed`/`awk`/`perl` 은 **역슬래시가 없는 텍스트**에만 쓴다.
>
> 꼭 스크립트로 해야 하면 `index()`/`substr()` 만 쓰는 awk 를 **파일로 작성해서**
> `-f` 로 부른다. `sub()`·`gsub()` 는 치환문에서 `&` 와 `\` 를 특별 취급하므로 쓰지 않는다.

### 5-2. 망가뜨렸으면 **원본 크기로 복구되었는지**까지 확인한다

- 손상 사본을 먼저 따로 남긴다 (`cp file /tmp/x.corrupt.bak`). 그것이 유일한 복구 근거다
- 삽입인지 **치환**인지 가른다. 지우기만 하면 잡아먹힌 글자가 안 돌아온다 —
  W01 은 줄 맨 앞 삽입이었고, A1 은 역슬래시 치환이었다. 처리가 달라야 했다
- 복구 후 **PDF 크기가 사고 전과 같은지** 본다. W01 은 2217 KB → (사고) → 2217 KB 로 돌아왔다
- `$$` 짝수, 절 개수, 줄 수, 그리고 **렌더해서 눈으로** 확인한다

## 6. 완성된 자료를 검토하는 법 — 2026-09-05 W01~W05·A1 검토에서

`vault_check.sh` 는 **형식**만 본다. 아래 넷은 전부 그것을 통과한 상태에서 나왔다.
새 주차를 끝냈다고 검토가 끝난 것이 아니다.

### 6-1. 절 스크립트를 전부 돌려 문서의 수와 대조한다

이것이 가장 값이 크다. 30 개 스크립트를 돌려 문서에 적힌 수를 한 줄씩 맞춰 보면
형식 검사가 못 보는 것이 나온다. 실제로 나온 것:

| 무엇 | 어디 |
|---|---|
| 표에 `11.40`, 러너는 `11.54` | W03 §G — 같은 표의 다른 칸 `1.8e-1` 도 실제는 `7.0e-1` 이었다 |
| 서술의 `factor of 38`, 실제 `37.2` | W03 §I |
| `about 700 to 3000 N` 인데 실제는 `149.3 to 2979.2` | W03 §D — **아래 6-3** |

> **표와 서술에 같은 수를 두 번 적으면 언젠가 어긋난다.**
> 서술은 표를 가리키거나("표의 마지막 열"), 둘 다 러너 출력에서 만든다.

### 6-2. 그림 설명이 그림·자기 자신과 모순되지 않는가

W01 E 절의 한 설명 안에서 이런 일이 있었다.

- 같은 불릿 목록 위쪽: "narrowest at the **bottom**, 0.5286 m/s with it ahead"
- 네 불릿 아래: "a current stronger than the vessel makes the **northern** part of the egg collapse"

극좌표에서 좁은 쪽은 180°(아래)다. **자기 설명끼리 어긋난 것**이라 그림을 봐야만 잡힌다.

### 6-3. 그림에서 눈으로 읽은 수를 싣지 않는다

`about 700 N` 은 그림에서 읽은 값이었고, 실제 측정은 `149.3 N` 이었다 — 끝점을 잘못 짚어
**네 배 이상 틀렸다.** `about` 이 붙어 있어도 틀린 수는 틀린 수다.

> 고치는 법은 문장을 다듬는 것이 아니라 **러너에 열을 하나 더하는 것**이다.
> `max(abs(R{i}.y(:, c.X_cmd)))` 한 줄이면 그 수가 러너 출력까지 추적된다.

### 6-4. 주차 번호를 바꾸면 다른 자료를 전부 훑는다

한 줄은 "Weeks 10 to 12", 다른 두 줄은 "Weeks 9 to 11" 이었다.

`scripts/week_refs.sh` 가 이것을 본다. **낱말 하나로 대조하면 오탐이 35 건**이라
("following" 은 아무 데나 나온다) 주차를 유일하게 지목하는 **여러 낱말짜리 구절**만 본다.
새 주차를 만들면 그 파일의 표에 한 줄 더한다. `vault_check.sh` §14 가 부른다.

### 5-2. SVG 의 아래첨자 — 유니코드에 없는 글자를 쓰지 않는다

2026-09-05, `b = [e_x ; e_y ; …]` 를 그리려고 아래첨자 문자를 썼다가 두 번 틀렸다.

| 쓴 것 | 실제로 나온 글자 | 노렸던 것 |
|---|---|---|
| `&#8342;` | **ₖ** (아래첨자 k) | 아래첨자 y |
| `&#8355;` | **₣** (프랑 기호) | 아래첨자 i |

렌더된 그림에는 `e_k`, `κyF_nt` 로 찍혔고, **렌더해서 눈으로 보기 전에는 몰랐다.**

원인은 단순하다. 유니코드 아래첨자 라틴 문자는 ₐ ₑ ₕ ᵢ ⱼ ₖ ₗ ₘ ₙ ₒ ₚ ᵣ ₛ ₜ ᵤ ᵥ ₓ 뿐이고
**y 는 아예 없다.** x 는 `&#8339;`(ₓ), i 는 `&#7522;`(ᵢ) 로 서로 붙어 있지도 않다.

> [!caution] SVG 안에서는 평문으로 쓴다
> `e_x` · `e_y` · `X_cmd` · `X_sat` 처럼 밑줄을 그대로 둔다. 못생겼다고 느껴져도
> **틀린 글자보다는 낫고**, 그림은 어차피 본문 수식이 아니다.
> 진짜 아래첨자가 필요하면 `<tspan baseline-shift="sub" font-size="9">y</tspan>` 를 쓰되,
> 그때도 렌더해서 확인한다.

`.md` 본문은 다르다 — 거기서는 LaTeX 을 쓰므로 `$e_y$` 가 정상으로 조판된다.
이 규칙은 **SVG 안에서만** 적용된다.

## 7. 유도는 더블체크하고, 그 자리에 문헌을 적는다

> 사용자 원문: **"유도과정은 항상 더블 체크 하고 관련 문헌이 잇으면 반드시 그 부분에
> 표기해줘...너가 스스로 유도한거라도..더블체크 하고 스킬로 추가"**
> 그리고 **"ALOS 는 최신 MSS 툴박스에 잇어..그것으로 참조해서 더블체크 해줘"**

### 7-1. 내가 유도한 것일수록 더 세게 검증한다

"참고 구현이 없어서 직접 유도했다" 는 **검증을 면제받는 사유가 아니라 검증을 더
해야 하는 사유**다. §3-3 규칙 둘(차원·극한·부호·수치·출처)을 그대로 적용하고,
여기에 하나를 더한다.

| 추가 | 무엇을 |
|---|---|
| **문헌 표기** | 유도한 식 **바로 그 자리**에 출처를 적는다. 절 끝의 References 만으로는 부족하다 |
| **내 유도임을 밝힌다** | 문헌과 스케일링이 다르면 어느 쪽을 따르는지 명시한다 |
| **나중에 다시 찾는다** | "구현이 없다" 는 **그 시점의 릴리스에 대한 진술**이다. 새 판이 나오면 뒤집힌다 |

### 7-2. 실제로 뒤집힌 예 — ALOS

2026-09-05, W05 §5-9 를 **"벤더링된 MSS 2021 에 `ALOSpsi.m` 이 없어 직접 유도했다"**
고 써서 냈다. 사용자가 **"ALOS 는 최신 MSS 툴박스에 있다"** 고 알려 주었고,
디스크를 뒤지니 `선형제어시스템/.../[2025] MSS/GNC/ALOSpsi.m` 이 있었다.

대조 결과 **내 유도가 공식 구현과 한 줄도 다르지 않았다.**

| | MSS 2023+ `ALOSpsi.m` | 강의 §5-9 |
|---|---|---|
| 법칙 | `psi_ref = pi_h - beta_hat - atan(y_e/Delta_h)` | 같음 |
| 적응 | `beta_hat + h*gamma_h*Delta_h*y_e/sqrt(Delta_h^2+y_e^2)` | 같음 |
| 400 스텝 수치 대조 | $\lvert\Delta\psi_d\rvert = 0$, $\lvert\Delta y_e\rvert = 0$ | — |

**교훈은 유도가 틀렸다는 것이 아니라, "없다" 를 확인 없이 쓴 것이 틀렸다는 것이다.**

> [!caution] "구현이 없다" 를 쓰기 전에
> 1. 벤더링된 사본만 보지 말고 **디스크 전체**를 찾는다 — `find . -iname "*ALOS*.m"`
> 2. 그래도 없으면 **릴리스 연도를 명시**한다. "MSS 에 없다" 가 아니라
>    "이 볼트가 쓰는 2021 릴리스에는 없다"
> 3. 논문 인용은 **DOI 까지** 적는다. `ALOSpsi.m` 머리말이 그렇게 하고 있다

### 7-2-1. `otter.m` 이라고 쓸 때 **어느 `otter.m`** 인지 확인한다 — 2026-09-08

§7-1 의 "릴리스에 대한 진술" 이 계수에도 그대로 적용된다는 것을 **직접 틀려서** 배웠다.

사용자가 W04 의 2계 heading 식에서 $(I_z - N_{\dot r})\dot r \to M_{66}\dot r$ 이 맞는지
물었다. 확인하다가 강의자료의 다른 줄이 틀린 것을 찾았는데 — 그 "수정" 이 오히려
틀렸다. 볼트 안에는 `otter.m` 이 **두 벌** 있다.

| 사본 | 위치 | `Yv` |
|---|---|---|
| **강의가 실제로 쓰는 것** | `10_연구_USV_MILS/.../Tools/MSS/VESSELS/otter.m` (2021), `mss_path()` 가 얹는다 | `Yv = 0` (137행) |
| 커밋되어 있는 것 | `lectures/MSS-master/CRAFT/USV/models/otter.m` (2024 recalibration) | `Yv = -M(2,2)/T_sway` |

`grep` 이 먼저 찾은 것은 **볼트 안**의 `MSS-master` 였고, 그것을 근거로
"$Y_v = 0$ 은 틀렸다, 실제로는 $-162.5$" 라고 고쳤다. **강의가 돌리는 코드에서는
$Y_v = 0$ 이 맞다.** 사용자에게 내보내기 전에 되돌렸다.

**규칙 셋:**

- 계수를 인용하기 전에 **`which('otter')` 를 찍는다.** 파일을 `grep` 으로 찾지 않는다 —
  MATLAB 이 실제로 무엇을 부르는지가 유일한 답이다
- 행 번호를 적을 때도 같다. 두 사본의 행 번호가 다르다 (2021 의 `Nrdot` 은 103행,
  MSS-master 는 158행). **행 번호는 릴리스와 함께 적는다**
- **릴리스마다 갈리는 사실**은 그렇게 밝힌다. "이 강의가 쓰는 2021 판에서는 $Y_v = 0$,
  2024 recalibration 은 $-M_{22}/T_{sway}$" 처럼 쓰면 둘 다 옳고 학생이 헷갈리지 않는다

**같이 나온 것 — 문서 안에서 서로 부딪히던 두 진술.** W04 은 식에서
$(I_z - N_{\dot r})\dot r$ 을 $M_{66}\dot r$ 로 바꿔 놓고, 열 줄 뒤 콜아웃에서
**"$M_{66}$ 은 $I_z - N_{\dot r}$ 가 아니다"** 라고 부정하고 있었다. 재현해 보니
$M_{66} = I_z - N_{\dot r}$ 은 **맞다** — 단 $I_z$ 가 **CO(선체 원점) 둘레**일 때다.

```
Ig_CG(3,3) 13.7500  →  Ig(3,3) 15.1021  →  MRB(6,6) 16.9779  →  +25.6736  =  42.6515
선체만·CG      페이로드 포함·CG      평행축으로 CO 로       -N_rdot        M66
```

기호가 어느 점 둘레인지 밝히지 않으면 **맞는 식이 틀린 식처럼 보인다.**
부정하지 말고 **어느 점 둘레인지를 적는다.**

### 7-2-2. W01 §1-11·§1-12 재검토에서 나온 것 — 2026-09-11

사용자가 §1-11 의 유도를 보강하라고 했고, 그 김에 §1-12 도 유도하라고 했다.
`otter.m` 을 다시 세워 대조하니 셋이 나왔다.

| 무엇 | 문서에 있던 것 | 실제 | 어떻게 찾았나 |
|---|---|---|---|
| sway Coriolis 계수 | $(m - X_{\dot u})\,ur$ | $(m + m_p - X_{\dot u})\,ur = M_{11}ur = 85.50\,ur$ | $\mathbf{C}\boldsymbol\nu$ 를 `otter.m` 104–126 행대로 다시 세워 단위 속도로 계수를 뽑았다. §1-9 가 $m = 55$ kg 을 선체만으로 정의해 두었으므로 문서 식은 60.5 kg 이 되었다 |
| §1-11 의 63.2 % 시각 | 1.1064 s | 1.1057 s (Simulink ode4) · 1.1056 s (ode45) | **어떤 러너도 그 수를 찍지 않았다.** `grep` 으로 러너를 찾다가 없어서 다시 쟀다 |
| 절 번호 | "§1-5 established $Y \equiv 0$" 외 여덟 곳 | §1-10, §1-11 등 | 절을 옮긴 뒤 본문 참조를 안 고쳤다 (§6-4 와 같은 지뢰) |

**규칙 둘을 더한다.**

- 문서의 수를 고칠 때 **그 수를 찍는 러너부터 찾는다.** 없으면 러너를 만든 뒤에 고친다.
  `_tools/verify_w01_theory.m` 이 그렇게 생겼다
- 교과서 식을 옮길 때 **기호의 정의가 이 문서의 정의와 같은지** 본다. Fossen 의 $m$ 은
  강체 전체 질량이고 이 문서의 $m$ 은 선체만이다

**MSS 릴리스는 계수만이 아니라 동작도 갈린다.** 2021 판 `GNC/q2euler.m` 은
$\lvert R_{31}\rvert$ 가 round-off 로 1 을 넘으면 `theta` 를 계산하지 않고 끝나서
*Output argument "theta" not assigned* 로 멈춘다. 2022-04-15 수정본(2022+ 의

같은 파일이었으므로, 벤더링된 사본이 많다고 해서 최신이라는 뜻이 아니다.
`verify_w01_theory` 가 그 분기를 실제로 밟아 확인한다.

## 8. 설치·실습 문서는 "명령 모음" 으로 끝내지 않는다

> 사용자 원문: **"모든 실행 명령 이후에 화면을 캡처해서 넣어줘봐 지금은 명령 모음만
> 있으니까 잘 설치가 되었을 때 어떤 결과가 있을지...알기가 어려워...그리고 설치
> 에러가 났을 경우 어떻게 대처하는지도 추가해줘"** (2026-09-06)

명령만 늘어놓은 문서는 **성공을 확인할 방법을 주지 않는다.** 학생은 명령을 붙여넣고
무언가가 흘러간 뒤에 그것이 맞게 된 것인지 알 수 없다. 명령 하나마다 셋을 붙인다.

| 붙이는 것 | 규칙 |
|---|---|
| **정상 출력** | **실제로 돌려서 받은 것**만 싣는다. 길면 앞뒤를 자르고 `…` 로 줄이되, **글자를 고치지 않는다** |
| **무엇을 보고 성공을 판정하나** | "이 한 줄이 보이면 된 것" 을 한 문장으로. 버전 번호·경로처럼 **기계가 확인할 수 있는 것**으로 |
| **틀어졌을 때** | 증상 → 원인 → 고침 세 칸. 실제로 겪은 것만 (`CLAUDE.md` §3 Troubleshooting 규칙과 같다) |

### 8-0. 실습 문제지·답안지도 **PDF 로 같이 낸다**

> 사용자 원문: **"숙제도 MD 파일만 있는데 PDF로도 변환해서 같은 폴더에 넣어줘"**
> (2026-09-08)

학생이 받는 것은 전부 PDF 가 함께 있어야 한다. 이름이 `README.md` 라도 **폴더 색인이
아니라 배포물**이면 예외가 없다.

```bash
bash _tools/md2pdf.sh lectures/W01_simulink/problems/README.md \
                      lectures/W01_simulink/solutions/README.md
```

`vault_check.sh` 의 `delivered()` 가 이것을 강제한다. 색인용 README 둘만 빼고
(`lectures/README.md`, `lectures/WXX_simulink/README.md`), `problems/` 와
`solutions/` 아래의 README 는 **PDF 쌍 검사와 문체 검사에 함께 걸린다.**

- 그러니 문제지 본문도 영어 정식 어조다. 1·2인칭을 쓰지 않는다 — "Check work at
  any time" 은 되고 "Check your work" 는 안 된다.
- 파일 이름을 `README` 로 두는 이유는 강의 `.md` 가 그 이름으로 링크하고 있고,
  폴더 이름(`problems/`, `solutions/`)이 이미 무엇인지 말해 주기 때문이다.
  대신 **첫 줄 H1 이 제목 노릇을 한다** — PDF 만 따로 받아도 무엇인지 보인다.

### 8-1. 출력을 지어내지 않는다

이것이 이 절의 핵심이다. 그럴듯한 터미널 출력을 상상해서 적는 것은 **틀린 문서를
만드는 가장 빠른 길**이다. 버전 번호 한 자리가 다르면 학생은 자기 환경이 잘못된
줄 안다.

- 이 PC 에 **WSL2 + Ubuntu 22.04.5 + ROS 2 Humble + Gazebo Sim 7.9.0 + `~/vrx_ws`**
  가 실제로 있다. 실습 명령의 출력은 **거기서 받아 온다.**

  ```bash
  wsl -d Ubuntu-22.04 -- bash -lc '<명령>'
  ```
- 돌려 볼 수 없는 명령(설치처럼 상태를 바꾸는 것)은 **출력을 만들어 내지 말고**,
  "무엇을 보고 성공을 판정하나" 만 적는다.

### 8-2. GUI 화면은 캡처할 수 없다 — 그림으로 그린다

에이전트는 사용자의 바탕화면·설치 마법사·VS Code 창·Gazebo 창을 **캡처하지 못한다.**
캡처한 척하지 않는다. 대신 둘 중 하나를 쓴다.

| 대상 | 어떻게 |
|---|---|
| 터미널 | **verbatim 출력 상자.** 논문에서는 스크린샷보다 이쪽이 표준이고, 인쇄본에서 훨씬 잘 읽힌다 |

| 공개 웹페이지(다운로드 쪽 등) | 브라우저로 **진짜 캡처**할 수 있다 |

사용자가 실물 스크린샷을 원하면 **사용자가 찍어서 넣는다.** 문서에는 파일 이름과

## 9. 강의자료는 **소리 내어 읽어서 가르칠 수 있어야** 한다

> 사용자 원문: **"강의자료도 설명하기 좋게 문구나..형태나 수정해줘 그리고 최대한
> 이해하기 쉽게...내가 그것을 읽어도 그냥 동일하게 학생들이 이해할 수 있도록...
> 예를 들어 ALOS ILOS가 LOS 대비 왜 필요한지? 등...원리가 어떤것인지? 그냥 영어로
> 그대로 읽을 테니까 잘 이해되도록...수식, 원리, 적용, 특징, 결과 등...결국
> 이해하기가 쉬워야 돼"** (2026-09-08)

이것은 문체 규칙이 아니라 **문서의 목적**에 관한 규칙이다. 이 볼트의 `.md` 는
읽고 이해하는 참고서가 아니라, **강의자 화면에 띄워 놓고 그대로 읽으면 강의가 되는
원고**다. 그 기준을 통과하지 못하면 내용이 옳아도 다시 쓴다.

### 9-1. 판정 기준 하나

> **이 절을 처음 보는 사람이 소리 내어 읽었을 때, 듣는 학생이 이해하는가.**

- 읽는 사람이 **멈춰서 딴 데를 찾아봐야 하면** 실패다. 필요한 것이 그 자리에 없다
- 읽는 사람이 **문장을 스스로 풀어 말해야 하면** 실패다. 문장이 압축돼 있다
- 읽었을 때 **"그래서 왜?" 가 남으면** 실패다. 동기가 빠졌다

### 9-2. 개념 하나에 다섯 칸 — 이 순서로

새 알고리즘·새 법칙·새 모델을 낼 때는 언제나 이 다섯을 **이 순서로** 채운다.
순서가 요점이다. 수식을 먼저 내면 학생은 그것이 무엇을 푸는 수식인지 모른 채 본다.

| # | 칸 | 무엇을 쓰나 | 빠지면 생기는 일 |
|---|---|---|---|
| 1 | **왜 필요한가** | 앞의 방법이 **무엇을 못 하는가**를 먼저. 가능하면 **측정한 수치**로 | 학생이 새 수식을 "또 하나의 공식" 으로 외운다 |
| 2 | **원리** | 한 문장으로 된 착상. 대수 이전의 그림 | 유도는 따라가지만 왜 그렇게 하는지 모른다 |
| 3 | **수식** | 유도. 전체 모델에서 시작해 버린 항을 밝히고 (§3-3) | — |
| 4 | **적용** | 코드 어디에, 파라미터는 무엇을 넣나. 단위까지 | 시뮬링크에서 못 만든다 |
| 5 | **특징과 결과** | 무엇이 좋아졌는지 **측정치**로, 그리고 대가는 무엇인지 | 언제 쓰면 안 되는지를 모른다 |

**본보기 — LOS → ILOS → ALOS.** 사용자가 직접 예로 든 곳이다.

1. **왜** — LOS 는 조류에서 경로 옆 $\Delta\tan\beta_c = 2.25$ m 에 **영구히** 남는다.
   게인을 올려도 안 된다. 선수각 오차는 이미 0 이기 때문이다
2. **원리** — 선수를 상류로 기울여야 하는데, LOS 는 그 기울기를 살 **항이 하나뿐**이다.
   ILOS 는 없는 오차를 지어내서 사고, ALOS 는 조류를 **추정해서** 산다
3. **수식** — 적분항이 arctan **안**, 추정항이 arctan **밖**. 그래서 단위가 갈린다
4. **적용** — 이산 상태로. `kappa` 는 m/s, `gamma` 는 rad/(m·s)
5. **결과** — 2.253 m → 0.008 m / −0.004 m. 대가는 상태 하나와 튜닝 상수 하나

### 9-3. 문장을 고치는 규칙

- **한 문장에 새 기호 하나.** 두 개가 동시에 처음 나오면 문장을 쪼갠다
- **기호를 낼 때 소리 내어 읽는 법을 함께.** "$y_e$, the cross-track error" —
  읽는 사람이 "와이 이" 라고 읽고 넘어가지 않게 한다
- **비유는 한 절에 하나까지.** 둘 이상이면 서로 방해한다
- **표는 읽을 수 있게 쓴다.** 강의자가 표를 소리 내어 읽는 일은 없으므로,
  표 앞에 **그 표가 무엇을 보이는지 한 문장**을 반드시 둔다
- 영어 본문 규칙(1·2인칭 금지 등)은 그대로다. 쉬운 것과 구어체는 다르다

### 9-4. 이미 쓴 절을 고칠 때

내용을 지우지 않는다. **순서를 바꾸고, 빠진 칸을 채우고, 문장을 쪼갠다.**
깊이를 줄이는 것이 아니다 — 사용자는 쪽수 제한이 없다고 못박았다(§2).
어려움은 **깊이**에서 나와야지 **밀도**에서 나오면 안 된다.

### 8-3. 문제지에는 **정답의 결과 그래프**를 넣는다 — 정답 코드는 넣지 않는다

> 사용자 원문: **"각 W01, W03 등 모든 주차에서 HW READ.md 와 PDF에서 제대로
> 학생들이 구현을 했을 경우 어떤 결과 그래프가 나와야 하는지....솔루션 코드를
> 추가하라는게 아니라 솔루션의 결과 그래프를 추가해줘"** (2026-09-08)

수치는 **맞았는지**를 알려주고, 그림은 **만드는 도중에** 무엇이 틀렸는지 알려준다.
반대로 휘는 궤적, 안 정착하는 속도, 축 밖으로 달아나는 선수각은 체커를 돌리기
한참 전에 눈에 보인다.

| 어디에 | 무엇을 |
|---|---|
| `problems/img/WXX_P<n>_expected.png` | 정답 모델을 **실제로 돌려서** 낸 결과 그래프 |
| `problems/README.md` | 그림 + **"Reading the figure" 표** + "이게 아니면 무엇이 틀린 것인가" 한 줄 |
| `solutions/` | 정답 **코드**. 문제지로 넘어가지 않는다 |

- 그림은 `solutions/WXX_S_expected.m` 이 정답 모델을 돌려 만든다. 손으로 그리지
  않으므로 체커가 재는 값과 **어긋날 수가 없다.**
- 궤적 그림에는 반드시 `track_ships` 로 선체와 선수를 함께 그린다 —
  "선수는 북쪽인데 항적은 동쪽으로 기운다" 가 W01 문제 3 의 답 그 자체다.
- 표의 마지막 줄은 **오답의 증상**으로 쓴다. "궤적이 조금이라도 휘면 Constant
  두 성분이 같지 않은 것이다" 처럼.

### 9-5. 중언부언하지 않는다 — 한 번만, 제자리에서

|---|---|
| 같은 문장이 절마다 다시 나온다 | **처음 나오는 곳에 한 번만** 쓰고, 뒤에서는 §번호로 가리킨다 |
| 표를 만들고 그 표를 산문으로 다시 읽어 준다 | 표 **앞에** 한 문장으로 무엇을 보이는지만 쓰고, 표를 되풀이하지 않는다 |
| 그림 설명이 그림에 적힌 글자를 옮겨 적는다 | 그림에 **없는 것**만 쓴다 — 왜 그렇게 되는지, 무엇이 틀렸을 때 어떻게 보이는지 |
| 콜아웃이 바로 위 문단을 요약한다 | 콜아웃을 지운다. 요약이 필요하면 문단이 너무 길다 |
| "앞에서 보았듯이" 로 시작하는 문단 | 그 문단이 정말 새 내용을 담고 있는지 본다. 아니면 지운다 |

**판정 기준.** 한 문단을 지웠을 때 **잃는 것이 없으면 지운다.** 강조하려고 두 번
쓰는 것은 강조가 아니라 소음이다 — 두 번째를 읽는 사람은 첫 번째를 못 믿게 된다.

**다만 줄이지 않는 것 셋.** 유도의 중간 단계(§3-3), 버린 항의 근거, 측정 수치의
출처. 이것들은 반복이 아니라 **내용**이다. 쪽수 제한은 없다(§2) — 없애야 할 것은
길이가 아니라 **같은 말**이다.

### 9-6. 강의자료와 코드가 맞는지 본다

> 사용자 원문: **"강의 자료 pdf와 해당 예제 코드가 잘 매칭이 되는지 보고"**

|---|---|

### 9-8. 실습 예제는 **한 절에 한 요점, 한 그림**

> 사용자 원문: **"모든 세션도 예제 파일과 그에 대한 강의 자료가 너무 복잡해...

§9-5 는 **같은 말을 두 번 하지 말라**고 했다. 이 절은 그보다 강하다 —
**한 절이 두 가지를 보이려 하면, 둘 다 안 보인다.**

#### 판정 기준

> **"이 절은 무엇을 보이는가" 를 한 문장으로 말할 수 있는가.**
> 두 문장이 필요하면 절을 쪼개거나, 둘 중 하나를 버린다.

#### 실제로 걸린 것 둘 (W01, 2026-09-08)

부르고 있었다. **뗀 것을 적을 때 남긴 것도 다시 확인한다.**

#### 줄이는 순서

1. **그 절의 한 문장을 먼저 쓴다.** 그것을 보이는 데 필요 없는 것은 전부 후보다
2. **스윕을 의심한다.** 12점이 보이는 경향을 4점이 이미 보인다면 12점은 장식이다
3. **다패널을 의심한다.** 패널마다 다른 생각이면 그림 하나가 아니라 여러 개다
4. **그림에 6불릿이 붙었으면 그림이 과한 것이다.** 설명을 줄이지 말고 **그림을 줄인다**
5. 남은 그림에 **"What the figure says" 를 3~5불릿**으로. 첫 불릿은 언제나 그 한 문장

#### 줄이지 않는 것 — §9-5 와 같다

이론부의 **유도 중간 단계**, **버린 항의 근거**, **측정 수치의 출처**. 이것들은 내용이다.
줄이는 대상은 **실습 예제와 그 설명**이지 이론의 깊이가 아니다.

#### 지우지 말고 떼어 낸다

그림을 그리던 함수와 이미 생성된 PNG 는 **남긴다** (사용자 절대 지침: 파일을 지우지
않는다). 부르는 곳만 끊고, 스크립트 주석과 강의자료 파일 목록에 **왜 뗐는지**를
한 줄로 적는다 — 다음에 "왜 없지?" 하는 사람에게 답이 그 자리에 있어야 한다.

## 10. 기호·그림·본문이 서로 맞는지 **주기적으로 감사한다**

> 사용자 원문 (2026-09-10):
> **"각 심벌마다 충돌되어 정의되어 있지 않는지...다시 전체적으로 검토해줘"**
> **"그림과 설명이 제대로 일치 하는지...그림과 수식이 제대로 일치 하는지"**
> **"그림안에 들어 있는 설명 문구도...이상한 말이 아닌지도 검토"**

주차를 하나씩 만들 때는 안 보이고 **전체를 가로질러 봐야만 보이는 결함**이 있다.
아래 셋은 한 주차 안에서는 전부 정상으로 보였다.

### 10-1. 기호 충돌 — 한 글자가 두 가지를 뜻하고 있지 않은가

**실제로 잡은 것 (2026-09-10).**

| 기호 | 어디서 | 뜻 | |
|---|---|---|---|
| $\beta_c$ | `otter.m:35`, W01 §1-13, 모든 `*_0_setup.m` | **조류가 가는 방위** | ← 코드가 이렇게 쓴다 |
| $\beta_c$ | W05 본문 **84곳** | **크랩각** $\operatorname{atan2}(v,u)$ | ← 전혀 다른 양 |

학생이 W05 §5-7 의 $y_e^{ss} = \Delta\tan\beta_c$ 를 읽고 setup 의 `beta_c` 를 만지면
**조류 방향을 바꾸게 된다.** 문서가 자기가 돌리는 코드와 어긋난 상태였다.

같은 감사에서 **$N$** 도 걸렸다 — W01 은 North 좌표로, 나머지 전 주차는
$\boldsymbol\tau = [X\ Y\ N]^\top$ 의 **yaw moment** 로 쓰고 있었다.

**판정 규칙: 충돌하면 코드가 이긴다.** 문서는 고칠 수 있지만 학생이 돌리는
`otter.m` 은 못 고친다. 그래서 $\beta_c$ = 조류 방향으로 통일하고 크랩각은 $\beta$,
North·East 는 $x^n$·$y^n$ 으로 바꿨다.

**찾는 법** — 눈으로 읽지 말고 센다.

```bash
# 한 기호가 몇 주차에서 쓰이는가. 여러 주차에 걸치면 뜻이 하나인지 확인한다
for s in 'beta_c' 'tau_u' 'tau_N' '{N}' 'mathbf{R}' 'T_{'; do
  printf "  %-14s " "$s"
  for f in W01 W03 W04 W05 A1; do printf "%s:%-3s " "$f" "$(grep -c "$s" ${f}_*.md)"; done
  echo
done
# 그 다음 정의 줄만 뽑아 뜻이 같은지 본다
grep -n "| \$\\beta_c\$\|beta_c: " lectures/*.md ../**/otter.m
```

**아직 남아 있는 것 (기록만, 아직 안 고침):** $\tau_u$ 는 W03 에서 **시상수[s]**,
$\tau_N$ 은 W04 에서 **요 모멘트[N·m]**. 같은 그리스 문자에 아래첨자만 다르고
차원이 전혀 다르다. 고칠지 사용자에게 물을 것.

### 10-2. 그림과 수식이 같은 기호를 쓰는가

`.tex` 는 `.md` 와 따로 있어서 **본문만 고치면 그림에 옛 기호가 남는다.**
실제로 W05 의 $\beta_c$ 를 본문에서 고친 뒤 그림 넷에 그대로 남아 있었다.

```bash
# 본문에서 뺀 기호가 그림에 살아 있지 않은가
grep -n 'beta_c\|{\$N\$}\|{\$E\$}\|\dot N\|\dot E' figures/src/*.tex
```

> [!important] 생성되는 `.tex` 는 **생성기를 고친다**
> `w04-ssa.tex` · `w04-second-order.tex` · `w05-los-geometry-geo.tex` 는
> `_tools/*.m` 이 만든다. `.tex` 를 직접 고치면 **다음 생성에서 조용히 되돌아간다.**
> 파일 머리말에 생성기 이름이 적혀 있으니 고치기 전에 첫 줄을 읽는다.

### 10-3. 그림이 주장을 **보여 주는가**, 글로만 말하는가

W01 §1-13 이 "$\beta_c - \psi$ 가 뱃머리에서 잰 각" 이라고 썼는데, 그림 (b) 에는
**북쪽 기준선도 $\psi$ 도 없었다.** 두 각의 차라는 말을 그림이 뒷받침하지 못했다.
북쪽 점선과 $\psi$ 호를 넣으니 세 호가 나란히 놓여 뺄셈이 눈에 보인다.

**판정:** 본문이 "A 에서 B 를 빼면 C" 라고 하면 그림에 **A·B·C 가 다 있어야 한다.**
하나라도 없으면 그림이 아니라 삽화다.

### 10-4. 그림 안의 설명 문구도 읽는다

그림 안 캡션은 `.tex` 에 묻혀 있어 교정에서 빠지기 쉽다. `.md` 를 읽을 때 같이
읽지 않으면 몇 달을 그대로 간다.

```bash
grep -n 'node\[note\|node\[anote\|text width' figures/src/*.tex | grep -v '^\s*%'
```

- 문장이 되는가, 기호가 본문과 같은가, 숫자가 러너 출력과 같은가
- **뜻이 바뀐 기호를 캡션이 아직 옛 뜻으로 설명하고 있지 않은가**

### 10-5. 코드는 전부 돌려서 확인한다

`_tools/vault_runall.m` 이 전 주차의 setup·builder·절 스크립트를 순서대로 돌리고
표로 보고한다. 2026-09-10 기준 **38개 실행, 실패 0**.

## 12. 부호는 **규약이 아니라 일반형의 결과**여야 한다 — 2026-09-16

사용자가 W03 §3-4 의 그림을 보고 물었다. "$\dot u_d$ 가 시간에 따라 변하면
D 게인 앞의 $-$ 도 잘못된 것 아니야? 일반화된 식이라고 하기엔?"

**맞는 지적이었다.** 그리고 이것은 §11 에서 찾은 두 오류와 **같은 종류**다 —
식은 맞았고, 그 식을 읽은 문장이 틀렸다.

### 12-1. 무엇이 틀렸는가

미분을 측정값에서 받는 형태

$$X = K_p e + K_i\!\int\! e - K_d F(s)\,u$$

의 마이너스를 "교과서형의 플러스를 측정값으로 다시 쓴 것" 이라고 설명하고 있었다.
근거는 $\dot e = \dot u_d - \dot u$ 이고 설정값이 일정하면 $\dot u_d = 0$ 이라는 것.
**그 설명은 $\dot u_d = 0$ 일 때만 참이다.** 5주차부터 선수방위 명령은 유도법칙이
만들며 매 순간 변한다. 즉 강의가 스스로 곧 깨뜨릴 가정 위에 설명을 세워 두었다.

### 12-2. 고친 방법 — 특수한 경우를 일반형의 한 값으로 만든다

설정값 가중 $c_d$ 를 도입한다.

$$X = K_p e + K_i\!\int\! e + K_d F(s)\,(c_d u_d - u)$$

| $c_d$ | 미분하는 것 | 이름 |
|---|---|---|
| 1 | $e$ | 교과서형. Simulink PID 블록이 계산하는 것 |
| 0 | $-u$ | 측정값 미분. 이 강의가 쓰는 것 |

이제 마이너스는 **외울 규약이 아니라 $c_d = 0$ 을 넣은 결과**다. 부정하는 것이
없다 — 괄호의 설정값 쪽이 비어 있을 뿐이다.

**모델도 같이 바꾼다.** `D input` 합산기가 $c_d u_d - u$ 를 만들고, `X_pid` 는
세 항을 전부 `+` 로 받는다. 부호가 도면에서도 식과 같은 자리에 있게 된다.
4주차도 같다 — $\tau_N = K_p\,\mathrm{ssa}(\psi_d-\psi) + K_d(c_d r_d - r)$ 이고
$r_d$ 를 **신호로** 들여 8주차 기준모델이 채울 자리를 만들어 둔다.

### 12-3. 이렇게 하면 검증이 생긴다

일반형으로 두면 **두 형태가 같은 제어기라는 것을 시험할 수 있다.** 실제로:

| | 측정값 |
|---|---|
| $K_d=60$, $c_d=0$, 손으로 조립한 것 대 PID 블록 | $0.70$ m/s 차이 |
| $K_d=60$, $c_d=1$, 같은 둘 | $4\times10^{-16}$ m/s 차이 |

특수한 경우로 두었을 때는 "둘은 다르다" 는 관찰밖에 할 수 없었다. 일반형으로
두니 **다름의 원인이 파라미터 하나임을 측정으로 보일 수 있다.**

> [!important] 부호를 설명할 때 확인할 것
> "이 마이너스는 왜 마이너스인가" 를 설명하는 문장을 쓸 때마다,
> **그 설명이 가정하는 것이 이 강의의 뒤쪽에서 깨지는지** 본다. 깨진다면
> 특수한 경우를 설명하지 말고 **일반형을 쓰고 그 값을 대입한다.**

### 12-4. 같은 자리에서 나온 두 번째 오류 — "부호를 뒤집으면 불안정해진다"

같은 콜아웃에 "$+K_d\dot u$ 로 쓰면 감쇠가 반대로 걸려 고리가 불안정해진다" 고
적혀 있었다. **두 겹으로 틀렸다.**

- 이 축에서 미분항은 감쇠가 아니라 **질량**이다 (W03 §3-4 자신이 그렇게 유도한다)
- 그래서 부호를 뒤집으면 질량을 **빼는** 것이 되고, 선체 질량을 다 먹기
  전까지는 안정하다. 실측 문턱 $K_d = 90.13$ kg, 선체 서지 질량 $M_{11} = 85.5$ kg

$K_d = 2, 20, 60$ 에서는 부호를 뒤집어도 **안정하다.** "언제나 불안정해진다" 는
문장은 산술이 뒷받침하지 않는다.

**교훈**: 경고문도 수치로 확인한다. 경고는 틀려도 안전한 쪽이라고 생각하기 쉽지만,
틀린 경고는 학생에게 틀린 물리를 가르친다.

## 13. 블록 하나에 숨은 알고리즘은 **그 절의 주제일 때** 풀어 쓴다 — 2026-09-16

사용자가 Surge controller 를 열어 보고 물었다. "anti-windup 을 꼭 MATLAB
Function 으로 해야 하는지 의문이고 … 오히려 너무 복잡해 보여."

### 13-1. 판단 기준

MATLAB Function 한 개가 블록 열다섯 개보다 **언제나** 나은 것은 아니다. 기준은
하나다 — **그 안에 든 것이 그 절의 주제인가.**

| 상황 | 어느 쪽 |
|---|---|
| 알고리즘이 그 절의 **주제** | 표준 블록으로 풀어 쓴다. 신호를 따라가며 비교할 수 있어야 한다 |
| 알고리즘이 그 절의 **도구** | Function 하나로 둔다. 도면이 조용해야 주제가 보인다 |

W03 §3-6 은 세 가지 안티와인드업 방식이 **어떻게 다른가**를 가르친다. 그 차이가
더블클릭 뒤에 숨어 있으면 학생은 신호를 따라가는 대신 코드를 읽어야 한다.
그래서 풀어 썼다. 반대로 `allocation` 은 §3-5 의 도구일 뿐이므로 Function 으로 둔다.

### 13-2. 함께 얻은 단순화

풀어 쓰면서 `aw_mode` · `Ki` · `K_aw` 를 넣어 주던 **Constant 블록 셋을 서브시스템
안으로 옮겼다.** 상수이므로 바깥에 있을 이유가 없었고, 최상위 화면에서 블록 셋과
선 셋이 사라졌다. **"복잡해 보인다" 는 지적에는 부모 화면을 줄이는 답도 있다.**

### 13-2a. 풀어 쓰되 **평평하게 늘어놓지 않는다** — 2026-09-16, 같은 날 두 번째 교훈

첫 시도는 블록 열다섯 개를 한 화면에 평평하게 놓은 것이었다. 사용자가 보고
말했다. "너무 복잡하고 정신 없다 … 알고리즘이 너무 복잡해."

**맞는 지적이었다.** MATLAB Function 을 푸는 것과 그것을 한 화면에 쏟아 놓는 것은
다른 일이다. 겹친 선이 0 이어도 읽히지 않으면 실패다.

| | 블록 수 | 읽히는가 |
|---|---|---|
| MATLAB Function 하나 | 1 | 아니다 — 더블클릭해야 보인다 |
| 평평하게 푼 것 | 15 | 아니다 — 무엇이 어느 방식인지 구별되지 않는다 |
| **방식마다 상자 하나** | **6** (상자 둘 포함) | 그렇다 |

**규칙**: 비교하라고 만든 것이 n 가지이면, 화면에 **n 개의 상자**가 보여야 한다.
공유하는 계산만 바깥에 두고, 각자의 계산은 각자의 상자 안에 넣는다.
여기서는 `sat` 과 `Ki e` 만 바깥에 남았다 — 세 방식이 모두 쓰기 때문이다.

덤으로 얻는 것: 상수를 쓰는 곳 옆에 둘 수 있다. `Ki` 를 Constant + Product 로
받던 것이 **Gain 하나**가 되었고, `K_aw` 도 마찬가지다. Ki = 0 가드도 그것이
필요한 상자 안으로 들어갔다.

### 13-3. 반드시 회귀 검증을 붙인다

표현을 바꾼 것이지 동작을 바꾼 것이 아니므로, **그것을 증명해야 한다.**
`verify_w03_antiwindup` 이 하는 일:

- 강의노트 §F 표의 세 행(peak $I$ · peak $X_{\text{cmd}}$ · recovery)을 다시 재어
  **인쇄된 자릿수까지** 대조한다 — 그 값들은 교체 이전 모델이 낸 것이다
- $K_i = 0$ 일 때 역계산 항이 막히는지 (없는 적분기를 충전하지 않는지)
- 클램핑 조건을 코드판 `sign(e)==sign(sat)` 와 도면판 `e*sat > 0` 로 각각 계산해
  **0 과 허용오차 경계를 포함한 81 가지 조합**에서 일치하는지

세 가지 모두 통과했다. **회귀 검증 없이 "표현만 바꿨다" 고 말하지 않는다.**

### 13-3a. 회귀만으로는 부족하다 — **모델 밖의 구현**과 대조한다

사용자가 이어서 물었다. "실제 결과도 맞는지도 모르겠고 … 결과도 검토해주고."

회귀 검증은 "예전과 같다" 만 말한다. 예전 것이 틀렸으면 같이 틀린 채로 통과한다.
그래서 **Simulink 를 전혀 쓰지 않는 두 번째 구현**을 붙였다 — 강의에 적힌 식만
보고 PI · 안티와인드업 · 배분 · `otter.m` 을 평범한 MATLAB 으로 다시 짜고, 모델과
같은 고정 스텝 RK4 로 적분해 궤적 전체를 비교한다.

| 방식 | max&#124;Δu&#124; [m/s] | max&#124;ΔI&#124; [N] | max&#124;ΔX_cmd&#124; [N] |
|---|---|---|---|
| none | 7.6e-15 | 2.3e-12 | 2.3e-12 |
| clamping | 2.2e-16 | 1.4e-14 | 1.4e-14 |
| back-calculation | 2.2e-16 | 1.4e-14 | 1.4e-14 |

적분기 상태가 3438 N 까지 가는 계산에서 1e-12 N 의 차이는 같은 산술을 다른
순서로 한 것의 반올림이다. **이것이 "결과가 맞다" 에 대해 할 수 있는 가장 강한
진술이다** — 모델이 자기 배선이 아니라 강의의 식에서 그 수를 낸다는 뜻이기 때문이다.

> [!important] 언제 이 두 번째 검증을 만드는가
> 플랜트를 직접 부를 수 있고(여기서는 `otter.m`), 제어기가 강의에 식으로 적혀
> 있으면 언제나 가능하다. 비싸지 않다 — 50 줄이다. **사용자가 "결과가 맞는지
> 모르겠다" 고 말하기 전에 붙여 둔다.**

### 13-3c. 같은 수를 담아야 하는 두 파일은 **갈라진다** — 2026-09-16

`W03_0_setup.m` 과 `W03_vars.m` 은 "같은 숫자를 읽는다" 고 서로의 주석에 적어
두고서도 `K_aw` 가 달랐다 — 앞은 `1/T_u = 0.9071`, 뒤는 `5`.

결과: **학생이 Run 을 눌러 얻는 값과 강의노트의 표가 서로 달랐다.**

| K_aw | peak I [N] | peak X_cmd [N] | recovery [s] | 어디서 |
|---|---|---|---|---|
| 0.9071 | 339.0 | 464.1 | 3.640 | `W03_0_setup` — 학생이 보는 것 |
| 5 | 213.1 | 356.2 | 3.440 | `W03_vars` — 강의의 모든 측정값 |

> [!warning] 이 발견에는 뒷맛이 있다
> 2026-09-14 검토에서 §F 표의 `339.0 / 464.1 / 3.640` 을 **"stale 한 표"** 로 보고
> `213.1 / 356.2 / 3.440` 으로 고쳤다. 그런데 그 수들은 낡은 것이 아니라
> `W03_0_setup` 의 설정으로 잰 **옳은** 수였다. 증상만 고치고 원인을 놓친 채
> 스킬에 틀린 진단을 적어 둔 것이다 (§11).
>
> **교훈**: 문서의 수와 스크립트의 수가 다를 때, "문서가 낡았다" 는 **가설이지
> 결론이 아니다.** 그 수가 **어떤 설정에서 나오는 수인지** 먼저 찾는다. 재현되는
> 설정이 있다면 낡은 것이 아니라 **갈라진 것**이고, 고칠 곳은 표가 아니라 설정이다.

기계로 거를 수 있는가 — `vault_number_audit` 는 로그 어딘가에 같은 수가 있으면
통과시키므로 이런 갈라짐을 못 잡는다. 두 파일이 같은 이름의 변수를 서로 다른
값으로 정의하는지 세는 검사가 필요하다. 지금은 사람이 본다.

### 13-3b. 세 번째 방향 — **라이브러리 블록에 물어본다**. 그리고 안 맞을 때 하는 일

사용자가 이어서 물었다. "시뮬링크 PID 자체 블럭하고도 맞는지도."

Simulink PID Controller 블록은 자체 출력 포화와 자체 안티와인드업(clamping ·
back-calculation)을 갖고 있다. 이 강의의 모델은 그 한계를 배분이 거는 한계와
같은 값으로 두었으므로, **같은 방식을 고르면 두 경로가 같은 배를 몰아야 한다.**

역계산은 6.7e-16 으로 맞았다. **클램핑은 3.1e-02 m/s 어긋났다.**

#### 안 맞았을 때 추측하지 않는다 — 가설을 세우고 실험으로 죽인다

| 가설 | 실험 | 결과 |
|---|---|---|
| ① 지령이 한계를 넘나들며 떨려서 | 확실히 넘는 요구·안 넘는 요구로 바꿔 본다 | **틀림** — 셋 다 어긋난다 |
| ② MathWorks 의 얼림 조건이 다른 것이라서 (`sign(I)==sign(e)`) | 독립 구현에 두 규칙을 넣고 각각 블록과 비교 | **틀림** — 둘 다 3e-02 어긋난다 |
| ③ 오른편이 불연속이라 이산화가 달라서 | **스텝을 절반씩 줄여 본다** | **맞음** |

| h [s] | clamping | back-calculation |
|---|---|---|
| 0.02 | 3.11e-02 | 6.7e-16 |
| 0.01 | 1.56e-02 | 6.7e-16 |
| 0.005 | 6.39e-03 | 6.7e-16 |
| 0.0025 | 4.02e-03 | 4.4e-16 |

**규칙이 다르면 차이가 h 와 무관하게 남는다. h 와 함께 사라지면 이산화의
문제다.** 이 한 줄이 ②와 ③을 가른다.

원인: 클램핑은 적분기 입력이 `Ki e` 와 `0` 사이를 **뛴다.** 고정 스텝 솔버는
그 뜀을 스텝 안에서 해결하지 못하므로 두 구현이 스위치 순간을 h 만큼 다르게
잡는다. 역계산은 `Ki e - K_aw sat` 이고 sat 이 0 에서 연속으로 자라므로 뜀이
없다 — 그래서 어떤 h 에서도 기계 정밀도로 같다.

> [!important] 검증이 실패했을 때 허용오차를 늘리지 않는다
> 3e-02 을 통과시키려고 tol 을 키우는 것은 검증을 버리는 것이다. **무엇을 물어야
> 하는지를 다시 정한다.** 여기서 옳은 질문은 "같은가" 가 아니라 "수렴하는가"
> 였고, 그래서 검증도 `dc(j+1) < 0.8*dc(j)` 로 바뀌었다. 규칙이 달라지면 이
> 검증은 여전히 실패한다.

**그리고 이것은 강의 내용이 되었다.** W03 §3-6 은 역계산을 선호할 이유를 둘 갖고
있었다(멈추는 것 대 끌고 가는 것, 고정점의 위치). 여기서 셋째가 나왔다 —
**클램핑은 답이 솔버에 의존하게 만들고 역계산은 그렇지 않다.** 검증이 강의를
만든 사례다.

### 13-4. 배선은 통로를 직접 준다

새 서브시스템은 처음에 겹친 선이 6 쌍이었다. 자동 배선에 맡기면 서로 다른 신호가

## 14. `.m` 주석은 **그대로 읽으면 강의가 되게** 쓴다 — 2026-09-16

사용자 요구: "각 m 파일 주석에 한글과 영어를 다 혼용해서 … 그대로 읽으면 그
프로그램이 어떤 강의 내용의 일부이고 어떤 의미인지 알 수 있게." 그리고 기존
주석에 대해 "혼자 하는 독백 같아 … 약간 formal 하면서도 충분히 자세하게."

### 14-1. 표준 머리 주석

```matlab
%% W0X · 절 Y — 한 줄 제목
%  W0X · Section Y — the same title in English
%
%  실행 순서 / order of execution
%  강의에서의 위치 / place in the lecture      ← 어느 절과 짝인가, 왜 여기 있는가
%  절차 / procedure                            ← 번호를 붙여 단계별로
%  결과를 읽는 법 / how to read the result     ← 무엇이 보여야 하고 왜 그런가
%  만드는 것 / what it produces                ← 표, PNG 파일 이름
```

**두 언어가 각각 완결되어야 한다.** 한글만 읽어도, 영어만 읽어도 내용이 다
전달되어야 한다. 서로 보충하는 방식으로 나누어 쓰지 않는다.

- 영어 쪽은 강의 본문과 같은 규칙 — **1·2인칭 금지**
- 한글 쪽도 독백체를 피한다. "학생은 이 스크립트를 돌릴 필요가 없다" 가 아니라
  "실습 시간에는 이 스크립트를 돌리지 않아도 된다"
- **왜 그렇게 되는가**를 한 문단 넣는다. 무엇을 하는지만 적으면 읽어 줄 것이 없다

### 14-2. `fprintf` 로 찍는 설명문도 같은 기준이다

콘솔 출력의 산문은 강의노트가 그대로 인용하므로 **영어로 둔다**(CLAUDE.md §1).
그러나 품질 기준은 주석과 같다 — **숫자에 이름표를 붙이지 말고 메커니즘을 말한다.**

| 고치기 전 | 고친 뒤 |
|---|---|
| "적분기가 차이를 만드는 자리다" | "포화 중에는 네 방식 모두 작동기가 같은 값을 내므로 출력이 같을 수밖에 없다. 갈라지는 것은 적분기 안이고, $y$ 를 재서는 보이지 않는다" |
| "회복이 32.04 s 대 2.64 s, 12.1 배" | 같은 수치 + "오차가 충분히 오래 음이 되어 그 초과분을 다시 적분해 내보내기 전까지는 고리가 한계에서 내려올 수 없다. 그동안 제어기는 제어하지 않고 있다" |

### 14-3. 주장하지 말고 재서 적는다

"네 궤적이 같다" 고 쓰여 있던 자리에 **실제로 벌어진 차이를 재는 코드**를 넣었다.
결과는 정확히 0 이었고, 그래서 "수치 잡음" 이라는 표현은 오히려 사실보다 약한
말이 되었다. 0 일 때와 아닐 때를 나누어 찍도록 고쳤다.

> [!important] 문장 안에 숫자를 손으로 적지 않는다
> "게인을 100 에서 2000 으로 올리면 오차가 44 에서 4 퍼센트로" 처럼 적어 두면
> 게인을 바꾼 날 **문장만 옛날 값으로 남는다.** 바로 위에서 계산한 값을 `%.1f`
> 로 받아 쓴다. §11 의 수치 결함 여섯 건 중 셋이 이 유형이었다.

## 14-1. 도면에 **식**을 적는다, 그리고 다른 교재의 게인과 이어 준다 — 2026-09-16

사용자가 안티와인드업 서브시스템의 내부 화면을 보고 말했다. "이게 어떤 원리인지
수식도 넣어줘 … 정확히 모르겠어."

**블록만으로는 원리가 전달되지 않는다.** Sum 과 Gain 과 Switch 가 옳게 배선되어
있어도, 그것이 어떤 식인지는 도면 어디에도 쓰여 있지 않다. 강의노트에 식이 있어도
모델을 열어 본 사람에게는 닿지 않는다.

**규칙**: 알고리즘을 담은 서브시스템에는 **그 서브시스템이 푸는 식을 주석으로
적는다.** 강의노트의 절 번호도 함께 적어 둘을 잇는다.

```
BACK-CALCULATION, AS AN EQUATION
    dI/dt  =  Ki e  -  K_aw ( X_cmd - X_sat )
The correction is zero while nothing is refused, so the controller is unchanged
below the limit. Above it the term is a negative feedback on the excess with
time constant 1/K_aw, which is why K_aw is a RATE and carries units of 1/s.
```

### 14-1a. 다른 교재가 같은 법칙을 다른 모양으로 그리면, **게인의 관계를 밝힌다**

사용자의 다른 강의(선형제어시스템)는 Franklin 8E 그림 9.22 를 쓰는데, 거기서는
역계산 게인이 **적분게인 안쪽**에 있다.

|  | 식 | 게인의 단위 |
|---|---|---|
| 이 강의 | `dI/dt = Ki e - K_aw (u - u_sat)` | K_aw 는 언제나 1/s |
| Franklin | `dI/dt = kI [ e - Ka (u - u_sat) ]` | Ka 는 제어입력→오차 변환. 플랜트의 입출력 단위가 같을 때만 무차원 |

**같은 법칙이고 `K_aw = kI Ka` 이다.** Franklin 의 `kI = 4, Ka = 10` 은 곧
`K_aw = 40` 이므로, 10 을 그대로 옮겨 적으면 추종 시상수가 네 배 느려진다.

> [!important] 학생이 두 과목을 함께 듣는다
> 같은 것을 두 기호로 배우면 어느 쪽도 확신하지 못한다. 다른 과목의 자료가
> 들어오면 **표기를 통일하려 하지 말고, 변환 관계를 한 줄로 적어 준다.**

### 14-1b. 그 관계도 재서 확인한다

**출판된 그림을 재현하면 인용이 장식이 아니라 검증이 된다.**

## 14-2. 데모 절은 **출판된 예제**로 만든다 — 2026-09-16

§H 는 "선체를 치우고 원리만 본다" 는 절이다. 그런데 플랜트와 게인을 이쪽에서
고르면, 그 절이 확인하는 것은 결국 **이 강의가 자기 자신과 일치한다**는 것뿐이다.

§H 를 Franklin 8E 그림 9.22 의 구성으로 바꾸었다 — 플랜트 1/s, kp = 2, kI = 4,
Ka = 10, |u| <= 1, 단위 계단. 그림 9.23 이 싣는 값과 나란히 놓인다.

| | 출처 그림 9.23 | 이 강의가 잰 값 |
|---|---|---|
| 보호 없음 오버슛 | 약 1.53 | **1.53** |
| 역계산 오버슛 | 약 1.15 | **1.15** |

**출판된 그림을 재현하면 플랜트·게인·포화·안티와인드업을 한꺼번에, 이 강의가
쓰지 않은 구현에 대고 검사하게 된다.** 자기와 일치하는 것보다 강한 진술이다.

### 14-2a. 바꿀 때 딸려 오는 것들을 센다

데모의 플랜트를 바꾸면 그 절의 수치만 바뀌는 것이 아니다. 실제로 딸려 온 것:

| 딸려 온 것 | 왜 |
|---|---|
| 측정 항목 자체 | 도달 불가능한 설정값이 없으므로 "회복 시간" 이 정의되지 않는다 → 오버슛·정착시간으로 |
| 그림의 눈금 | 역계산이 적분기를 **음수**로 끌고 가므로 로그 눈금이 그 구간을 지운다 → 선형으로 |
| 그림의 보조선 | 1/s 에는 작동기가 만드는 출력 상한이 없다 → y_max 선을 뺀다 |
| W03 §3-6 의 고정점 표 | 적분기 플랜트에서는 어떤 상수 설정값도 결국 도달 가능하므로 **고정점이 점유되지 않는다** → 그 표는 1/(s+1) 에 남겨 두고, 왜 다른 플랜트가 필요한지를 본문에 적는다 |

> [!important] 마지막 줄이 요점이다
> 데모 둘이 서로 다른 플랜트를 쓰는 것은 게으름이 아니라 **서로 다른 것을 보이기
> 때문**이다. 그 이유를 본문에 적지 않으면 읽는 사람은 불일치로 읽는다.

### 14-2b. 창(window)은 주장에 맞추어 정한다

"네 방식이 포화 중에는 같다" 를 확인하면서 창을 `t < 1 s` 로 임의로 잡았더니,
그 안에 이미 클램핑이 한계를 떠난 시각이 들어 있어서 실재하는 차이 `6.3e-02` 를
**"솔버 잡음"** 이라고 적을 뻔했다.

창을 "네 방식이 **모두** 한계에 앉아 있는 동안" 으로 신호에서 직접 구하니
0.50 s 였고, 그 안에서는 네 궤적이 비트 단위로 같았다.

**임의의 상수로 창을 잡지 않는다. 주장이 성립하는 구간을 신호에서 찾는다.**

## 14-3. 다른 강의의 한국어 자료를 옮겨 올 때 — 2026-09-18

사용자가 다른 자료의 한국어 설명(“속도는 어느 축에서 잰 것인가 — u·v 와 V_N·V_E”,
네 칸 그림과 표)을 보여 주며 W01 에 영어로, 가장 알맞은 자리에 넣어 달라고 했다.

### 14-3a. 옮기는 것은 내용이지 기호가 아니다

원 자료는 `V_N`, `V_E` 와 축 이름 `N (북)`, `E (동)` 을 쓴다. 이 볼트는
**그림과 수식에 N 과 E 를 쓰지 않는다** (사용자 지시, 2026-09-12). 그래서 옮기면서

| 원 자료 | 이 볼트 |
|---|---|
| `V_N`, `V_E` | $\dot x^n$, $\dot y^n$ |
| 축 `N (북)`, `E (동)` | $x^n$, $y^n$ |
| “어디로 가는가” = atan2(V_E, V_N) | 침로 $\chi = \operatorname{atan2}(\dot y^n, \dot x^n)$ |
| 크랩각 | $\beta = \operatorname{atan2}(v,u) = \chi - \psi$ — W01 §1-12 · W05 와 같은 기호 |

**번역은 문장만이 아니라 기호 체계까지 이 볼트의 것으로 바꾸는 일이다.** 원 자료의
기호를 그대로 가져오면 다른 절과 충돌한다.

### 14-3b. 자리는 “이미 있는 것에 무엇이 빠졌는가” 로 고른다

§1-4 에는 이미 예제가 하나 있었다 (ψ = 30°, u = 2, v = 0.5). 그러나 그 예제는
**선수각과 옆 속도를 한꺼번에** 바꾸므로 어느 쪽이 무엇을 하는지 가르지 못한다.
옮겨 온 네 칸은 그 둘을 떼어 낸다 — (1)(2)(3) 은 선수각만, (4) 는 옆 속도만.
그래서 새 절을 만들지 않고 §1-4 의 기존 예제 **바로 뒤**에 `### One velocity,
read in two frames` 로 넣었다. 빠져 있던 것을 채우는 자리이다.

### 14-3c. 옆 그림과 색 이름을 맞춘다

바로 위 그림(`w01-velocity`)은 같은 색 `pathc` 를 자기 캡션에서 **green** 이라
부른다. 새 그림에서 처음에 **teal** 이라고 적었다가 green 으로 바꿨다. 한 절 안에서
같은 색을 두 이름으로 부르면 읽는 사람은 다른 색이라고 믿는다.

그러다 기존 그림의 범례가 벡터를 **blue** 라고 부르고 있는 것도 찾았다 — 실제로는
투영선과 같은 green 이다. 같이 고쳤다.

### 14-3d. 지나가다 본 결함은 그 자리에서 고친다

같은 파일을 읽다가 §1-12 의 `\Delta\tan\beta_c` 를 발견했다. 크랩각은 `\beta` 이고
`\beta_c` 는 조류 방향이다 — 2026-09-10 에 W05 에서 고친 충돌이 W01 과 W05 의
Simulink 주석 한 줄에 남아 있었다. 편집하던 파일이고 한 글자짜리 수정이므로 바로
고쳤다. 기호 변환기는 문서를 고쳤지만 **모델 캔버스 주석 문자열까지는 보지
않았다** — 다음 변환 때는 `.m` 안의 주석 문자열도 대상에 넣는다.

### 15-10. 절 스크립트는 "그대로 읽으면 되는" 한·영 설명을 단다 — 2026-09-22

사용자 지시: "강의 자료의 m 파일에 영어랑 한글 설명이 있어야지... m 파일은 최대한 간단히 해주되...
자세한 설명이 있어야 돼...그대로 읽으면 되도록". 코드는 짧게 두고, 설명을 늘린다.

| 자리 | 쓰는 것 |
|---|---|
| 머리말 `이 절이 묻는 것 / the question` | 이 절이 답하는 질문 하나, 한국어 한 줄 + 영어 한 줄 |
| `이 스크립트가 하는 일 / what this script does` | ①②③ 번호를 붙인 단계. 모델 이름, 바꾸는 값, 찍는 것 |
| `출력에서 볼 것 / what to look for in the output` | **실제로 나오는 숫자**를 들어, 무엇을 보고 무슨 결론을 내는지. 강의자가 읽어 주면 설명이 된다 |
| 본문 `%% 0) 경로`, `%% 1) …` | 블록마다 한·영 한 줄씩. 도우미(W0x_read, step_metrics)가 무엇을 돌려주는지, 왜 그 구간/기준으로 재는지 |
| 바꾸지 않는 것 | 코드. 주석만 더하고, 더한 뒤 **다시 돌려 출력이 같은지** 확인한다 |
