## 15-62. 다른 과정과 1 대 1 로 맞출 때 — 사다리는 번호를 지키고, 빈 칸을 비운다 — 2026-10-27

> **"그래프나 시뮬링크 모든 결과도 캡스톤 디자인 내용과 1대 1로 매칭 되도록 해줘."**

W06 을 학부 캡스톤 W06 과 맞추면서 배운 것이다. 캡스톤 자료는 모델을 **한 단씩** 쌓는
사다리이고, 단 번호가 그 자료의 뼈대다. 이쪽에서 같은 단을 세울 때 어기기 쉬운 것 다섯.

- **단 번호는 저쪽 것을 그대로 쓴다.** 둘을 나란히 펼쳐 놓고 읽게 하는 것이 목적이므로,
  이쪽 사정으로 번호를 당기면 그 목적이 사라진다
- **없는 단은 메우지 않고 비운다.** 캡스톤 6 단은 5 단을 Gazebo·VRX 에 붙이는 단이고
  이 과정은 Otter 동역학만 쓴다. 비워 두면 7 · 8 단이 양쪽에서 같은 번호로 남는다.
  **비었다는 것을 본문이 말한다** — 말하지 않으면 학생은 빠뜨린 것으로 읽는다
- **방향이 거꾸로인 단이 있으면 그것도 적는다.** 캡스톤 3 단은 추력곡선을 **더하고**,
  이쪽 모델은 첫 단부터 배분과 곡선을 안에 들고 있으므로 거꾸로 **고리를 떼어** 곡선만
  드러낸다. 두 사다리가 반대로 가는 유일한 자리라고 그 자리에 쓴다
- **빈 칸은 실패가 아니라 없다는 뜻이다.** 표에 `NaN` 이 찍히는 자리(목표 없는 단의 거리,
  접안 아닌 단의 단계)마다 본문이 한 줄로 그렇게 말한다
- **단이 새로 생기면 모델이 새로 생기는 것이 아니다.** 일곱 단이 모델 넷을 덮어쓴 값만
  바꿔 돌았다. 새 파일은 스크립트 셋뿐이다

그림은 둘로 나뉘고, 둘이 하는 일이 다르다.

| 그림 | 하는 일 | 지켜야 할 것 |
|---|---|---|
| 단마다 한 장 (`W06_fig_rung`) | 한 단을 여섯 칸으로 | 칸의 **뜻과 자리와 눈금이 모든 단에서 같다**. 추력 칸은 `ylim([T_min-15, T_max+15])` 하나로 고정 — 단마다 자동 눈금이면 천장에 닿은 단이 닿지 않은 단처럼 보인다 |
| 전체 한 장 (`W06_fig_ladder`) | 단들을 **겹친다** | 겹쳐야만 보이는 것만 담는다 — 어디로 갔는가 · 거리를 얼마나 빨리 닫았는가 · 어느 단이 천장에 닿았는가 |

> [!warning] 두 줄을 빼는 것은 하나만 다를 때에만 정직하다
> 사다리 표는 줄을 빼 보고 싶게 생겼다. 그런데 1 단과 5 단은 모델 · 목표 · 길이 ·
> 제어기가 **넷 다** 다르므로, 그 사이의 33 초는 **아무것도 재지 않는다.** 한 단에
> 새로 생기는 것이 하나뿐인 자리에서만 차이가 뜻을 갖는다. 이 경고를 문서 안에 둔다 —
> 표를 보고 학생이 할 첫 번째 일이 그 뺄셈이다.

문서 쪽에서 걸린 것 둘.

- **`vault_check.sh` §18** 은 한 주차에서 모델 하나를 두 토큰이 가져가는 것을 막는다.
  모델 여럿을 한 실험이 돌리면 `**The model.** \`X\`` 가 아니라 **`**The models.**`**
  복수로 쓴다 — 실험 6-8 이 모델 넷을 돌리므로 그렇게 했다
- **도면을 다시 싣지 않는다** (CLAUDE.md §9-5). 사다리 절은 네 모델의 도면을 다시
  넣는 대신 **"각 모델의 도면이 있는 곳"** 표로 §6-1 · §6-3 · §6-5 · §6-7 을 가리킨다

MATLAB 쪽 두 가지는 다른 주차에서도 쓴다.

```matlab
ft = @(t,m) min([t(m); NaN]);   % 처음으로 참이 된 시각. 끝까지 거짓이면 NaN
c = [nm; num2cell(M.')];        % fprintf 는 cell 을 바로 못 받는다. 이름 + 열 전개
fprintf('    %-31s %10.2f %9.2f\n', c{:});
```

`min([t(m); NaN])` 은 조건이 한 번도 참이 아니면 **빈 벡터 대신 NaN** 을 낸다 —
`find(…,1)` 로 쓰면 빈 것이 와서 그 줄의 나머지 열이 밀린다.

## 15-63. 표 칸 안의 맨 `|` 가 수식을 삼킨다 — 2026-10-27

W06 의 PDF 를 글자층으로 뽑아 보니 `$0.353$` 이 숫자가 아니라 `$` 째로 찍혀 있었다.
문서에는 `$0.353$` 이 맞게 적혀 있었다. 범인은 그 줄의 **다른 칸**이었다.

```markdown
| `max |v| = 0.356` m/s | 옆 칸, $0.353$ |     <- 깨진다
| `max \|v\| = 0.356` m/s | 옆 칸, $0.353$ |   <- 맞다
```

기계는 이 순서로 읽는다.

1. **표 한 줄을 맨 `|` 로 칸으로 쪼갠다.** 이때 코드 스팬은 **아직 없다**
2. 쪼갠 칸마다 인라인 파싱을 한다

그래서 코드 스팬 안의 `|` 도 칸을 가른다. 가른 자리에서 백틱 하나가 짝을 잃고,
그것이 **다음 칸까지** `<code>` 로 삼킨다. 삼켜진 자리의 `$…$` 는 MathJax 가
건너뛰므로 수식이 글자 그대로 남는다. 수식이 깨진 자리와 원인이 **다른 칸**이라
문서를 눈으로 보면 찾을 수 없다.

- **표 줄에서는 코드 스팬 안이라도 `\|` 가 바른 탈출이다.** 쪼갤 때는 아직 코드
  스팬이 아니기 때문이다. 산문의 코드 스팬에서는 탈출이 처리되지 않아 `\|` 가
  **글자 그대로** 찍히므로, **표 줄만** 고친다 — 펜스 안의 콘솔 출력과
  `> - **Point to**: …` 꼴 인용문 산문은 손대지 않는다. W06 에서 그렇게 여덟 자리를
  남겼다
- 이것은 CLAUDE.md §4-11 의 `\|` (노름 ‖·‖) 와 **다른 것**이다. 그쪽은 수식 안이고
  이쪽은 마크다운 표 줄이다. 코드 스팬 안의 절댓값 막대는 `\lvert` 로 바꾸지 않는다 —
  그것은 학생이 복사해 쓸 **글자**다

> [!important] 추론으로 결론 내지 않고 **렌더해서** 결정했다
> 세 줄짜리 시험 문서(맨 `|` · `\|` · 코드 스팬 안의 `\`)를 만들어 `md2pdf.sh` 에
> 넣고 `pdftotext -layout` 으로 읽었다. 그 한 번이 세 가지를 동시에 정했다:
> 맨 `|` 가 정말 칸을 가르는가, `\|` 가 정말 고치는가, 역슬래시 줄이 정말 멀쩡한가.
> 마크다운 명세를 머리로 따지는 것보다 빠르고, 틀릴 수가 없다.

검출기를 **두 번 잘못 썼고, 두 번 다 그 시험 문서가 잡아 주었다.**

| 틀린 판정 | 왜 틀렸나 |
|---|---|
| 코드 스팬 안의 역슬래시를 글자로 보았다 | 인라인 파싱에서는 맞지만 **쪼개기는 그보다 먼저**다. 방금 고친 28 줄을 전부 다시 지적했다 |
| `\` 다음 글자를 무조건 넘겼다 | `` `\` `` 의 닫는 백틱을 삼켜 멀쩡한 네 줄을 지적했다. **다음 글자가 `|` 일 때만** 넘긴다 |

`vault_check.sh` **§20** 이 이것을 센다 (`--pipes`). 판정은 하나다 — 맨 `|` 로 칸을
나눈 뒤 **칸마다 백틱을 세어 홀수면 깨진 것**이다. 말로 두지 않고 절로 내린 이유는
§0-0 이고, 넣자마자 W07 394 행과 W08 602 행에서 **같은 결함 둘**을 더 찾았다.
눈으로는 몇 주 동안 못 보던 것이다.

## 15-64. 점검이 느리면 일이 아니라 **포크**를 센다 — 2026-10-27

사용자 지시: "조금 더 속도를 빠르게 하기 위해서?" `vault_check.sh` 전체 점검이
**450 초**였고, 그 시간의 대부분이 검사가 아니라 **프로세스를 띄우는 값**이었다.

```
real 7m30.318s   user 2m21.301s   sys 6m28.548s
```

`sys` 가 `user` 의 세 배다. 이것이 진단이다 — 커널에서 보낸 시간이 계산한 시간보다
훨씬 많으면 **포크가 병이다.** Windows 의 Git Bash 에서 `find` 한 번이 0.294 초,
`grep` 한 번이 0.08 초다. 알고리즘을 고치는 것이 아니라 **띄우는 횟수를 줄인다.**

### 같은 병이 여섯 군데에 있었다

| 절 | 무엇을 항목마다 띄웠나 | 몇 번 | 고친 방법 |
|---|---|---|---|
| §15 문서↔코드 | 토큰마다 `find lectures -name …` 최대 여섯 번 | 토큰 506 개 → 9,108 프로세스 | 트리를 한 번 걷고 `HAVE_F`·`HAVE_D` 연관배열로 이름 조회 |
| §9 금지 표현 | (표현, 문서) 쌍마다 `strip_code \| grep \| wc` | 16 × 35 = 560 | 사본을 한 번 벗겨 `$TMPD` 에 두고, 표현 하나마다 **문서 전부를 한 grep 에** |
| §6 오래된 PNG | PNG 마다 `grep -qr` 로 4 MB 를 뒤짐 | 248 | `grep -ohE` 한 번으로 본문에 나온 PNG 이름을 모아 둠 |
| §7 PNG 폭 | 그림마다 `od` 또는 `identify` | 150 | `perl` 한 번이 150 개의 IHDR 을 읽음 |
| §16 범례 표 | 그림마다 `sed -n` + `grep` | ~500 | `mapfile` 로 문서를 배열에 담고 쉘 안에서 훑음 |
| §2 wikilink | 링크마다 `find . -name "<이름>.md"` | 링크 수만큼 | `HAVE_MD` 로 이름 조회 |

목록도 같았다 — `mds()` 하나가 0.448 초인데 §9 가 그것을 열여섯 번 불렀다.
`lists()` 가 `MDS`·`DELIVERED`·`LABDOCS` 를 한 번 만들어 전 절이 돌려 쓴다.

**450 초 → 48 초.** 9.4 배다.

### 판정은 **바이트 대조**다

빨라진 검사기가 **다르게 판정하면 그것은 고장**이다. 그래서 고치기 전에 옛 코드의
출력을 그대로 받아 두고(복사본 `vault_check_base.sh` 를 같은 폴더에서 돌려 `ROOT` 가
같게 했다), 새 출력과 `diff` 했다. 120 줄 · 지적 50 건이 **한 글자도 다르지 않아야**
끝이다. 두 번 돌렸고 두 번 다 같았다.

- 돌아가는 스크립트를 **고치지 않는다.** 실행 중인 `bash` 는 파일을 다시 읽으므로
  편집하면 조용히 깨진다. 기준 출력은 **복사본**으로 받는다
- `grep -oiEH` 로 파일을 한꺼번에 넣을 때 출력 순서는 **인자 순서**다. 그래서
  `DELIVERED` 순서로 넣으면 옛 루프와 줄 순서가 같다
- 겹치는 패턴(`\byou\b` 가 `you're` 의 `you` 를 잡는다)은 **하나의 교대 패턴으로
  합칠 수 없다.** 횟수가 달라진다. "사본은 한 번, grep 은 그대로 열여섯 번"이다
- 이 볼트의 `python` 은 아무것도 하지 않는 껍데기다(`Python` 한 줄만 찍는다).
  쉘 스크립트를 고칠 때도 Edit 도구를 쓴다 → `orders-tooling.md` §5-1

## 15-65. 창의 절반은 일하기 전에 이미 차 있다 — 한 절만 꺼내 읽는다 — 2026-10-27

사용자가 "여전히 계속 compact 하고 있네" 라고 했다. 점검기를 9.4 배 빠르게 한
뒤였다. 도구가 빨라진 것과 **세션이 숨 쉴 자리**는 다른 문제였다. 재 보았다.

| 무엇 | 토큰 | 창의 |
|---|---|---|
| System tools (내장 도구) | 36,544 | 19 % |
| MCP tools | 27,947 | 15 % |
| System prompt | 11,502 | 6 % |
| Skills | 9,920 | 5 % |
| Memory files | 5,717 | 3 % |
| **고정 비용 합** | **91,630** | **48 %** |
| 실제 대화 (Messages) | 31,440 | 17 % |

창은 190,000 이고 auto-compact 는 **83 %(157,700)** 에서 돈다. 그러면 일할 자리는
157,700 − 91,630 ≈ **66,000 토큰**이다. 그런데 강의 `.md` 는 145~185 KB,
토큰으로 **50,000~60,000** 이다 — **한 주차 문서를 통째로 읽으면 그 한 번으로
여유가 끝난다.** 읽고 고치고 확인하면 compact 가 돈다. 느린 것이 아니라
**자리가 없는 것**이었다.

그래서 `_tools/md_section.sh` 를 만들었다. 제목을 한 번 모아 두고 번호로 찾아
**같거나 더 높은 수준의 다음 제목 전까지** 꺼낸다. 코드펜스 안의 `#` 는 제목으로
세지 않는다.

```bash
bash _tools/md_section.sh -l lectures/W06_*.md          # 절 목록 — 줄번호·줄 수
bash _tools/md_section.sh    lectures/W06_*.md 6-2      # 그 절만 (하위 절 포함)
bash _tools/md_section.sh -n lectures/W06_*.md 6-2      # 줄 범위만 → 345,518
```

W06 §6-2 로 재니 **145,048 B → 11,964 B, 12.1 배**다. 하위 절
(Experiment 6-2)까지 들어오고 다음 절로 넘어가지 않는다. `-n` 이 주는 범위는
`Read` 의 `offset`·`limit` 에 그대로 넣는 수다.

**규칙.** 강의 `.md` 의 한 절을 보려고 파일을 통째로 읽지 않는다. `-l` 로 자리를
잡고 그 절만 꺼낸다. 문서 전체를 봐야 하는 일(전체 검토·기호 통일)은 그 일만
하는 세션이나 서브에이전트에 맡긴다 — 그쪽 창을 쓰고 결론만 돌려받는다.

**고정 비용에서 줄일 수 있는 것과 없는 것.** 셋 중 둘은 세션 안에서 못 줄인다.

| 항목 | 줄일 수 있나 | 어떻게 |
|---|---|---|
| System tools 36,544 | 아니다 | 내장 도구다. deferred 방식이 이미 적용돼 있다 |
| MCP tools 27,947 | 부분적으로 | `matlab` 서버의 13 개 중 `model_edit`·`model_read`·`model_test` 설명이 거대하다. 이 볼트는 모델을 **코드로** 짓지 `model_edit` 로 짓지 않으므로 쓰지 않는 쪽이다 — 서버 단위로만 끌 수 있어 선택이 안 된다 |
| Skills 9,920 | 그렇다, **앱을 다시 켜야** | `~/.claude/settings.json` 의 MATLAB 팩을 31 → 6 으로 줄여 두었는데 (2026-10-27), **실행 중인 세션에는 적용되지 않는다.** 이 세션은 아직 31 개를 들고 있다 |
| `engineering@inline` | 앱 설정에서만 | 앱에 **내장된** 플러그인이라 `settings.json` 에 없다. MCP 서버 10 개(8 개는 인증이 없어 쓸 수 없다)와 스킬 11 개를 들고 온다 |

**이 세션은 좋아지지 않는다.** 플러그인 축소는 재시작 뒤에, 그것도 **새 세션**에서
효력이 생긴다. 포크한 세션은 부모의 대화를 그대로 안고 시작하므로 더 불리하다.
긴 작업을 시작하기 전에 **앱을 다시 켜고 새 세션을 연다.**

## 15-66. 끄기는 두 군데에 있고, `.gitignore` 는 이미 추적된 것을 놓아 주지 않는다 — 2026-10-27

§15-65 가 창의 절반이 일하기 전에 차 있다는 것을 재고 **무엇을 줄일 수 있는지**까지
적었다. 이 절은 그 뒤에 실제로 끈 것, 끄려다 못 끈 것, 그리고 끄는 과정에서
**하마터면 118 MB 를 학생들 저장소에서 지울 뻔한 일**을 적는다.

### 스킬은 `settings.json` 하나에 있지 않다

`~/.claude/settings.json` 의 `enabledPlugins` 를 줄였는데도 스킬 수가 그대로였다.
MATLAB 쪽은 **자기 설정 파일**을 따로 들고 있다.

| 파일 | 무엇을 정하나 | 한 일 |
|---|---|---|
| `~/.claude/settings.json` | `enabledPlugins` | MATLAB 팩 축소 (§15-65) |
| `~/.matlab/agentic-toolkits/config.json` | `configurations.global.claude_code.skillGroups` | **여기서도** 줄여야 했다 — `matlab` 25 → 3, `simulink` 9 → 2 |
| `~/.claude.json` | `mcpServers.matlab.args` | `--extension-file=…/simulink/tools/tools.json` 를 뺐다 → `model_*` 8 개가 사라지고 기본 MATLAB 도구 5 개만 남는다 |

남긴 스킬 그룹은 `matlab: control-systems · matlab-core · signal-processing` 과
`simulink: simulink-environment-fundamentals · simulink-simulation` 다섯이다.
둘 다 `.bak` 을 옆에 두었다. **둘 다 앱을 다시 켜야 효력이 생긴다.**

이 둘을 합쳐 약 12,700 토큰, 작업 공간이 66,000 → 79,000 이 된다. 설정으로 얻을 수
있는 것은 거기까지다 — 더 큰 것은 **새 세션으로 시작하기**(대화 31,693)와
**강의 `.md` 를 통째로 읽지 않기**(한 번에 50,000)이고, 둘 다 설정이 아니라 습관이다.
그래서 뒤의 것을 `CLAUDE.md` 의 **맨 앞 콜아웃**으로 올렸다 — 모든 세션이 첫 글자부터
읽는 자리다.

### `CLAUDE.md` 는 더 줄지 않는다 — 13 KB 는 규칙이다

28,246 → 27,249 바이트, 1 KB 밖에 줄지 않았다. 절별로 세어 보니 긴 것은 이야기가
아니라 **규칙**이었다 (§2 6,492 · §4 6,717 · §5 5,999). 사건 서술은 `orders-*.md` 로
내리고 자리에는 규칙 한 줄과 § 번호만 남겼지만, 그렇게 내릴 수 있는 분량이 애초에
1 KB 였다. **더 줄이려면 규칙을 지워야 하므로 거기서 멈췄다.**

**규칙.** `CLAUDE.md` 를 "가볍게" 만들려는 시도는 이것으로 끝이다. 새 지침은 여기에
**규칙 한 줄 + § 번호**로만 붙이고, 사건과 수치는 `orders-*.md` 에 적는다.

### `.gitignore` 에 써 넣어도 이미 추적된 파일은 그대로 추적된다

큰 이진 파일을 찾다가 `lectures/MSS-master/` 118 MB 를 발견했다. `.gitignore` 에
`lectures/MSS-master/` 가 **이미 있었다.** 그래서 추적되지 않는다고 보고 폴더를
볼트 밖으로 옮겼다 — `git status` 에 **삭제 449 건**이 떴다.

```
$ git ls-files 'lectures/MSS-master' | wc -l
449
```

`.gitignore` 는 **아직 추적되지 않은** 파일에만 걸린다. 이미 색인에 들어간 파일은
패턴을 아무리 써 넣어도 계속 추적된다 — 놓아 주는 것은 `git rm --cached` 뿐이고,
그것은 **다음 `git pull` 때 학생들 폴더에서 118 MB 가 지워진다**는 뜻이다.
폴더를 제자리로 돌려놓았다 (삭제 기록 0 건 확인).

이것은 정리가 아니라 **저장소 범위를 바꾸는 결정**이다. `CLAUDE.md` §7 의
`[!warning] 범위를 넓히지 않는다` 가 범위 변경은 사용자에게 묻는다고 못박았으므로,
"직접 해 줘" 라는 포괄 허가보다 그 조항이 앞선다. 사용자에게 올려 둔다.

**규칙.** 큰 파일을 치우기 전에 **`git ls-files <경로>` 로 추적 여부를 먼저 센다.**
`.gitignore` 에 있다는 것은 추적되지 않는다는 증거가 아니다.

### 지울 수 있는 것은 빌드 캐시뿐이었다

`.mat` 1,241 개는 전부 24 개 `slprj/` 안의 Simulink 빌드 캐시였다 — gitignore 되어
있고 MATLAB 이 다시 만든다. 옆 세션이 쓰는 `lectures/W06_simulink/` 를 빼고 지웠고,

MATLAB 을 닫은 뒤에 다시 돌리면 나머지도 지워진다.

### `grep -c` 는 0 을 찍고 1 로 끝난다

`git status --porcelain | grep -c 'MSS-master'` 가 `0` 을 **출력하고도** 종료 코드 1 을

## 15-67. `git commit -- <경로>` 는 `git rm --cached` 를 되돌린다 — 2026-10-27

§15-66 의 빼내기를 올리면서 **메시지는 맞고 내용은 빈 커밋**을 하나 만들었다.
이 세션은 다른 세션이 W06 파일 45 개를 index 에 올려 둔 상태였으므로, 그것을
휩쓸지 않으려고 경로를 한정해 커밋했다.

```
$ git rm -r --cached lectures/MSS-master        # index 에서 449 개를 뺀다
$ git commit -F - -- lectures/MSS-master .../orders-log-5.md
 1 file changed, 27 insertions(+)               # <- MSS 는 한 줄도 없다
$ git ls-files lectures/MSS-master | wc -l
449                                             # <- index 로 돌아왔다
```

**경로를 붙인 `git commit` 은 index 를 보지 않는다.** 그 경로의 **작업 트리 내용**을
그대로 커밋하고, index 를 거기에 맞춘다. MSS 파일 449 개는 디스크에 **그대로 있으니**
git 은 "바뀐 것 없음" 으로 보았고, 그러면서 index 의 삭제 표시를 지워 버렸다.
`git rm --cached` 로 한 일이 바로 다음 명령에 취소된 것이다.

| 하려는 것 | 경로 한정 커밋 | 맞는 방법 |
|---|---|---|
| 파일 **내용** 변경을 올린다 | 된다 — 작업 트리가 곧 올리려는 것이다 | 그대로 |
| 파일을 **추적에서만** 뺀다 (디스크에 남긴다) | **안 된다 — 되돌려진다** | HEAD 에서 읽은 **임시 index** 로 커밋을 만든다 |
| 파일을 추적과 디스크에서 다 뺀다 | 된다 (작업 트리에 없으므로) | 그대로 |

가운데 칸이 이번 경우였다. 진짜 index 를 건드리지 않고 커밋 하나를 만드는 법:

```
$ GIT_INDEX_FILE=$T git read-tree HEAD
$ GIT_INDEX_FILE=$T git rm -r --cached lectures/MSS-master
$ TREE=$(GIT_INDEX_FILE=$T git write-tree)
$ COMMIT=$(git commit-tree $TREE -p HEAD -F msg.txt)
$ git update-ref refs/heads/main $COMMIT HEAD
$ git rm -r --cached lectures/MSS-master          # 진짜 index 도 새 HEAD 에 맞춘다
```

`update-ref` 에 **옛 값(`HEAD`)을 함께 준다** — 그 사이 다른 세션이 커밋했으면 거부된다.
마지막 줄의 `git rm --cached` 는 경로가 한정되어 있어 남의 45 개를 건드리지 않는다.

**규칙 둘.**
① **커밋한 뒤 그 커밋이 무엇을 담았는지 센다.** `git show --stat` 한 줄이다.
메시지가 맞다고 내용이 맞는 것이 아니다 — 이번에는 "118 MB 를 뺐다" 는 커밋이
27 줄의 글만 담고 있었고, 세지 않았으면 기록만 참인 채로 남았다.
