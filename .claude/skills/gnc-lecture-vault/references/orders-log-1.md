### 15-4. 스크립트가 기본 작업공간에 남기는 이름

절 스크립트는 기본 작업공간에서 돈다. W02_I 가 익명함수를 `run` 이라 이름 지었더니 그 뒤의
`run(...)` 호출이 전부 그 함수로 갔다. W02_E 의 `s = tf('s')` 는 루프 변수 `s` 를 덮었다.
**MATLAB 함수 이름과 흔한 루프 변수 이름을 스크립트 변수로 쓰지 않는다.** `vault_runall` 은
함수 안의 지역 목록으로 돌기 때문에 영향을 받지 않는다 — 여러 스크립트를 돌릴 때는 그것을 쓴다.

### 15-5. 채점기·그림 스크립트는 `W02_0_setup` 을 부르지 않는다

`W02_0_setup` 의 첫 줄은 `clear; close all;` 이다. 그림을 그리는 도중에 부르면 그리던 그림이
닫힌다(`exportgraphics` 가 "axes 가 아니다" 로 실패). 채점기에서 부르면 학생의 작업공간이
지워진다. 둘 다 `WXX_vars()` 의 값을 `assignin` 으로 넣는다.

### 15-6. 실습 모델은 "돌리면 보이게", 스크립트는 짧게 — 2026-09-21

> **"pseudo derivatives 전달함수를 그대로 쓰면 않될까? ... pid 블락은 subsystem 으로 굳이
> 만들필요가 없어보이는데 ... 각 예제마다 그냥 시뮬링크 파일을 따로 만드는게 어떨까? ...
> 시뮬링크 자체만 돌려도 그래프를 통해서 pid 게인 값 변경했을 경우 반응이 어떤지를 바로바로
> 보고 싶어 ... 하나의 scope에서 가능하면 모두 다"**,
> **"최대한 m 파일은 더 내용을 간단히 하고 시뮬링크 자체로만 돌려서도 무슨 내용인지 이해가 가도록"**

| 규칙 | W02 에서 한 것 |
|---|---|
| **예제 하나에 모델 하나** | `W02_C_P` · `W02_D_PD` · `W02_E_PID` · `W02_F_block_vs_hand` · `W02_G_derivative_bench` · `W02_G_noise_kick` · `W02_H_antiwindup` · `W02_I_tuning`. 빌더 하나(`W02_1_build_pid`)가 옵션 표로 전부 만든다 |

### 15-10. 절 스크립트는 "그대로 읽으면 되는" 한·영 설명을 단다 — 2026-09-22

사용자 지시: "강의 자료의 m 파일에 영어랑 한글 설명이 있어야지... m 파일은 최대한 간단히 해주되...
자세한 설명이 있어야 돼...그대로 읽으면 되도록". 코드는 짧게 두고, 설명을 늘린다.

| 자리 | 쓰는 것 |
|---|---|
| 머리말 `이 절이 묻는 것 / the question` | 이 절이 답하는 질문 하나, 한국어 한 줄 + 영어 한 줄 |
| `이 스크립트가 하는 일 / what this script does` | ①②③ 번호를 붙인 단계. 모델 이름, 바꾸는 값, 찍는 것 |
| `출력에서 볼 것 / what to look for in the output` | **실제로 나오는 숫자**를 들어, 무엇을 보고 무슨 결론을 내는지. 강의자가 읽어 주면 설명이 된다 |
| 본문 `%% 0) 경로`, `%% 1) …` | 블록마다 한·영 한 줄씩. 도우미(W0x_read, step_metrics)가 무엇을 돌려주는지, 왜 그 구간/기준으로 재는지 |
| 바꾸지 않는 것 | 코드. 주석만 더하고, 더한 뒤 **다시 돌려 출력이 같은지** 확인한다 |

### 15-13. W05 재작성 — 유도도 "PID 튜닝" 으로 본다 (2026-09-22)

| 규칙 | 어떻게 |
|---|---|
| 유도를 제어기로 읽는다 | LOS 는 y_e 에 대한 P (Kp = 1/Delta, 작은 오차에서 atan 을 선형화), ILOS 는 PI (I = kappa/Delta). 튜닝 순서 Delta -> R -> kappa 는 2주차의 P -> I |
| 오프셋 예측을 기계로 | 조류 속 LOS 의 남는 오차 = Delta tan(유지한 선수각). `verify_w05_guidance` 가 시뮬레이션으로 대조 |
| MATLAB Function 은 둘뿐 | guidance 와 allocation. 제어기 둘은 서브시스템(`add_heading_loop`·`add_speed_loop`)이고, 유도의 **상태는 Unit Delay** 가 들고 있다 → 15-42 절. 상수는 `mlfcn_params` |
| 항적은 XY Graph + 그림에는 선체 | 모델에 XY Graph 를 두어 Run 중 항적이 보이게. 결과 그림은 `track_ships` 로 선체·선수를 그리고 선 색과 `COL` 을 맞춘다(범례 색이 어긋났었다) |
| 튜닝은 그 과제에서 | kappa 는 긴 다리(0.1)와 60 m 임무(0.3)에서 답이 다르다 — 쓰일 과제에서 고른다 |
| 표시용 변환은 readouts 하나로 | Selector·Fcn·Gain 을 줄줄이 두지 않는다(겹침·기울어진 선의 원인). From 블록 폭 75 px 이상(좁으면 `-T-` 로 보인다) |

### 15-14. 설명 바로 아래에 그 설명의 예제 (2026-09-25, 사용자 지시)

> 사용자: "설명이 잇으면 그 바로 아래 해당 example이 나오도록 ... pid 설명이 나와 잇으면
> 그 설명과 정확히 매칭 되는 example이 바로 나와서 그 설명을 이해할 수 있도록"
> 참고 틀: `캡스톤디자인/1_2026-2학기_강의자료/10-주차별-강의자료/W04_Simulink_PID와_첫_제어기.md`

**Part 1 은 이론, Part 2 는 실습** 이라는 옛 골격을 버린다. 이론 절 하나가 곧 실험 하나를 데리고 있다.
Part 2 는 **실행 순서 색인**(실험 번호 · 모델 · 스크립트 · 무엇을 보이는가) 한 표로만 남긴다.

| 절의 네 부분 | 담는 것 |
|---|---|
| **What is observed** | 무엇이 보이는가 — 수치와 함께 두세 줄. 식보다 **현상이 먼저** |
| **The result** | 그 절이 벌어들일 식 하나 |
| **Derivation, one line at a time** | 번호 매긴 유도. 한 줄에 한 단계, 중간 단계를 건너뛰지 않는다 |
| **Experiment N-x** | `What it measures`(유도의 몇 번 줄을 재는가) · `The model` · `Opening and running`(주석 달린 명령) · 실제 출력 · 그림 · **Reading the figure against the derivation** · `What to try` · In class |

- **핵심은 "Reading the figure against the derivation" 표다.** 열 셋: 어디를 보는가 / 무엇이 있는가 /
  **유도의 몇 번 줄이 그것을 예측하는가**. 그림의 모든 특징이 유도의 한 줄에 매인다 — 이것이 없으면
  학생은 그래프와 식을 따로 외운다.
- 실험 번호는 **절 번호를 따른다**(§2-6 → 실험 2-6). 절 하나에 실험이 둘이면 2-10a · 2-10b.
  실습 절 문자(A~J)는 쓰지 않는다. `.m` 파일명은 그대로 두되(이름을 바꾸면 이력이 끊긴다),
  **러너가 찍는 제목과 그림 제목은 실험 번호로** 바꾼다 — 출력과 문서가 같은 말을 해야 한다.
- `What to try` 의 결과도 **실제로 돌려서** 적는다. 실제로 "Kd 를 키우면 느려진다" 고 추측해 적었다가
  재 보니 상승은 빨라지고 오버슛이 28 % 로 커지는 것이었다. 추측한 문장은 한 줄도 남기지 않는다.
- 명령 블록의 주석은 한국어/영어 두 줄로, **무엇이 보일지**를 적는다: `% Run — 잔물결이 줄어든다 / the ripple shrinks`.

**보조 규칙 두 가지** (15-14 와 함께 쓴다)

- `vault_check.sh` §16 의 범례 표 머리말은 `^\*\*Reading the figure` 로 느슨해졌다.
  "**Reading the figure against the derivation.**" 처럼 뒷말을 붙여도 통과한다 (2026-09-25).
- 실험 번호를 붙일 때 **`.m` 파일 이름은 바꾸지 않는다.** 이름을 바꾸면 git 이력과 문제지·답안지가
  한꺼번에 어긋난다. 대신 파일 첫 줄 주석, `fprintf` 제목, `lab_fig` 제목을 실험 번호로 바꾸고,
  Part 2 색인 표에 "실험 번호 ↔ 모델 ↔ 스크립트" 를 적어 둘을 잇는다.

### 15-15. 실험 하나에 모델 하나, `.m` 은 돌리고 그리는 것까지 (2026-09-25, 사용자 지시)

> 사용자: "모든 m 파일은 그림 그려서 plot 하는 정도만 아주 간단히 ... 각 실습은 개별 시뮬링크
> 파일로 실행하도록"

| 규칙 | 어떻게 |
|---|---|
| **실험 하나 = 모델 하나** | 두 실험이 한 `.slx` 를 쓰지 않는다. 같은 회로가 필요하면 빌더의 목록에 이름을 하나 더 넣어 **같은 내용의 모델을 하나 더 만든다** (예: `W02_C_metrics`, `W05_F_LOS`). 학생은 실험 이름으로 파일을 열고 Run 만 누른다 |
| **실험 하나 = 스크립트 하나** | 한 스크립트가 표를 둘 이상 찍고 있으면 그 스크립트는 실험 둘이다. 나눈다 (`W02_G_bench` + `W02_G_noise_and_kick`, `W05_F_LOS_in_a_current` + `W05_F_ILOS_removes_it`) |
| **`.m` 은 얇게** | 주석을 뺀 실행 줄 **45 줄 이하**. 하는 일은 ① 모델을 몇 값으로 돌리고 ② 표를 찍고 ③ 그림을 그려 저장하는 것뿐이다. 계산이 그보다 많아지면 그것은 `_tools/` 의 함수이거나 모델 안에 있어야 한다 |
| **머리말은 그대로 길게** | 15-13 의 한국어/영어 설명은 줄이지 않는다. 얇게 하라는 것은 **코드**이지 설명이 아니다 |
| 이름 | 모델과 `.m` 은 같은 이름을 쓸 수 없다 (CLAUDE.md §2). `W02_C_metrics.slx` 의 스크립트는 `W02_C_five_numbers.m` |
| 예외 | W01 의 `W01_openloop` 은 실험 1-11 과 1-12 가 함께 쓴다. 한 번의 개루프 주행에 두 질문을 하는 것이고, 무엇보다 **사용자가 편집 중인 파일**이라 건드리지 않는다. Part 2 색인에 그렇게 적어 둔다 |
| 기계 검사 | `vault_check.sh` §18 이 ① 실행 줄 수 ② 한 주차 안에서 `**The model.**` 이 같은 모델을 두 실험에 쓰지 않는지 본다 |
