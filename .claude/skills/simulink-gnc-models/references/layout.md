# 배치 정리 — `tidy_layout.m`

## 무엇을 하는가 (순서가 중요하다)

| 단계 | 하는 일 | 왜 |
|---|---|---|
| 1 | 포트가 많은 블록을 세로로 늘림 | 포트 간격 46px 확보 |
| 2 | 앞뒤로 이어지는 블록의 **포트 간격을 맞춤** | k개 신호가 한꺼번에 직선이 됨 |
| 3~4 | 겹침 해소(세로) ↔ 체인 정렬을 6회 반복 | **반드시 정렬로 끝낸다** |
| 5 | 먹임·받기 블록을 상대 포트 높이에 맞춤 (세로) | 짧은 직선 |
| 6 | 겹침 해소(가로) | 세로를 건드리지 않으므로 직선이 안 깨짐 |
| 6-2 | 먹임 블록을 **받는 블록 왼쪽 60px** 로 데려옴 | 멀면 선이 큰 블록을 가로지름 |
| 6-3 | 주석 글상자를 도면 위쪽으로 올림 | 블록 위에 겹치면 못 읽음 |
| 7 | 색칠 + 태그 이름 감춤 | |
| 8 | 선 다시 그리기 — 높이가 같으면 직선, 아니면 `autorouting` | 대각선 0 |

서브시스템 내부는 `Simulink.BlockDiagram.arrangeSystem` 에 맡긴다.
안쪽은 연결이 촘촘해서 전부 직선으로 만들면 오히려 겹친다.

## 이미 밟은 지뢰

| 증상 | 원인 | 해법 |
|---|---|---|
| 함수를 고쳐도 예전 동작 | MATLAB 이 함수를 캐시함 | `clear functions; rehash` |
| 모든 서브시스템이 건너뛰어짐 | `MaskType` 이 MATLAB Function 을 포함한 서브시스템에도 걸림 | `SFBlockType` 으로 판별. **`'NONE'` 을 돌려준다** (빈 문자열 아님) |
| `str2double` 오류 | `PortNumber` 가 숫자로 올 때가 있음 | 숫자·문자 둘 다 받는 `pnum` 헬퍼 |
| 포트 간격 계산이 안 맞음 | 서브시스템 포트는 `height/n` 간격 (`n+1` 아님). 블록마다 다름 | **재보면서 비율로 늘린다.** 공식을 쓰지 말 것 |
| 정렬해 놨는데 다시 어긋남 | 정렬 뒤에 세로 이동을 또 함 | 세로 이동은 **정렬 이전에만** |
| 먹임 블록이 멀리 밀려남 | 겹침 해소가 먹임 블록을 왼쪽으로 계속 밀어냄 | 자리가 막혔으면 **받는 블록부터 오른쪽으로 밀어 공간을 만든다** (`shiftRightFrom`) |
| 태그 변환·흐름 강제가 도면을 망침 | `convertToTags`, `enforceFlow` | **쓰지 않는다.** 코드에는 남아 있으나 파이프라인에서 뺐다 |
| `arrangeSystem` 경고 | 이미 정리된 도면 | 무해. 무시 |

## 결과 확인

```matlab
tidy_all('<주차자료 폴더>')
```

- **겹침 0** 이 목표이자 합격선
- 꺾인 선은 되먹임(Unit Delay 되돌림)과 포트 수가 다른 블록 사이에만 남는다
- 실측: 모델 22개 / 블록 659개 / 선 667개 → 겹침 0, 꺾임 97 (14.5%)

## 두 번 부르면 좋아진다

`tidy_layout` 은 한 번에 수렴하지 않는다. 생성 스크립트 끝에서 두 번 부른다.

```matlab
slxList = dir('*.slx');
for k = 1:numel(slxList)
    [~, mName] = fileparts(slxList(k).name);
    try, tidy_layout(mName); tidy_layout(mName); catch, end
end
```
